这段视频围绕“如何免费使用 Claude Code”展开，作者指出，正常使用 Claude Code 通常有两种方式：要么订阅官方付费套餐，要么手动对接第三方 API 服务，本质上都需要花钱。视频作者发现了一套“白嫖方案”：用 **Agnes AI** 提供免费的文本、图片、视频模型接口，再用 **CCSwitch** 负责把 Claude Code 的请求转发到 Agnes AI。作者不仅讲配置流程，还展示了几个实际测试案例，包括运营复盘看板、商务合作落地页、文生图、图生图和视频生成效果。

## 核心观点

### 1. Claude Code 原本通常需要付费，但视频提供了一套免费替代方案

作者一开始就指出，想使用 Claude Code，一般有两种主流方案：一种是订阅官方付费套餐，另一种是自己对接第三方 API 服务。无论哪种方案，本质上都离不开付费，因为 Claude Code 需要调用大模型作为后端能力。视频的核心卖点，就是作者发现了一种“无限制免费使用 Claude Code”的方法。这个方法不是破解 Claude Code 本身，而是通过替换后端模型供应商，让 Claude Code 的请求走到 Agnes AI 的免费模型接口上。也就是说，Claude Code 仍然负责执行 Agent 工作流，真正承担模型调用成本的是 Agnes AI。

### 2. 视频中的三件核心工具分别承担不同角色：Claude Code 干活，Agnes AI 供模型，CCSwitch 做连接

作者明确介绍了本期涉及的三个工具。第一个是 **Claude Code**，视频称它是“目前公认最强的 AI Agent 工具之一”，主要负责执行代码、写文案、调用模型、生成项目文件等实际任务。第二个是 **Agnes AI**，视频称它是一个免费的 AI 模型平台，并强调它不是普通“套壳”或“中转站”，而是文本、图片、视频三个模型都自研，对标 OpenAI、谷歌等第一梯队模型。第三个是 **CCSwitch**，作者把它解释成“接口切换器”，用来统一管理 Claude Code 要连接哪个后端、填什么 API Key、使用什么接口地址、调用哪个模型。三者关系可以概括为：**Claude Code 负责干活，Agnes AI 提供免费的模型，CCSwitch 把二者连接起来**。

### 3. Agnes AI 的吸引力在于免费开放全模态接口，而且视频声称不限期、不限量

视频对 Agnes AI 的介绍是整套方案的关键。作者称 Agnes AI 不仅有文本模型，还提供图片生成和视频生成模型，而且“把这一整套全模态的接口完全免费开放了出来”。更重要的是，作者强调这不是常见的限量试用，而是“不限期、不限量”，用户可以“零成本随便用”。视频还提到一个增长数据：Agnes AI 在 **6 月 1 日免费开放后的第一周**，文本模型调用量、图片生成量、视频生成量都非常高，其中图片生成超过 **200 万张**，视频生成超过 **200 万秒**。作者虽然说“没太搞懂它们这是什么打法”，但从用户角度认为这是“实打实的福利”。

### 4. CCSwitch 的作用是把 Claude Code 的模型请求统一转发到 Agnes AI

视频中最关键的技术环节，是用 CCSwitch 来配置 Claude Code 的后端供应商。作者解释，CCSwitch 可以统一管理“Claude Code 要连哪个后端、Key 填什么、接口地址填什么、用哪个模型”。配置完成后，用户只需要在 CCSwitch 里点击切换供应商，Claude Code 的请求就会走到新的模型服务。视频这次要做的事情，就是把 Claude Code 的后端从默认配置切换成 Agnes AI。这样一来，用户在终端里继续使用 Claude Code，但实际模型调用不再走原来的付费渠道，而是通过 CCSwitch 转发到 Agnes 的免费网关。

### 5. 配置流程的核心包括获取 API Key、添加供应商、填写网关地址、拉取模型列表和启用路由

作者展示的配置步骤比较完整。首先打开 **Agnes API 开放平台**，在左侧菜单点击 **API 密钥**，再创建一个新的密钥，名称随便填写即可。然后打开 **CCSwitch**，在顶部工具栏切换到专门配置 Claude Code 的项目，点击右上角加号新增供应商，类型选择 **Cloud Provider**，再选择 **自定义供应商**。接着填写 Agnes 平台复制出来的 API Key，并填写请求地址，用于把 Claude Code 的请求转发到 Agnes 的网关。随后在 API 格式处选择对应选项，其他字段保持默认，点击获取模型列表；如果能够成功拉出模型，就说明已经连上 Agnes。最后还要开启 CCSwitch 的本地路由，并打开 Claude 路由开关，再回到供应商列表启用 Agnes，这样 Claude Code 的请求才会真正被转发。

### 6. 模型映射是让 Claude Code 全部调用 Agnes 2.0 Flash 的关键一步

视频中特别提到“模型映射”这个步骤。作者的做法是，把 Claude Code 可能调用到的几个模型，全部映射到 **Agnes 2.0 Flash**。这样无论 Claude Code 原本想调用哪个模型，实际请求都会被转到 Agnes 2.0 Flash 上。这个操作的目的，是避免 Claude Code 在执行不同任务时因为模型名不匹配而报错，同时确保所有调用都走 Agnes 的免费模型。配置完成后，供应商列表里会出现 Agnes 这一项，点击启用之后，作者在终端输入 Claude 命令并发送“你好”，看到模型成功回复，说明整套配置已经跑通。

### 7. 文本模型测试显示：Agnes 2.0 Flash 可以完成数据分析看板和商务落地页

配置完成后，作者没有停留在安装教程，而是用实际工作需求测试文本模型能力。他拿了一份自己的视频运营数据作为测试材料，这份数据有 **一百多条**，横跨多个平台。作者让 Claude Code 调用 **Agnes 2.0 Flash**，基于这份数据生成一个运营复盘看板，结果包含图表、筛选、明细等功能，页面也比较清爽，能够用于日常复盘。随后，他又让模型把这个看板升级成可以直接发给品牌方的商务合作落地页，结果页面里包含数据快照、代表作、合作方式等模块。作者认为，从普通数据表格到复盘看板，再到商务合作页面，背后都靠免费的 Agnes 模型完成，效果已经“很可以”。

### 8. 图片生成测试分为文生图和图生图，作者认为实用性较强

由于 Claude Code 本身只能接入文本模型，作者专门创建了一个调用 Agnes 生图模型的 **Skill**。使用时仍然在 Claude Code 对话框里输入需求，Claude Code 会自动调用这个 Skill，并把生成的图片直接保存到项目目录。作者先测试了文生图能力，提示词要求生成一张 **35 毫米胶片、直闪风格的人像照片**，最终效果呈现出胶片质感、闪光灯打在脸上的高光、皮肤纹理和毛孔细节，以及街头运动风氛围。随后作者测试图生图能力，也就是给模型一张参考图，让它基于图片二次创作，结果生成了一张职业形象照：半身构图、表情自然、笑容真诚，并且“脸还是原来的脸”，但衣服、背景、灯光都换掉了。作者认为这种“换装不换脸”的能力非常实用，可以把生活照改成适合简历、领英主页使用的职业照。

### 9. 视频生成能力有亮点也有瑕疵，但免费不限量降低了试错成本

作者最后测试了 Agnes 的视频生成能力。第一个案例是用提示词生成一段 **女歌手唱歌的短视频**：画面中是红发女歌手半身特写，卷发发丝、逆光高光都比较清晰，更难得的是情绪变化比较连贯。作者描述她一开始闭眼酝酿，随后慢慢进入状态，张嘴开始唱，到后面眉头微皱，整个人沉入情绪里；握麦的手、嘴形、呼吸节奏也比较连贯，没有明显“一眼假”的僵硬感。但作者也承认模型偶尔会“抽风”，比如另一个夜晚街拍美女视频里，背景左侧路人突然从一个人变成两个人，像凭空克隆出来一样。作者的态度是，主体人物本身比较稳定，背景小瑕疵可以通过多抽几次来解决，而因为模型免费不限量，反复尝试的成本为零。

## 值得记住的点 / 行动建议

### 1. 先理解工具分工，再动手配置，避免把 Claude Code、Agnes AI、CCSwitch 混在一起

这套方案看起来步骤多，但本质逻辑并不复杂。Claude Code 是前端工作流和 Agent 执行工具，负责理解需求、拆任务、写代码、生成文件。Agnes AI 是模型供应方，提供文本、图片、视频能力。CCSwitch 是中间层，负责把 Claude Code 原本要发出的模型请求转发到 Agnes AI。只要先理解这三个角色，就不会在配置时混淆“在哪里填 API Key”“在哪里切模型”“在哪里开启路由”。

### 2. 配置前先准备好 Agnes API Key，这是整套方案的入口

视频中第一步就是去 Agnes API 开放平台创建 API Key。具体做法是进入平台后，点击左侧菜单栏的 **API 密钥**，再点击创建新密钥，并随便起一个名称。创建成功后复制这串 Key，后面要粘贴到 CCSwitch 的供应商配置中。这个 Key 相当于 Claude Code 通过 CCSwitch 调用 Agnes AI 的身份凭证。如果 Key 填错，后续即使接口地址和模型映射正确，也无法正常拉取模型或调用模型。

### 3. 在 CCSwitch 中新增自定义供应商时，重点检查 API Key、请求地址和 API 格式

视频配置 CCSwitch 的核心环节，是新增一个供应商，并选择 **Cloud Provider / 自定义供应商**。这里最关键的字段是 API Key 和请求地址：API Key 来自 Agnes 平台，请求地址用于把 Claude Code 的请求转发到 Agnes 网关。API 格式也要按视频中对应选项选择，其他字段可以先保持默认。填完之后点击“获取模型列表”是一个很重要的验证动作；如果模型列表能够成功拉出来，说明 Key、地址和格式大概率都没问题。反之，如果模型列表拉不出来，就应该优先检查这几个字段，而不是急着修改其他复杂设置。

### 4. 做好模型映射，确保 Claude Code 的调用都能落到 Agnes 2.0 Flash 上

作者把多个模型统一映射到 **Agnes 2.0 Flash**，这是为了让 Claude Code 无论调用哪个模型名，最后都能实际走到 Agnes 的免费模型。这个步骤很关键，因为 Claude Code 内部可能会根据不同任务调用不同模型，如果没有映射，就可能出现模型名不匹配、请求失败或走错供应商的情况。统一映射可以降低配置复杂度，也更方便验证整套链路是否成功。对于新手来说，先按视频方法把模型都映射到同一个稳定模型，比一开始就做复杂多模型路由更容易成功。

### 5. 保存供应商还不等于配置完成，必须开启本地路由和 Claude 路由

视频特别强调，供应商配好之后还不够，还要让 CCSwitch 真正转发请求。具体操作是进入左上角设置，打开路由页面，开启本地路由，并把 Claude 相关路由开关打开。然后回到供应商列表，找到 Agnes 并点击启用。只有完成这一步，Claude Code 的请求才会经过 CCSwitch 转发到 Agnes 的免费网关。很多配置失败可能并不是 API Key 错了，而是忘了启用本地路由或没有把 Agnes 设为当前供应商。

### 6. 配置完成后先用最简单的“你好”测试链路，不要一上来就跑复杂项目

作者在终端输入 Claude 命令后，先发送了一个“你好”，确认模型能够成功回复。这个验证方式很实用，因为它把问题简化到了最小：只要能回复，就说明 Claude Code、CCSwitch、Agnes API Key、路由和模型映射至少基本打通。新手不要一上来就让它生成复杂项目，否则一旦报错，很难判断是代码任务问题、模型问题、路由问题还是 Key 配置问题。先用简单对话验证，再逐步测试文本生成、代码生成、图片 Skill 和视频生成，是更稳妥的流程。

### 7. 文本模型可以优先用于结构化输出任务，比如数据复盘、看板、落地页

视频中最有参考价值的文本测试，是把一份一百多条、多平台的视频运营数据交给 Agnes 2.0 Flash，让它生成运营复盘看板。这个任务并不是简单聊天，而是包含数据理解、信息组织、页面结构设计和前端输出。随后作者又让它进一步生成商务合作落地页，包括数据快照、代表作、合作方式等模块。普通用户可以借鉴这个思路，把 AI 用在“把原始资料变成可展示页面”的场景里。比如运营复盘、个人作品集、品牌合作页、项目总结、数据仪表盘，都是 Claude Code + 免费模型比较适合尝试的方向。

### 8. 图片生成建议通过 Skill 接入，不要期待 Claude Code 原生直接完成生图

作者明确提到，Claude Code 本身只能接入文本模型，所以他专门创建了一个用于调用 Agnes 生图模型的 Skill。这个点很重要：如果用户只配置了文本模型，Claude Code 未必能直接完成图片生成。正确做法是给 Claude Code 增加一个调用生图接口的工具能力，让它在用户输入提示词时自动触发该 Skill，并把图片保存到项目目录。这样一来，Claude Code 就不仅是聊天工具，而更像一个可以调度文本、图片、视频能力的本地 Agent。

### 9. 用免费生图模型时，要利用“不限量”的优势反复试提示词

作者对生图的评价不是“每次都完美”，而是强调免费模型最大的优势在于可以无限试。AI 生图往往不是一次就出理想结果，同一个提示词可能需要多次生成，或者不断调整角度、光线、风格、构图、人物表情。付费模型如果每张图都要几毛钱，反复试错成本会迅速累积。Agnes AI 如果确实如视频所说免费不限量，那么用户就可以把它当作“高频试稿工具”，先大量探索风格和构图，再挑选最满意的结果。

### 10. 图生图很适合做职业形象照、头像升级、换装和场景替换

视频里的图生图案例非常实用：给模型一张生活照，再用提示词生成职业形象照。作者强调生成结果“脸还是原来的脸”，但衣服、背景、灯光都换掉了，这正是图生图最有价值的地方。普通人可以把它用于简历头像、领英头像、公众号作者照、商务介绍页、个人品牌主页等场景。相比完全文生图，图生图更容易保留人物身份特征，也更适合做“原图基础上的升级”。不过涉及真人照片时，也要注意隐私、安全和使用边界，尤其不要滥用他人肖像。

### 11. 视频生成可以用于短视频创意验证，但要接受偶发瑕疵

作者展示的视频生成效果有亮点，比如女歌手唱歌时的表情、嘴形、握麦动作和呼吸节奏比较连贯。但他也展示了缺陷案例：夜晚街拍视频中，背景路人突然变成两个人，出现“凭空克隆”的问题。这说明当前视频生成模型即使效果不错，也仍可能在背景人物、肢体、连续性和物理一致性上出现瑕疵。实际使用时，更适合先拿来做创意验证、分镜测试、素材草稿或氛围片段，而不是直接用于高要求商业成片。免费不限量的优势，恰好可以用来多生成几版，再筛选相对稳定的一版。

### 12. 对“免费不限量”保持理性：适合尝鲜和低成本实验，但重要项目要留备选方案

视频整体非常兴奋地强调 Agnes AI 免费、不限量、全模态开放，但普通用户仍然应该保持一点谨慎。免费服务的政策、额度、稳定性、接口规则、模型名称和可用性都有可能变化。重要项目不要完全依赖单一免费接口，最好保留官方付费模型、其他 API 或本地模型作为备选。尤其是涉及商业交付、客户项目、隐私数据和长期工作流时，要关注服务条款、数据安全和稳定性。把这套方案当作低成本学习、原型开发、个人效率工具非常合适，但不要把“永久免费”当成确定不变的基础设施。
