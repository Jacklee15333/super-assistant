## 🤖 AI 分析

## 一句话概括

这条视频用 Codework 这类通用桌面 Agent 为例，说明 AI 正在从“只能聊天回答”的工具，变成能操作电脑、浏览器和专业软件环境、替用户完成真实任务的“可执行型数字下属”。

## 背景与主题

这期视频讨论的是“桌面 Agent / 通用 Agent”的实际用法。作者认为，普通聊天 AI 更像“聪明网友”，只能把答案以文字形式回复给你；而 Agent 的关键区别是，它可以在获得授权后直接进入电脑、浏览器和工具环境，帮用户一步步执行任务。视频以阿里的一款通用 Agent 产品 Codework 为例，展示了电脑故障排查、网页数据爬取、自动整理表格、制作小工具、网页设计、写作/合同/财税/法务等工作场景。作者的角度很偏实操：不是讲 Agent 的抽象概念，而是告诉普通人“怎么用它解决日常电脑工作中的问题”。

## 核心观点

### 1. 聊天 AI 和通用 Agent 的本质区别，是“回答问题”与“动手做事”的区别

作者一开始就把聊天 AI 比作“一个聪明网友”，它能理解问题、给出建议，但最终结果通常还是一段文字。也就是说，聊天 AI 的能力主要停留在对话框内，用户还需要自己复制、粘贴、下载、整理、操作软件。通用 Agent 则不同，它可以在用户授权之后直接进入电脑环境、浏览器环境和各类工具环境，替用户完成实际任务。作者最后总结说，通用 Agent 更像是“真正能干活的下属”，不是只告诉你该怎么做，而是把任务拆开后一步步执行完。这也是视频的核心判断：AI 的下一阶段价值，不只是“会说”，而是“会做”。

### 2. Codework 被作者作为通用 Agent 的代表，原因是它更适合日常工作场景

视频提到，目前很火的 Codex 是通用 Agent 类产品的代表，但 Codex 对多数普通用户来说仍然有一定使用门槛。因此作者选择用阿里的 Codework 来演示，因为它既具备基础 Agent 能力，又针对日常办公环境做了许多优化。作者用了一个很口语化的说法：它“比较适合中国宝宝体质”，意思是安装、使用、交互门槛更低，更接近普通中国用户的工作习惯。Codework 的安装方式也被描述得很简单：像安装普通软件一样下载对应安装包，然后一路下一步即可。主界面大致分为三个区域：右侧是与 Agent 对话的区域，左侧是任务记录，上方是日常功能选项，这种布局也降低了普通用户上手难度。

### 3. Agent 的第一大能力是 Computer Use：直接操作电脑，处理过去需要人工排查的问题

作者展示的第一个案例是排查自己的 MacBook Pro 卡顿问题。那台 MacBook Pro 过去是作者的主力工作电脑，但后来连操作 PPT 都会卡，作者一直找不到原因，只好放在家里“吃灰”。他向 Agent 发出指令：“电脑卡顿厉害，帮我检查一下，再看看怎么解决。”随后 Agent 在右侧生成待办清单，先检查系统使用情况，再分析原因，最后给出处理建议，每完成一项就划掉进入下一步。作者虽然看不懂过程中运行的许多命令，但最终结果很直观：电脑硬件没有问题，真正的问题是系统环境很糟糕，甚至“元凶”竟然是一个清理电脑的工具，占用了 16G 内存中的 10G。这个案例说明，Agent 不只是给出“你可以检查内存占用”的建议，而是可以真的进入电脑环境，执行检查、定位问题并进行后续处理。

### 4. Computer Use 的价值在于，把“会用电脑的人才能做的杂活”交给 AI

作者把这种能力称为 “computer use”，即 Agent 在获得授权后可以进入用户电脑环境帮忙干活。它能做的不只是系统排查，还包括整理文件夹、处理本地资料、检查电脑问题等过去需要人工一步步操作的事情。这里的逻辑是：很多电脑任务本身并不难，但步骤琐碎、路径复杂、需要一定经验，普通人容易卡在“我知道大概方向，但不知道具体怎么点、怎么查、怎么整理”。Agent 的优势就在于，它可以把这些琐碎步骤自动拆解成待办项，并持续执行到有结果。作者强调，这些过去“只有人才能做到的事”，现在都可以交给 Agent 试一试，这意味着个人工作流中的大量低价值操作会被自动化。

### 5. Agent 的第二大能力是 Browser Use：打开浏览器后，它可以去网上完成调研、爬取和整理数据

除了操作本地电脑，Agent 还能操作浏览器，这就是作者提到的 “browser use”。视频里提到，只要点击“小眼睛”图标，把浏览器开关打开，Agent 的能力就从电脑扩展到网络。作者建议模式选择“标准”即可，只有当任务执行结果不理想时，再尝试“旗舰”模式。随后他演示了一个典型数据收集任务：让 Agent 调研 GitHub 上当年 1 月到 5 月最受欢迎的 100 个项目，并把数据写入多维表格。Agent 最后以 star 数作为“最受欢迎”的核心依据，整理了 100 个项目，包括项目简介、地址、star、fork 等信息，整个过程不到 5 分钟。作者认为，这直接节省了几个小时的手工检索、复制、清洗和录入时间。

### 6. 成功完成的任务可以沉淀成可复用工作流，提升长期效率

视频里提到，当你每成功完成一次任务，都可以考虑把它变成一个可复用的工作流，文字稿中识别成 “spill”，结合语境更可能是在说类似 “skill / 技能 / 工作流” 的能力。以 GitHub 调研任务为例，用户可以把“调研 GitHub 热门项目并写入多维表格”这个过程保存下来。以后只要再次提出类似需求，Agent 就会按照同样方式创建同样结构的表格，不需要重新教它一遍。这一点非常重要，因为 Agent 的价值不只是单次帮你干活，而是可以把一次成功经验标准化、模板化、流程化。长期看，这会把用户自己积累的工作方法变成一套可重复调用的自动化能力。

### 7. 指定工作文件夹和项目分组，是管理 Agent 任务的重要习惯

作者提醒，Agent 每次执行任务时会产生很多工作文件，不仅包括最终成果文件，还可能包括中间文件、运行环境、依赖文件等。如果不加管理，任务越多，文件就越容易混乱。因此作者建议，在任务开始时就给 Agent 指定一个文件夹作为工作目录。这样一来，放到目录里的文档也会自动成为任务上下文，用户不需要每次单独上传给 Agent 读取。视频还提到左侧有“分组”这种项目管理方式，作者按自己的习惯做了分类。这背后的逻辑是：Agent 越能干，越需要用户建立任务边界和文件秩序，否则自动化能力会反过来制造信息混乱。

### 8. Agent 可以帮普通人“手搓小工具”，让非技术用户也能进入轻量开发

作者展示的另一个案例是“猫猫番茄钟”：可以设置工作时间和休息时间，时间一到猫猫就爬进屏幕阻止用户继续工作，提醒休息。作者参考了某个已有工具的思路，但想把里面的猫咪换成自己的，于是先做了一张猫咪动态图，再让 Agent 参考目标功能和交互逻辑进行开发。整个过程经历了三到四轮对话就完成了，而且作者强调自己没有进行任何技术沟通，只是把使用体验反馈给 Agent，让它不断调优。这个案例说明，Agent 正在降低软件开发门槛：用户不必懂代码，只要能描述需求、反馈体验，就可以做出满足自己需求的小工具。作者鼓励大家以后“放心大胆地去 web coding”，去体验这种创造感。

### 9. 用语音和 Agent 沟通，能提供更完整的上下文，比刻意写短 prompt 更有价值

作者提到，自己日常会用语音方式和 Agent 交流。这里的关键不是“语音转文字”本身，而是语音能减少用户在打字时的自我压缩。打字时，人往往会下意识把话说短、说清楚，但很多灵感、背景、限制条件、模糊想法也会在这个压缩过程中被删掉。相反，用语音时，用户可以把脑子里的想法直接“倒出来”，想到什么说什么，不必一开始就追求逻辑完美。作者认为，相比一个漂亮的 prompt，模型更需要的是完整的上下文；他说自己经常不知不觉把一个问题描述三五分钟，结果需求反而表达得更充分。这其实也是 Agent 使用的核心技巧：不要只给一句命令，要给足背景、目标、偏好和反馈。

### 10. 工作台和专家套件代表 Agent 的进一步进化：不只交付结果，还搭建生产环境和专业方法

视频后半部分提到，Codework 除了通用模式，还有设计模式、写作模式、幻灯片模式等“工作台”。例如，当作者想做一个“小红书风格网页”时，通用模式下会得到一个 HTML 和一些中间文件，结果看起来不错，但如果要修改细节，还得切换到其他工具。但如果换到设计模式，输出的不只是一份 HTML，而是一整套可以编辑的设计环境，体验上像 Figma 一样。作者认为，工作台的本质是把 Agent 的任务执行能力往前推进一步：它不只是给你一个结果，还同时帮你搭建生产环境。另一个功能是左上角的“专家套件”，更像是给 Agent 补充专业知识和任务拆解方法，适用于合同、产品、财税、法务等细分场景。通用模型也许能回答这些问题，但专家套件更知道“这个任务该怎么看、怎么拆、怎么输出”。

## 值得记住的点 / 行动建议

### 1. 先把 Agent 当作“会操作电脑的助手”，从本地杂活开始试

普通人不要一开始就把 Agent 用在特别复杂、抽象的大项目上，可以先从电脑卡顿排查、文件整理、资料归档、本地文档处理这类任务开始。因为这些任务目标清楚、过程琐碎，非常适合测试 Agent 的 Computer Use 能力。比如你可以直接说：“帮我检查电脑为什么变慢，找出占用资源最多的程序，并给出处理建议。”这类任务能让你直观看到 Agent 如何生成待办清单、执行命令、分析结果、继续下一步。只要注意授权边界，不让它处理敏感文件，就可以比较安全地熟悉 Agent 的工作方式。

### 2. 做网络调研时，让 Agent 同时完成“搜索、筛选、结构化、表格化”

视频中的 GitHub 热门项目案例非常典型：用户不是让 Agent 简单回答“有哪些热门项目”，而是要求它调研指定时间范围、指定数量、指定指标，并输出到多维表格。这个思路可以迁移到很多场景，比如竞品调研、供应商名单整理、论文资料收集、招聘岗位分析、产品价格对比等。关键是任务要说清楚：数据来源、时间范围、数量要求、排序标准、表格字段、输出格式。比如可以说：“帮我调研 2026 年 1 月到 5 月 GitHub 上 star 增长最快的 50 个 AI 项目，字段包括项目名、链接、简介、star、fork、主要语言、适用场景，并整理成表格。”这样 Agent 就不只是“搜一下”，而是直接完成可用的数据资产。

### 3. 每个成功任务都要沉淀成工作流，不要只做一次性使用

作者提到的可复用工作流非常关键。很多人使用 AI 的方式是一次性提问，用完就结束，下次还要重新描述一遍需求。更高效的方式是：当某个任务执行效果不错时，把步骤、格式、判断标准保存成模板，让 Agent 以后按同样方法执行。比如“GitHub 热门项目调研”“客户询盘背景调查”“小红书选题表生成”“周报汇总”“竞品价格监控”等，都可以变成固定工作流。这样你实际上是在把自己的工作方法训练成一套可重复调用的自动化系统。

### 4. 给 Agent 指定工作目录，避免文件和上下文混乱

Agent 在执行复杂任务时会产生环境文件、依赖文件、中间文件、结果文件，如果不管理，很容易让电脑目录变乱。因此一个实用习惯是：每个项目都建立独立文件夹，并在任务开始时明确告诉 Agent：“请把所有文件都放在这个文件夹里，并把这里的资料作为上下文。”这样做有两个好处：一是便于后续查找结果，二是便于 Agent 自动读取相关材料。尤其是涉及文档、表格、图片、代码、网页设计的任务，工作目录能让上下文持续存在，不必每次重新上传。长期使用 Agent 的人，一定要把“文件夹即项目上下文”作为基本工作方法。

### 5. 用语音讲需求时，不要急着压缩，尽量把背景说完整

作者强调，语音沟通的价值不是简单提高输入速度，而是保留更多上下文。打字时，人会自然压缩信息，只写“帮我做个网页”“帮我整理数据”，但 Agent 往往需要知道网页风格、受众、用途、参考对象、输出格式、修改偏好等细节。用语音时，可以像跟同事交代任务一样，把想到的背景、目标、限制、例子和担忧都说出来。哪怕一开始逻辑不完美，也比一句短 prompt 更容易让模型理解真实需求。尤其在做设计、写作、开发小工具时，完整上下文通常比“精致 prompt”更重要。

### 6. 让 Agent 做设计或写作时，优先使用对应工作台，而不只是通用模式

通用模式适合广泛任务，但如果你明确要做网页设计、PPT、文档或写作，使用对应工作台通常更高效。视频里的例子显示，同样是做网页，通用模式可能只给 HTML 和中间文件，而设计模式会直接提供一套可编辑的设计环境。这意味着后续修改会更方便，不需要再在多个工具之间来回切换。写作模式、幻灯片模式也类似，它们不是简单输出一段内容，而是更接近完整生产环境。普通用户使用时可以先问自己：我最终想要的是“一个答案”，还是“一个可继续编辑的作品”？如果是后者，就应该优先选择工作台。

### 7. 遇到专业任务时，不要只依赖通用模型，尽量启用专家套件

合同、产品、财税、法务这类任务有明显专业边界，不能只靠通用回答。视频里提到，专家套件像是给 Agent 补充专业知识，帮助它理解任务该怎么看、怎么拆、怎么输出。比如合同审查不是简单润色文字，而是要识别风险条款、责任边界、违约条件、付款节点、争议解决方式等。财税任务也不仅是做表，而是要理解凭证、税率、成本、合规风险。普通人使用这类功能时，应该把专家套件当作“专业框架补充”，但最终重要法律、税务、合同决策仍然应由专业人士复核。

### 8. 对 Agent 的输出要持续反馈，而不是期待一次完美

猫猫番茄钟案例说明，作者并不是一次就得到完美工具，而是经历了三到四轮对话，不断反馈体验，让 Agent 调优。使用 Agent 的正确心态不是“我说一句，它必须一次做对”，而是把它当作可以快速迭代的协作者。你可以反馈：“这个按钮太小”“提醒出现得太突然”“动画太挡视线”“休息时间结束后要自动消失”。这些体验型反馈比技术指令更适合普通用户，也更符合 Agent 的工作方式。只要你能判断结果好不好，并清楚说出哪里要改，就可以参与创造。

## 我的点评

这个视频的核心判断是有道理的：Agent 的真正价值确实不在于“更会聊天”，而在于把搜索、操作、整理、执行、迭代这些动作串起来，完成真实任务。它特别适合处理那些流程固定、信息量大、操作繁琐但判断难度不极高的工作，例如资料整理、网页调研、表格生成、本地文件管理和轻量工具开发。需要注意的是，视频呈现的是比较理想化的成功案例，实际使用中 Agent 仍可能出现误操作、理解偏差、爬取失败、格式错误或安全风险。尤其涉及电脑权限、账号登录、合同财税法务等敏感场景，用户不能完全放手，仍要保留审核和确认环节。普通人最适合的用法，是先把 Agent 用作“效率放大器”，从低风险、高重复的任务开始，逐步建立自己的工作流和文件管理习惯。
