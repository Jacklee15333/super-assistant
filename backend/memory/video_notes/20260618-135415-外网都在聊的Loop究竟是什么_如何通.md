## 背景与主题

视频围绕最近外网热议的 **Loop / 循环工程** 展开，作者认为它正在取代年初爆火的 Prompt Engineering，成为 AI Agent 使用的新核心。作者提到，Claude Code 相关创始人/开发者表示，从 **4.6 版本开始，他们已经不再跟 agent 对话，而是跟 loop 对话**。X 上关于“loop 正在取代提示词工程师”的帖子在 **6 月 8 日**已经达到 **170 万浏览量**，另一个关于用 Claude Code 新发布的 **Fable 5** 模型设计循环的帖子，也超过了 **180 万浏览量**。作者站在 AI 工具开发者和 Agent 使用者的角度，重点解释 Loop 是什么、为什么重要、怎么设计才有效，以及 Scream Code 里如何通过“目标 + 笔记系统 + 裁判机制”提升循环成功率。

## 核心观点

### 1. AI Agent 的使用范式正在从 Prompt Engineering 转向 Loop Engineering

作者一开始就指出，最近外网大量讨论 **loop**，并把它和过去流行的 **prompt engineering** 做对比。过去使用 AI 的核心是写好 prompt：你输入一个提示词，AI 返回结果，你再根据结果继续补充、纠错、追问或重新要求。这个过程看似人在指挥 AI，实际上每一步都需要人来判断 AI 哪里错了、下一步该怎么做，所以人始终被困在循环里面。作者认为，这种方式已经越来越像“人在给 AI 当保姆”，而不是在真正享受 AI 带来的效率提升。Loop Engineering 的出现，就是要把人从这种不断纠错、不断补 prompt 的低效角色中解放出来。

### 2. Loop 的本质是让 AI 在明确目标和验收标准下自我循环、自我修正

视频里对 Loop 的解释很直接：**Loop 就是循环**。但这里的循环不是简单地重复问答，而是让 Agent 围绕一个目标，不断执行、检查、纠错、改进，直到达到某个预设的合格线。过去没有 loop 时，AI 的每一步都会停下来等人给新的 prompt；现在的 loop 则是人先写好规划和及格线，让 AI 在自己的管道里“自己死磕、自己聊天、自己试错、自己改”。用户不再需要一步一步告诉它“这里错了”“那里不该这样”“你应该如何如何”，而是从过程监督者变成最终验收者。作者把这种变化概括为：过去你是循环中的一员，现在 AI 自己在循环里跑，你只需要验收是否合格。

### 3. “AI 做红烧肉”的比喻说明了 Loop 的四个关键阶段

作者用一个非常形象的“把 AI 关进厨房做红烧肉”的例子解释 loop。第一步，你给 AI 一张单子，告诉它“今晚八点我要吃到红烧肉甜口蛋”，这对应功能层里的**目标设定**。第二步，AI 开始第一轮工作，比如把肉炖了，但发现没熟，于是进入第二轮**自主纠错**：判断火候不够，自己重新下锅加热。第三步，引入一个独立裁判，肉炖好了以后，裁判尝一口说“太难吃，重做”，于是 AI 继续回到流程里修改。第四步是**记忆罗盘**，AI 记下“刚才放了一勺盐太淡了”“肉煮轻了，要更久一点”等经验，然后继续循环，直到裁判认为味道不错、目标达成，门才打开，AI 把红烧肉送出来。这个例子把 Loop 的核心结构讲清楚了：目标、执行、反馈、记忆、再执行、最终验收。

### 4. 好的 Loop 不是“让 AI 无限跑”，而是要有目标、管道和及格线

作者强调，Loop 不是盲目地让 AI 不停干活，而是要把目标设定清楚、把 loop 规则设定明白、把 Agent 的 loop 机制调教好。很多 Agent 工具里都有类似 **go** 的选项，这个 go 就是启动目标导向循环的入口。用户需要先明确：到底要 AI 完成什么任务，什么结果算合格，什么情况下需要重试，什么时候必须停下来交给人验收。没有目标和及格线的 loop 很容易变成 token 黑洞，AI 可能反复碰壁、反复生成无效内容，最后不仅没有提高效率，反而浪费算力和时间。作者真正推崇的不是“循环本身”，而是有边界、有记忆、有评判机制的有效循环。

### 5. 有效 Loop 的关键不是状态机复杂，而是每次循环都有清楚记忆

作者在讲 Scream Code 的循环机制时，特意说要“抛开复杂的状态机，讲要点”。在他看来，循环本身并不难做，真正难的是**如何有效循环**，因为没有人希望设定一个任务后，AI 在里面反复碰壁，白白浪费 token。作者认为 Loop 的底层核心问题只有一个：**如何让每次循环对话都有清楚的记忆**。市面上很多 Agent 的做法，是抓取最后一次聊天内容，再结合目标开启新一轮循环，然后继续抓取新聊天和目标再循环。作者认为这种方式“也许能成，但绝对不是最佳选项”，因为它过度依赖最近上下文，容易丢失历史错误、判断依据和中间经验。

### 6. Scream Code 的做法是加入 `write_goal_note`：让循环自带“笔记本”

作者介绍，自己在 **Scream Code** 中加入了类似 `write_goal_note` 的机制，可以理解为一个随着 loop 存在的笔记系统。每次循环中的内容、要点、错误、正确经验，AI 都会记录到这个“小笔记本”里。这样下一轮循环不是从零开始，也不是只看最后一次聊天，而是能带着之前的经验继续推进。比如红烧肉例子里，AI 会记下“刚才盐放少了”“肉煮得不够久”，这就是所谓的“记忆罗盘”。等最终目标达成后，这个临时笔记本就可以扔掉。作者认为，这套机制可以极大提高 loop 的成功率，因为 AI 每次循环都能吸取上一次失败的教训，而不是重复犯错。

### 7. Loop 会把人从“监督 AI 干活”变成“批作业的人”

作者认为，从结果和发展趋势看，Loop 会极大解放人类时间。过去使用 AI 时，人需要不断监督它、纠正它、提示它，实际上还在深度参与执行过程。Loop 机制成熟后，人会从“监督 AI 干活的人”变成“批作业的人”：AI 自己执行、自己检查、自己重试，最后把结果交出来，人只需要判断是否通过。这个变化会显著提升 Agent 的实际可用性，因为它减少了人工干预频率，也让复杂任务能够连续推进。对个人用户、开发者和企业来说，这意味着 AI 不再只是一个需要频繁提问的聊天工具，而更像一个能在限定范围内独立完成任务的执行系统。

### 8. Loop 有可能减少大模型“得过且过”的问题，因为结果由裁判说了算

作者特别提到，随着 loop 不断优化和迭代，它会消灭大模型那种“得过且过，我认为不错”的幻觉式交付。很多大模型在没有外部检验机制时，会倾向于给出一个看似合理但未必真正达标的结果，然后用自信语言包装出来。Loop 的关键改进在于：**AI 的结果自己说了不算，裁判说可以才 OK**。这里的裁判可以是测试用例、规则检查器、评分模型、人工验收、代码运行结果，或者某种独立评估机制。只要裁判机制足够清晰，AI 就不能只靠“看起来不错”过关，而必须通过可验证的标准。这个逻辑尤其适合代码、数据处理、文档生成、自动化流程等需要明确验收标准的任务。

### 9. Loop 会把失败经验资产化，让 Agent 越用越聪明

作者进一步指出，Loop 带来的价值不只是单次任务效率提升，还有长期的组织经验沉淀。只要 AI 在循环里失败，错误就会被记录下来；只要错误被记录，它就可能变成下一次避免犯错的经验。作者称这种机制会让“组织经验资产化”，也就是把过去分散在任务过程中的失败、纠错、判断、规范，变成 Agent 工具持续学习和复用的资产。对于团队来说，这很重要，因为 AI 不只是完成一次任务，而是在每一次循环中积累做事方法。长期看，一个拥有高质量循环记忆、评估规则和失败记录的 Agent，会比只靠临时 prompt 的 Agent 更稳定、更懂团队规范。

### 10. Loop 不是万能药，小白盲目开启可能批量制造“精妙垃圾代码”

作者最后提醒，Loop 的效率提升很恐怖，但它也会带来负面问题。尤其是如果用户什么都不懂，只是盲目开启循环，AI 可能不会帮你自动产出好代码，而是全自动、批量化地制造出更多“精妙的垃圾代码”。这里的“精妙垃圾代码”指的是看起来复杂、完整、有结构，但实际设计错误、质量低下、难维护、不可用甚至存在安全问题的代码。Loop 会放大 AI 的执行能力，也会放大错误方向上的产出速度。作者因此强调：**想明白、规范好，比盲目开启 loop 循环更重要**。也就是说，Loop 的前提不是“让 AI 自由发挥”，而是人要先定义好目标、边界、质量标准、记忆机制和评判机制。

## 值得记住的点 / 行动建议

### 1. 不要只学写 prompt，要学会设计循环

视频最核心的建议是：未来使用 AI Agent，不应该只停留在“怎么写一个好 prompt”，而要学会“怎么设计一个好 loop”。Prompt 更像是一次性指令，而 Loop 是一个持续执行系统。真正高质量的 AI 工作流，需要目标、步骤、反馈、记忆、评估和终止条件。普通用户如果只会不断补充 prompt，效率提升会有限，因为你仍然在参与每一步执行。更好的方式是提前设计好任务目标和验收标准，让 AI 在这个框架里自主迭代。

### 2. 开始 Loop 前，先把目标写清楚

Loop 的第一步不是点击 go，而是明确目标。目标越模糊，AI 循环越容易发散；目标越清楚，AI 才越容易判断自己离结果还有多远。比如“帮我优化代码”就不如“在不改变功能的前提下，将这个模块拆成三个函数，并通过现有测试”；“帮我写文章”也不如“写一篇 1500 字中文科普文，面向非技术读者，结构包括背景、案例、风险和建议”。作者用“今晚八点我要吃到红烧肉甜口蛋”的例子说明，目标必须包含任务对象、完成时间、结果形态和基本偏好。没有清楚目标的 Loop，本质上只是让 AI 在雾里狂奔。

### 3. 给 AI 设置“及格线”，不要让它自己宣布完成

作者反复强调，Loop 的关键是要有验收标准，也就是“裁判”。没有裁判时，AI 很容易觉得“我已经做得不错了”，但实际结果可能不准确、不完整、不可运行。对于代码任务，裁判可以是单元测试、编译结果、lint 检查、性能指标、安全扫描；对于文档任务，裁判可以是字数、结构、术语一致性、事实核查清单；对于业务流程任务，裁判可以是是否满足客户需求、是否覆盖边界条件、是否有明确交付物。用户最好在任务开始前就写清楚“什么算通过，什么必须重做”。这样 AI 的循环才不会停在“看起来差不多”，而会朝着明确标准逼近。

### 4. 给 Loop 配一个“笔记本”，记录每轮对错和经验

作者认为有效循环的核心是记忆，因此推荐类似 `write_goal_note` 的笔记机制。每轮循环结束后，AI 应该记录这轮做了什么、哪里失败、哪里有效、下一轮要避免什么。这样下一轮不是重新猜，也不是只依赖最后一条聊天记录，而是带着累积经验继续推进。对个人用户来说，即使工具没有内置 `write_goal_note`，也可以手动要求 AI 在每轮后维护一个“任务笔记”或“错误清单”。例如可以让 AI 始终更新三块内容：当前目标、已尝试方案、失败原因与下一步计划。

### 5. 引入独立评估机制，避免 AI 自评自夸

一个高质量 Loop 不应该完全依赖同一个 AI 自己生成、自己检查、自己通过。作者用“裁判尝红烧肉”的例子说明，最好有独立评估环节。这个裁判可以是另一个模型、测试脚本、规则系统、人工验收，也可以是外部工具运行结果。尤其在代码、数据、财务、医疗、法律等高风险任务中，AI 自己觉得对不代表真的对。实际使用时，可以把任务拆成“生成者”和“评审者”两个角色，让评审者严格指出问题，再让生成者修改。这样比单模型一次性输出更可靠。

### 6. 设计 Loop 时要考虑停止条件，避免浪费 token

Loop 不等于无限循环。作者提到，没人希望设定一个任务后，让 AI 各种碰壁，白白浪费 token。一个实用的 Loop 应该设置停止条件，比如最多循环几轮、连续两次无改进就停、测试全部通过就停、遇到权限或信息不足就停、成本超过预算就停。没有停止条件的 Agent 可能会不断重写、不断尝试、不断生成看似努力但没有价值的内容。好的循环应该既能让 AI 自主推进，也能在无效时及时刹车。这样才能把 Loop 变成效率工具，而不是成本黑洞。

### 7. 把错误沉淀成组织资产，而不是让它一次性消失

视频里很有价值的一点是“组织经验资产化”。每次 AI 失败，如果只是当场修掉，下次还可能再犯；但如果把失败原因、修正方法、规范要求记录下来，就会变成团队长期资产。比如代码项目可以沉淀为开发规范、测试清单、常见坑列表；内容团队可以沉淀为风格指南、禁用表达、事实核查规则；客服团队可以沉淀为异常案例库和标准回复流程。Loop 的长期价值，不只是完成眼前任务，而是让组织越来越会使用 AI。越早建立错误记录和复盘机制，Agent 的长期表现越可能稳定提升。

### 8. 小白不要盲目开 Loop，要先理解任务和规范

作者最后的警告非常重要：如果用户什么都不懂，Loop 可能不是提高质量，而是更快地产生垃圾。特别是在编程场景中，小白可能无法判断代码架构是否合理、安全性是否有问题、依赖是否乱用、边界条件是否缺失。AI 一旦进入自动循环，就可能生成大量“看起来很高级”的复杂代码，但这些代码实际不可维护、不可扩展、甚至无法运行。因此，在开启 Loop 前，用户至少要明确基本规范、验收标准和风险边界。Loop 适合放大清晰目标和专业判断，不适合替代所有判断。

### 9. 把自己从“过程指挥者”升级成“结果验收者”

使用 Loop 的最终目标，是改变人与 AI 的协作关系。过去人要不断告诉 AI 下一步怎么做，像项目经理盯着实习生逐步执行；现在人应该尽量把任务目标、规则和评估机制设定好，让 AI 自己在内部完成过程迭代。这样人的精力可以从琐碎纠错转向目标设计、质量验收和策略判断。对个人工作者来说，这意味着你可以同时让多个 Agent 跑不同任务，最后集中批改结果。对团队来说，这意味着管理重点从“人盯 AI”转向“制度管 AI”。

## 我的点评

这个视频抓住了 AI Agent 发展的一个关键趋势：从单轮 prompt 到多轮自主循环，确实是让 AI 从“聊天助手”走向“执行系统”的重要一步。作者强调目标、及格线、裁判和记忆机制，这些判断很有价值，尤其适合代码生成、文档生产、数据处理、自动化测试等可验证任务。不过，视频里“Prompt Engineering 已经过时”的说法略显绝对，现实中 prompt 仍然是设定目标、规则和角色的重要入口，只是它不再是全部。Loop 的风险也不能低估：如果目标错、评估错、记忆错，AI 会在错误方向上越跑越远，甚至以更高效率制造低质量结果。普通人最适合采用的方式，是先在低风险任务里尝试小循环，逐步建立目标模板、检查清单和错误笔记，而不是一上来就把复杂任务完全交给 Agent 自主运行。
