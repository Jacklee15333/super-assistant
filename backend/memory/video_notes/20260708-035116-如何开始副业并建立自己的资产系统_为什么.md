## 核心观点

### 1. 副业的起点不是寻找大项目，而是认真做好一件小事
很多人做不成事情，是因为总想着找到一个足够大的项目，等待一个足够好的机会，然后集中精力一口气完成。他们往往把创业想得过于宏大，认为必须先有完整的商业模式、成熟的技术、充足的资金和明确的市场机会才能开始。但分享者认为，真正有效的起点恰恰相反：先找到一件具体的小事，然后认真把它做好。
这件小事不一定很有技术含量，也不一定看起来有多大的商业价值。关键是它真实存在、能够解决某个问题，并且可以通过持续实践不断改进。做一件小事的过程中，你会逐渐发现需要哪些知识、哪些技能、哪些工具，以及别人是否也存在同样的需求。
当一件小事被反复做好，就有机会从个人经验变成标准化的方法，再从标准化的方法变成产品。副业也就不再是单纯依靠个人额外劳动换钱，而是开始拥有可以积累、传播和重复使用的成果。
核心逻辑：不要等待一个大机会，而要通过持续完成小事情，逐渐构建出一个有商业价值的机会。

### 2. 已经有工作的人，应该从工作中寻找可以资产化的重复任务
分享者特别提醒已经有工作的人：
如果你现在有工作，请你不要讨厌你的工作。

既然已经在做这份工作，就应该认真观察工作内容，寻找其中哪些事情非常重要、不断重复出现，而且繁琐、枯燥、令人不愿意做，却又必须每天完成。
他实际上提出了一套寻找副业机会的方法：
- 找到工作中反复出现的任务。
- 判断这些任务是否具有固定的执行规律。
- 分析哪些步骤可以标准化。
- 将其整理成流程、模板或自动化工具。
- 观察其他人是否也存在相同的问题。
- 将解决方案发布到网上，寻找潜在用户。

例如，工作中可能经常需要制作PPT、组织会议、整理论文、编写文档等。这些事情虽然每次都需要完成，但实际上很多操作具有重复性。
如果能够把PPT制作经验整理成模板，把会议组织经验整理成会议流程，把文档写作方法整理成标准模板，就不再需要每次从零开始。
更重要的是，其他公司、团队和个人可能也需要类似的东西。原本只是自己工作中的一项重复任务，现在却可能成为能够向其他人提供的产品。
这里有一个重要的思维转换：
不要只想着如何把工作完成，而要思考如何让这项工作以后不必每次都由自己重新完成。
这就是从劳动中提取资产的第一步。

### 3. 无法将本职工作产品化的人，可以利用业余时间独立构建产品
分享者考虑到了另一种情况：有些人的工作内容涉及保密信息、内部业务数据或特殊工作流程，不能直接将工作成果拿出来公开销售。
对于这类人，他给出了另一条路径：自己寻找一件值得长期构建的小事，每天投入固定时间，持续积累成果。
他提出的时间安排是：
- 每天至少投入1个小时。
- 周末也要保持投入，可以安排周六、周日各1小时。
- 不要试图一次完成整个项目。
- 今天完成一点，明天再完成一点，后天继续完善。
- 通过持续积累，让一个原本很小的东西逐渐变得完整。

他列举了一些可以尝试的方向：

| 产品方向 | 具体构建内容 |
| --- | --- |
| PPT模板 | 将常见的PPT制作需求整理成可复用模板 |
| 邮件模板 | 将重复使用的邮件内容、沟通场景标准化 |
| 手机信息自动生成 | 探索手机背景信息、内容等自动生成方式 |
| 文本自动化 | 实现文本自动整理、文章生成等功能 |
| 自学模板 | 将个人学习方法整理成可重复使用的模板 |
| 打卡系统 | 构建能够帮助别人持续学习和完成任务的系统 |

这些项目有一个共同特点：不需要一开始就做得非常大，也不要求一次性完成。
真正重要的是每天都能产生一点实际成果。
分享者还提出，可以暂时采用 Build in Public（公开构建）的方式，一边做产品，一边把构建过程公开出来，让别人看到你在做什么、解决什么问题，以及产品是如何逐渐完善的。
这样做不仅是在开发产品，也是在积累潜在用户、公开展示能力和获取反馈。

### 4. 不要把学习当成做事的替代品，必须通过实际构建发现自己需要学习什么
这是视频中非常值得重视的一条观点。
分享者对一种常见现象提出了直接批评：
有些人会说自己已经学习了两年、上了很多课程、读了大量书籍，但实际上始终没有做出任何具体成果。
他明确强调：
认真做一件事，不允许给我去阅读，不允许给我去学习，不允许给我去上课。

这里并不是说阅读、学习和上课没有价值，而是反对把学习本身当作完成任务。
正确的顺序应该是：
**1. 先确定自己要做什么。**
**2. 开始实际构建。**
**3. 在执行过程中发现具体问题。**
**4. 针对问题学习所需要的知识。**
**5. 把学到的知识立即应用到项目中。**
**6. 继续构建，直到问题得到解决。**

例如，如果你正在制作一个自动生成文章的工具，可能会遇到文本处理、数据整理、自动化流程等问题。这时候就应该针对这些具体问题学习相应知识，而不是先花半年时间把所有相关课程学完，再考虑开始制作。
这种方式的本质是问题驱动学习。
学习应该服务于构建，而构建又会不断产生新的学习需求。
真正有效的学习，不是让自己感觉知道了很多，而是让自己能够完成过去无法完成的事情。

### 5. Build in Public 和 Learning in Public：公开构建、公开学习，把别人遇到的问题变成产品机会
分享者认为，做一件事情不能只停留在自己内部，还应该尽可能把构建过程公开出来。
他提到两个重要概念：
- Build in Public：公开构建。 把产品从想法、开发、测试到完善的过程公开展示。
- Learning in Public：公开学习。 把自己解决问题、掌握技能和形成经验的过程公开分享。

具体来说，无论你做的是文章、短视频，还是其他内容形式，都应该把自己正在做的事情展示出来。
但他特别强调，不要一开始就把注意力放在流量上，也不要因为暂时没有多少人观看就停止。
真正重要的是：只要有人提出与你正在构建的东西相关的问题，就主动帮助对方解决。
例如，你正在开发一个PPT模板系统，别人询问如何快速制作某类PPT，你就可以主动帮助他；你正在制作一个自学打卡工具，别人询问如何解决学习过程中无法坚持的问题，你就可以提供帮助。
在这个过程中，你实际上是在接触真实用户、了解他们的问题、验证自己的解决方案。
公开内容也会逐渐积累成一个长期存在的资料库。后来的人可能通过文章、视频或其他内容找到你，进一步了解你的产品。
因此，公开构建不只是宣传手段，更是一个持续获取需求、积累用户和完善产品的过程。

### 6. 初期不要急着收费，免费帮助别人实际上是在构建自己的产品
这是整段视频中最有商业思维的一部分。
分享者反复强调，刚开始不要因为帮别人解决了一点问题，就立即想着收费。
他甚至批评一些人：
好多人帮了个屁大点事，就管人要钱。

他的意思不是永远不收费，而是不要在产品尚未形成、需求尚未验证时，就把每一次帮助都当成独立的收费机会。
他用自己的日常行为举例：每天休息的时候，会主动回答别人提出的问题。
有些人可能认为他是在免费帮助别人，甚至觉得他像一个不求回报的志愿者。但他看待这件事情的角度完全不同。
他认为，别人提出的问题本身就是一种资产。
原因在于：
- 一个人问某个问题，说明这个问题可能真实存在。
- 第二个人也问同样的问题，说明这个问题可能具有一定普遍性。
- 更多人不断提出相似的问题，就意味着存在一群有相同需求的潜在用户。
- 如果自己能够反复解决这些问题，就可以逐渐提炼出一套标准化的解决方案。
- 当解决方案成熟之后，就可以把它制作成产品，提供给更多人使用。

因此，免费回答问题实际上有三个作用：
第一，发现需求。 通过用户的问题了解市场真正需要什么。
第二，完善产品。 通过反复解决相似问题，找到可以标准化的流程和方法。
第三，积累用户。 通过持续帮助别人建立信任，让更多人认识自己的产品和能力。
分享者特别强调，不要认为自己免费帮助别人，就是被别人占了便宜。
他的观点是：
你以为你在免费，人家占你便宜？你记清楚了，人家在帮你构建产品。

这句话揭示了一种不同于传统服务交易的思路：早期的用户互动本身就是产品研发和市场调研的一部分。

### 7. 从免费服务到产品收费，要通过真实需求逐步建立商业门槛
免费帮助别人并不是最终目的。
分享者描述了一条逐渐实现商业化的路径：
免费帮助 → 收集问题 → 形成解决方案 → 产品化 → 用户持续使用 → 建立收费门槛。
当越来越多的人通过公开内容找到你，并且不断使用你提供的解决方案时，你就可以逐渐把这些内容整理成一个完整的产品。
例如：
- 最初只是免费分享PPT模板。
- 后来发现很多人都需要类似的模板。
- 进一步整理成一套完整的模板库。
- 用户开始持续使用这些模板。
- 当产品已经能够稳定解决问题时，就可以设置一个较小的付费门槛。

这个时候，收费就不是凭空向别人索取钱，而是对已经形成的产品价值进行商业化。
这里有一个重要区别：
初期收费，可能只是把个人时间卖给某个客户；而产品成熟之后收费，卖的是已经构建好的解决方案。
后者有机会同时服务更多用户，而不需要为每个人重新完成全部工作。
分享者强调，开始时不要过度关注收入，而应该先关注产品是否真正有用、是否有人需要、是否能够持续解决问题。
先让产品拥有真实价值，再让产品产生收入。

### 8. 从资源提供者转变为配置者，通过自动化、规模化和可复制化建立系统
这是整段视频最终要落到的核心商业逻辑。
分享者把人的赚钱方式分成两个阶段。
第一阶段：资源提供者。
在这个阶段，个人主要提供自己的时间、精力、技能和劳动。
例如：
- 按小时提供服务。
- 按项目完成任务。
- 每次都亲自制作PPT。
- 每次都亲自回答问题。
- 每次都亲自完成重复性工作。

收入主要取决于自己投入多少时间和精力。
如果停止工作，收入也往往随之停止。
第二阶段：配置者。
当某件事情已经被市场证明有需求，别人也愿意持续使用时，就不应该再把全部工作都压在自己身上。
而应该开始思考：
- 如何让产品自动化？
- 如何让更多人同时使用？
- 如何降低每次交付的成本？
- 如何把有效经验变成可以复制的流程？
- 如何在不同比例增加个人劳动的情况下扩大服务规模？

分享者将这一阶段概括为：
你要把这个事自动化、规模化、可复制化。

他还进一步提出三个方向：
**1. 做得更好： 不断优化产品质量，提高解决问题的能力。**
**2. 成本更低： 减少重复劳动，提高生产和交付效率。**
**3. 用户更大： 让更多人能够使用同一套解决方案。**

他将这个过程称为资本化，也就是开始加杠杆、实现规模化和自动化。
这里的杠杆并不只是借钱或者融资，更重要的是利用已经构建好的产品、工具、流程和系统，放大个人创造价值的能力。
最终，个人不再需要每次都亲自完成所有任务，而是通过系统持续提供价值。
这就是从出卖时间赚钱，逐渐转变为依靠资产和系统赚钱。

| 资本化 | 通过自动化、规模化和杠杆放大价值 | 从个人劳动转向系统创造价值 |
| 资产系统 | 可以持续积累、重复使用和提供价值的产品与流程 | 实现长期价值积累 |

## 值得记住的点 / 行动建议

### 9. 先检查自己的工作，列出一份重复性任务清单
不要急着研究副业赛道，也不要一开始就考虑做什么App、开发什么平台。
先把自己目前的工作完整梳理一遍，找出那些每天、每周或者每个月反复发生的事情。
尤其关注以下三类任务：
- 明明很重要，但每次都要花很多时间完成的事情。
- 已经做过很多次，但每次仍然需要重复操作的事情。
- 大家普遍不喜欢做，却又不得不完成的事情。

可以建立一个简单的记录表：

| 任务 | 重复频率 | 当前痛点 | 可产品化方向 |
| --- | --- | --- | --- |
| 制作PPT | 经常 | 每次从头排版 | PPT模板库 |
| 写工作邮件 | 每天 | 重复组织语言 | 邮件模板 |
| 整理会议记录 | 每周 | 信息整理耗时 | 自动化会议纪要 |
| 编写报告 | 每月 | 格式和结构重复 | 报告模板 |
| 整理学习资料 | 经常 | 资料分散 | 自动化知识整理工具 |

重点不是马上决定卖什么，而是找到一个值得反复解决的问题。

### 10. 选定一件小事，每天至少投入1小时持续构建
确定一个方向之后，不要继续无限寻找更好的项目。
给自己设置一个明确的构建任务。
例如，如果选择制作PPT模板，可以拆成：
- 第一天：确定目标用户和PPT使用场景。
- 第二天：整理常见页面类型。
- 第三天：制作封面模板。
- 第四天：制作目录和内容页模板。
- 第五天：完善图表和数据展示模板。
- 第六天：整理成一个可使用的模板包。
- 第七天：找人试用，收集修改意见。

这只是一个执行示例，实际周期可以根据项目复杂程度调整。
关键是每次投入都要留下具体成果，而不是每天只是思考、阅读和规划。

### 11. 遇到问题再学习，把学习变成解决问题的工具
不要把学习和行动割裂开来。
在项目构建过程中，遇到什么问题，就针对性地学习什么知识。
例如：
- 不会设计，就学习相关设计方法。
- 不会自动化，就研究自动化工具。
- 不懂文本处理，就学习文本处理技术。
- 不知道用户需要什么，就去了解真实用户的使用场景。

学习完成后，必须回到项目中应用。
可以用一个简单的标准衡量学习是否有效：
今天学到的东西，有没有让正在构建的产品多完成一个功能，或者解决一个实际问题？
如果没有，就需要反思自己的学习是否偏离了当前目标。

### 12. 尽早公开构建过程，不要等到产品完美才发布
将产品开发过程变成持续的内容输出。
可以选择文章、短视频或者其他适合自己的形式。
内容不需要一开始就非常专业，也不需要每一篇都追求很高的播放量。
可以分享：
- 今天发现了什么问题。
- 今天完成了什么功能。
- 遇到了什么技术困难。
- 是如何解决这个问题的。
- 产品目前能够帮助别人做什么。
- 别人使用之后提出了哪些建议。

这样既可以积累公开内容，也可以逐步形成个人在某个领域的可信度。
更重要的是，公开分享能够让潜在用户找到你，而不是等到产品完成之后才开始考虑如何获客。

### 13. 主动帮助用户，建立真实的问题数据库
不要把每一次用户提问都当作一项孤立的服务。
应该将问题记录下来，并进行分类。
例如：

| 用户提出的问题 | 可能反映的需求 | 后续产品化方向 |
| --- | --- | --- |
| PPT怎么快速制作？ | 办公效率需求 | PPT模板产品 |
| 邮件怎么写更规范？ | 沟通效率需求 | 邮件模板库 |
| 怎样坚持学习？ | 学习管理需求 | 自学打卡系统 |
| 怎样自动生成文章？ | 内容生产需求 | 文本自动化工具 |

当类似问题反复出现，就说明值得深入研究。
建议建立一个简单的问题数据库，持续记录：
**1. 用户原始问题。**
**2. 问题出现的频率。**
**3. 用户目前采用的解决方法。**
**4. 现有方法存在的不足。**
**5. 自己提供的解决方案。**
**6. 用户使用后的反馈。**
**7. 是否值得开发成独立产品。**

这会逐渐形成一个非常有价值的产品需求库。

### 14. 从免费服务开始，但要明确免费服务的目的
免费帮助别人不是无条件投入所有时间。
视频中的思路是：初期通过免费帮助积累问题、经验、反馈和用户，而不是立即将每次帮助变成收费交易。
但执行时应该区分：
- 可以标准化的问题：优先整理成公开教程或模板。
- 反复出现的问题：考虑开发成工具或产品。
- 具有代表性的复杂问题：深入研究，作为产品验证案例。
- 高度个性化的工作：评估是否值得单独提供收费服务。

免费阶段的核心目标，是验证需求并构建产品，而不是无限制地提供私人劳动。
当解决方案已经成熟，用户能够持续获得价值时，就可以考虑设置付费门槛。

### 15. 产品有真实需求之后，再考虑自动化和规模化
不要一开始就把大量时间花在搭建复杂系统上。
应该先通过人工方式把事情做通。
例如，别人需要一份报告模板，你先手动帮助他完成；当越来越多人需要相同的东西，再将制作过程标准化。
当流程已经稳定之后，再考虑使用自动化工具替代重复操作。
可以按照以下顺序推进：
- 第一阶段：自己亲自完成，弄清楚整个流程。
- 第二阶段：把有效方法整理成标准流程。
- 第三阶段：把重复部分做成模板。
- 第四阶段：利用工具自动完成固定步骤。
- 第五阶段：让更多用户能够独立使用。
- 第六阶段：持续降低成本，提高交付效率。

这比一开始就开发一个功能复杂、却没有真实用户的系统更合理。

### 16. 定期从具体工作中抽离方法，逐渐形成个人系统
每完成一项任务，都应该问自己：
- 这次做的事情有没有重复价值？
- 哪些步骤下次可以直接复用？
- 哪些经验可以写成模板？
- 哪些操作可以交给工具？
- 哪些方法可以让其他人也使用？
- 有没有可能把多个方法整合成一个完整产品？

例如，最初只是制作一份PPT，后来发现其中包含内容整理、页面设计、图表制作和表达结构等多个环节。
如果将这些环节分别沉淀下来，就可能逐渐形成一套完整的PPT制作系统。
系统不是一开始就设计出来的，而是在反复实践中形成的。
每一次完成任务，都应该尽量留下可以复用的东西。

## 我的点评
这段视频最有价值的地方，是把副业从寻找项目、寻找风口的思维，拉回到具体的问题解决和资产积累上。尤其是从工作中的重复任务寻找产品机会，以及把用户提问当成需求数据，这两种思路具有很强的可操作性，也符合产品开发中先发现需求、再验证解决方案的基本逻辑。
我尤其认同分享者强调的行动优先于被动学习，以及从人工解决问题逐步走向流程化、自动化的路径。不过，免费帮助别人并不必然意味着能够形成产品，还需要判断问题是否具有足够的普遍性、用户是否愿意付费，以及解决方案是否具有持续价值。另外，并非所有重复性工作都适合产品化，涉及公司商业秘密、客户隐私和知识产权的内容尤其需要谨慎处理。
另一个值得注意的地方是，自动化和规模化并不能自动创造商业价值。如果最初解决的问题没有真实需求，即使做出了复杂的系统，也可能只是增加了开发成本。因此，最好先验证用户是否真的需要，再投入资源扩大规模。
对普通人而言，这套方法最值得借鉴的是：不要等到有了完美的创业计划才开始，而是从身边一个真实、具体、反复出现的问题入手，每天留下实际成果，通过公开分享和用户反馈不断改进，最终把个人经验变成可重复使用的产品。
整段视频最核心的启示是：不要只积累知识和劳动时间，要让每一次劳动都尽可能留下可以重复创造价值的资产；不要一开始就试图拥有一个系统，而要通过持续构建，最终把系统做出来。
