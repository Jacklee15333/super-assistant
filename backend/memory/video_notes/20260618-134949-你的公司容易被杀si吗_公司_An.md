## 🤖 AI 分析

## 一句话概括

这个视频在讲：**很多 AI 应用创业公司表面上是在做公司，实际上可能只是在帮 Anthropic 等模型公司验证某个“未来会被内化进模型能力”的功能；真正不容易被杀死的公司，必须把护城河建在模型能力之外、模型公司不愿意做的重活里，或成为模型层越强自己越赚钱的基础设施。**

## 背景与主题

这段视频讨论的是 **AI 应用层创业公司是否容易被 Anthropic / Claude 这类模型公司“杀死”**。作者从和几个做 AI 应用的朋友讨论出发，指出他们逐渐意识到一个残酷事实：很多 AI 应用公司并不是在建立独立公司，而是在做 “Anthropic 还没做出来的功能”。视频重点分析了浏览器 Agent、Coding 助手、垂直工作流 Agent 等创业方向被 Claude 新能力吸收的案例。作者的角度比较尖锐：他不是单纯唱衰 AI 创业，而是在提醒创业者分清楚自己到底是在做“模型能力外的公司”，还是在为模型公司做免费的产品验证。

## 核心观点

### 1. 很多 AI 应用公司不是公司，而是模型公司未来的功能

作者开头提出一个非常直接的判断：**“我们做的不是公司，我们做的是 Anthropic 还没做出来的功能。”**这句话的核心意思是，很多 AI 应用创业公司看起来有产品、有融资、有用户、有增长，但它们的核心价值其实只是暂时弥补了大模型能力还没覆盖到的空白。一旦 Anthropic、OpenAI、Google 等模型公司把相关能力内化到模型或官方工具里，这些应用公司的差异化就会迅速消失。作者尤其强调，创业公司做得越好，越可能证明这个方向有需求、有付费意愿、流程能跑通，从而给模型公司提供了明确的产品路线图。换句话说，很多 AI 应用不是死于自己做得差，而是死于自己太早、太清楚地证明了某个功能值得被模型公司吸收。

### 2. 浏览器 Agent 是一个典型案例：热潮起来后，Claude 的 Computer Use 直接改变竞争格局

作者提到，去年这个时候有一批做 **浏览器 Agent** 的创业公司估值“疯涨”。所谓浏览器 Agent，大致是让 AI 像人一样操作浏览器，完成打开网页、点击按钮、填写表单、搜索信息、执行任务等动作。后来 Anthropic 推出了 **Computer Use**，也就是让 Claude 能够操作电脑界面、理解屏幕内容并完成任务的能力。作者认为，这类能力一旦进入模型层，原本靠浏览器自动化能力融资和增长的创业公司就会受到巨大冲击。他用了一个很重的说法：那批公司“现在活着不到一半”。这个例子说明，如果一家公司的核心护城河只是“让模型能操作浏览器”，那当模型自己具备这个能力时，公司就会从“产品”退化成“过渡方案”。

### 3. Coding 助手的定位被 Claude Code 改写：从“最好工具”变成“最佳搭档”

第二个案例是 **AI Coding 助手**。作者说，去年也有一批做 Coding 助手的公司融了几千万美金，它们最初的叙事往往是“我们要做最好的 AI coding 工具”。但 **Claude Code** 出来以后，这些公司的核心叙事发生了变化，从“我们是最好的 AI coding 工具”变成了“我们是 Claude Code 的最佳搭档”。这个转变很微妙，也很关键：它意味着这些公司不再处于主导位置，而是被迫围绕模型公司的官方能力重新定位自己。原来它们可能想做开发者入口，现在却可能只能做插件、增强层、适配层、企业部署层。作者借这个例子提醒创业者：如果你的产品核心能力可以被模型公司直接做掉，那么你迟早会从“独立产品”变成“生态配角”。

### 4. 垂直 Agent 可能被一个 `skill.md` 文件替代，说明很多产品只是模型能力的临时包装

第三个案例是 **workflow / vertical agent**，也就是面向销售、客服、法务等场景的垂直工作流 Agent。作者说，去年有一批公司分别做销售 Agent、客服 Agent、法务 Agent，花了两年时间做产品、流程和交互。但 Anthropic 发布了 **Skills** 之后，用户只需要写一个 Markdown 文件，比如 `skill.md`，Claude 就可能变成某个垂直领域 Agent。作者用很夸张但有冲击力的表达说：那些花两年做出来的产品，被一个 `skill.md` 文件替代了。这里的重点不是说所有垂直 Agent 都会被完全消灭，而是说：如果你的产品只是把提示词、流程、工具说明和领域 SOP 包装成一个 UI，那么模型公司很容易用 Skills、系统能力或配置文件把它吸收到模型层。真正危险的是，那些看似是“应用”的东西，本质上只是模型还没内置的工作流模板。

### 5. Anthropic 最“阴”的地方不是明抢，而是等创业公司完成产品验证后再内化

作者认为，Anthropic 最可怕的地方不在于它没看到这些创业公司，而在于它**看到了，但选择等待**。它等创业公司证明这件事可行，等用户愿意付费，等流程跑得通，然后再把这个能力内化进 **model capacity**。这是一种很典型的平台型公司逻辑：先观察生态里哪些需求真实存在，再把最通用、最高频、最有价值的能力吸收到核心平台。作者说，Anthropic 不一定抢 UI 层，而是把原本需要 UI 层做的事情变成“模型自己就能做”。这比直接推出一个竞品应用更危险，因为它不是在和你抢同一个界面，而是在消灭你这个界面存在的必要性。创业者以为模型公司给自己留了空间，但作者认为，很多创业公司其实是在给模型公司做免费的 product validation。

### 6. OpenAI 因为“公开抢”容易被防备，Anthropic 的克制反而更危险

作者特别比较了 OpenAI 和 Anthropic 的不同威胁方式。他说：“OpenAI 大家防了，因为它公开抢；Anthropic 没人防，因为它克制。”这句话背后的逻辑是，OpenAI 经常直接发布面向用户的产品和功能，因此应用层公司会天然警惕它，提前考虑被官方产品替代的风险。Anthropic 看起来更克制、更少直接下场抢 UI 层应用，因此很多创业者误以为自己相对安全。但作者认为，这种克制比抢还可怕，因为它会让创业者继续投入、继续积累真实使用数据、继续把用户行为和业务流程“喂”给模型生态。最终，真正杀死创业公司的可能不是一次声势浩大的发布会，而是 Anthropic 某个版本 Release Note 里一行不起眼的能力提升。

### 7. 不会被杀死的第一类公司：做模型公司永远做不了的东西

作者观察下来，第一类不容易被 Anthropic 杀死的公司，是做 **Anthropic 永远不会做、也很难做的事**。他列举的例子包括：品牌、社区、人和人之间的信任、行业内关系网、监管层面的合规牌照。这些东西不属于纯模型能力，而属于长期积累的社会资产、组织资产和信任资产。比如作者提到疑似 **Midjourney 的 Discord 社区**，这种社区氛围、用户关系和文化认同，Anthropic 很难直接复制；又比如 **Cursor 的 IDE 品牌**，Anthropic 不一定会亲自下场做一个完全相同的 IDE 品牌来抢。作者给出的判断标准非常清楚：如果你的护城河在模型能力上，你“死定了”；如果你的护城河在模型之外，你才有继续活下去的可能。

### 8. 不会被杀死的第二类公司：做模型公司不愿意做的脏活、重活、慢活

第二类不容易被杀死的公司，是做 **Anthropic 不愿意做的事**。作者列举了 B2B 销售、企业合规、医院 IT 对接、银行风控审计等场景。这些事情通常很脏、很重、很慢，涉及复杂组织流程、客户关系、定制化交付、法律责任、内部系统集成和大量非标准沟通。模型公司虽然技术能力强，但它们往往不愿意深入每一家医院、每一家银行、每一个企业客户的流程里做苦活。作者的判断是：你越愿意做模型公司觉得低端、麻烦、不够“性感”的事情，你的位置反而越稳。因为这些事情不能靠一次模型升级解决，它们需要长期的销售、实施、交付和信任建设。

### 9. 不会被杀死的第三类公司：模型越强，自己越赚钱

第三类公司，是那些 **Anthropic 做得越强，反而越受益** 的公司。作者举的例子包括 AI 工作流编排平台、AI 应用基础设施等。如果你做的是模型层的杠杆，而不是模型层的竞争对手，那么 Claude 升级会让你的产品自动变强。比如一个工作流编排平台，如果接入的是 Claude，那么 Claude 能力越强，平台能完成的任务越复杂，客户使用价值也越高。又比如面向 AI 应用的基础设施公司，只要越来越多企业和开发者使用 Claude，就越可能需要你的监控、编排、权限、缓存、评估、数据连接和部署能力。作者把这类公司称为“模型层的杠杆”，而不是“模型层的竞争对手”，这是判断 AI 公司安全性的一个重要标准。

## 值得记住的点 / 行动建议

### 1. 先判断自己是在做“公司”，还是在做“未来模型功能”

AI 创业者最应该先问自己的问题是：如果 Claude、OpenAI 或 Gemini 下一版原生支持我现在的核心能力，我的公司还剩下什么？如果答案是“只剩一个 UI”或者“只剩一套提示词包装”，那风险就非常高。真正的公司应该拥有模型之外的资产，比如客户关系、行业数据闭环、交付体系、合规能力、品牌认知、社区关系或业务流程控制权。如果你现在做的功能可以被模型公司用一次版本更新内化，那就需要尽快调整定位。不要只看当前产品有没有用户，而要看你的价值是不是会随着模型能力增强而被压缩。

### 2. 不要把“模型暂时不会”误认为“模型永远不会”

很多 AI 应用公司的机会，来自模型当前还不够强，比如不会稳定操作浏览器、不会写完整项目、不会理解企业流程、不会自动调用复杂工具。但“暂时不会”并不等于“永远不会”。作者提到的浏览器 Agent、Coding 助手、vertical agent，本质上都是模型能力提升后被快速压缩的方向。创业者需要区分两种空白：一种是技术暂时还没做到，另一种是模型公司因为商业、组织、监管或战略原因不愿意做。前者迟早会被填上，后者才更可能成为创业空间。

### 3. 把护城河尽量放到模型能力之外

如果一家公司的核心壁垒只是“我比别人更会调模型”“我有更好的 prompt”“我包了一层更好看的界面”，那在模型升级面前非常脆弱。更安全的护城河应该在模型之外，例如特定行业的信任、长期客户关系、社区文化、企业内部流程接入、线下交付能力、合规牌照和品牌心智。作者举了社区和品牌的例子，比如疑似 Midjourney 的 Discord 社区、Cursor 的 IDE 品牌，这些都不是 Claude 直接更新一个模型能力就能复制的。普通创业者也可以用这个标准检查自己：如果明天模型免费提供你的核心功能，你是否仍有客户愿意留下来？如果有，留下来的原因是什么？

### 4. 主动去做模型公司嫌麻烦的 B2B 重活

视频里非常实用的一点是：越脏、越重、越复杂的活，反而越可能安全。比如企业合规、医院 IT 对接、银行风控审计、B2B 销售，这些场景不只是模型能力问题，还涉及采购流程、权限系统、数据安全、内部审批、责任划分和长期服务。模型公司通常更愿意提供底层能力和通用产品，而不是深入到每个客户现场做复杂实施。AI 应用公司如果愿意扎进这些场景，就能把自己从“功能供应商”变成“解决方案交付方”。这类公司短期看增长慢、销售周期长，但长期看更不容易被一个模型版本更新杀死。

### 5. 尽量成为模型层的杠杆，而不是模型层的竞争对手

作者给出的第三类安全公司非常关键：**Claude 越强，你越赚钱。**这意味着创业者应该尽量把自己放在模型生态的增强位，而不是替代位。比如做 AI 工作流编排、模型评测、权限治理、日志审计、成本优化、RAG 基础设施、MCP 工具、企业集成平台等，模型越强，客户越需要这些配套系统。反过来，如果你做的是“Claude 还不会的某个具体能力”，那 Claude 一旦会了，你的价值就会下降。判断一个方向好不好，可以问一句：模型升级时，我的产品是被淘汰，还是自动变强？

### 6. 不要只防 OpenAI，也要警惕 Anthropic 这种“克制型威胁”

很多创业者容易盯着 OpenAI，因为 OpenAI 的产品发布更高调，竞争意图也更明显。但作者提醒，Anthropic 的威胁可能更隐蔽，因为它不像 OpenAI 那样频繁公开下场抢应用层，而是通过模型能力和工具能力逐步吸收生态里的成功模式。这种“克制”会让创业者误判安全边界，继续把真实用户数据、使用流程、产品交互和市场需求暴露在模型生态里。对于创业者来说，不能只看模型公司现在有没有做竞品，而要看它们有没有能力、有没有动机、有没有通用化这个功能的可能。一旦某个方向被证明足够通用、足够高频、足够可规模化，就有被模型公司吸收的风险。

### 7. 重新审视 AI 咨询和服务公司的窗口期

作者提到，做服务咨询的人对这种压力会感觉更明显。现在 AI 咨询公司还有空间，是因为 Claude 还没有把“咨询顾问”完整打包成一个能力；但未来版本会不会做到，没有人敢保证。咨询公司如果只是卖“我帮你写 prompt、搭 agent、做自动化流程”，风险会逐渐变高，因为这些能力可能被模型官方工具、模板、Skills 和工作流产品替代。更稳妥的方向是把咨询嵌入客户实际业务结果中，例如帮企业改流程、做组织培训、负责系统落地、承担合规和交付责任。也就是说，AI 咨询公司不能只卖知识差，而要卖执行力、行业理解和落地结果。

### 8. 用“三类安全公司”框架定期检查业务方向

作者最后给出的三类公司，可以当成 AI 创业方向的体检表。第一类是模型公司永远做不了的：品牌、社区、信任、关系、牌照。第二类是模型公司不愿意做的：企业销售、合规、重实施、行业系统对接。第三类是模型公司做了反而帮你的：工作流编排、AI 基础设施、模型生态工具。如果一个 AI 创业项目不属于这三类任何一种，就要认真想清楚：你到底是在创业，还是在为 Anthropic 做无偿研发？这个框架对普通人也有用，不管是做产品、咨询、SaaS 还是个人 AI 工具，都可以用它判断自己的长期安全性。

## 我的点评

这个视频的判断很犀利，也抓住了 AI 应用创业的一个真实风险：**应用层如果只建立在模型暂时不会的能力上，确实很容易被模型升级吞掉**。作者提出的“三类不会被杀死的公司”很有参考价值，尤其是把护城河从“功能”转移到“信任、合规、交付、基础设施、生态杠杆”上，这比单纯追热点更成熟。不过，视频也有一定夸张成分，比如不是所有被模型覆盖的应用都会死，很多公司仍可能通过更好的体验、垂直数据、企业部署、品牌和渠道活下来。需要注意的是，Anthropic 或 OpenAI 的能力增强并不必然消灭所有应用层，而是会压缩那些缺乏差异化、缺乏客户控制权、缺乏场景深度的应用。普通创业者可以把这段视频当成一次战略压力测试：问自己“模型下一版变强后，我的价值是减少，还是增加？”如果答案是减少，就需要尽快把业务往模型之外的护城河迁移。
