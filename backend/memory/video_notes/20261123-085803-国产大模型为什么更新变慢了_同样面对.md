## 🤖 AI 分析

## 一句话概括
国产大模型部分厂商更新放缓，主要不是因为 Anthropic、OpenAI 限制模型蒸馏，而是因为推理业务快速增长挤占训练算力、依靠旧底座进行低成本迭代的空间逐渐耗尽，以及高端训练芯片供给不足；反蒸馏措施则通过增加自主生成训练数据的成本，进一步加重了算力压力。

## 背景与主题
近期，Anthropic 和 OpenAI 加强了针对中国大模型企业的反蒸馏限制，与此同时，智谱、MiniMax 和 DeepSeek 的旗舰模型更新间隔明显拉长，引发了国产大模型是否被美国企业技术封锁拖慢的讨论。
然而，同样受到限制的阿里巴巴和月之暗面仍然保持相对稳定的模型发布节奏，说明反蒸馏限制难以单独解释不同企业之间的差异。作者通过比较五家中国大模型公司的发布周期、算力投入、API 业务增长、训练成本及芯片供应情况，提出一个更具解释力的判断：大模型竞争正在从依靠后训练快速迭代，转向依赖大规模预训练算力和稳定芯片供应的阶段。
视频的核心立场是：蒸馏限制会提高成本，但真正决定下一代旗舰模型能否发布的，是企业能否获得足够的高端训练算力。

## 核心观点

### 1. 国产大模型并非集体放缓，而是五家企业出现了明显分化
作者首先反对“国产大模型集体哑火”的笼统判断，因为五家代表性企业的发布节奏并不一致。视频统计，MiniMax 已经171天没有发布新旗舰，DeepSeek 为209天，智谱为97天，这三家的更新频率相比过去明显下降。相反，月之暗面7月发布 K3、10月发布 K3.1，仍保持三四个月推出一次重大更新的节奏；阿里则在当年推出四代模型，平均约三个月一代，并于视频所说的当月发布千问4。作为对照，Anthropic 当年更新了10次，发布间隔从75天缩短至22天，显示头部模型厂商之间的迭代速度差异正在扩大。
因此，真正需要解释的不是“中国模型为什么都慢了”，而是为什么同处中国市场、面对相似外部限制的五家公司，只有其中三家的更新节奏显著放缓。

### 2. Anthropic 和 OpenAI 确实采取了反蒸馏措施，但封锁程度不能直接解释更新速度
蒸馏（Distillation，知识蒸馏）是利用更强模型生成的回答、推理示例或其他输出，训练另一个模型的技术。视频称，Anthropic 在2月公开点名 DeepSeek、月之暗面和 MiniMax，指控相关主体使用约24,000个虚假账号，与 Claude（克劳德）进行了1,600万次交互。到了9月，又有一份154页的报告涉及7家中国公司，并采取封禁账号等措施；OpenAI 也通过隐藏部分模型思考过程、减少可获得的推理细节来增加蒸馏难度。这些措施意味着，过去通过调用外部先进模型来低成本获得高质量训练示范的方式受到限制。
但是，反蒸馏措施增加了数据获取难度，并不等于企业完全失去训练能力，更不能直接推导出某家公司必然因此延迟发布新模型。

### 3. 被指调用量最大的企业反而没有明显放缓，削弱了“蒸馏限制是主要原因”的解释
作者用一组对比数据反驳简单的因果判断：视频引用的报告显示，阿里相关调用量达到约1.5亿次，月之暗面达到约2,300万次，而智谱只有300多万次。按照“过去越依赖外部蒸馏，封禁以后受到的影响越严重”的假设，阿里和月之暗面本应更容易出现更新延迟。然而，被指调用量最高的两家企业，在封禁措施后的约两个月内分别推出了千问4和K3.1，更新节奏并未明显中断；调用量较少的智谱反而出现放缓。作者还特别强调，这些调用数字来自 Anthropic 平台记录，只能证明存在大量请求，不能单凭调用量证明相关输出确实进入了模型训练流程，更不能证明蒸馏贡献了多少模型能力。
这意味着，视频中呈现的证据不支持把反蒸馏限制视为各公司更新速度差异的唯一或主要解释，但也不能据此断言蒸馏限制毫无影响。

### 4. 算力资源差异，是解释不同公司更新节奏的重要变量
作者认为，阿里能够保持较快迭代，与其云计算基础设施和资本开支规模密切相关。视频称，阿里当年第二季度投入机房和芯片的资金达到677亿元人民币，而智谱整个上半年的收入约为9.5亿元，前者约为后者的71倍。这个比较虽然涉及不同财务口径，但直观反映出大型云厂商与独立模型创业公司在资源规模上的巨大差异。阿里拥有云计算基础设施和庞大的算力采购能力，相较于依赖外部供应商的创业公司，更有条件同时支持模型训练与线上推理服务。
因此，作者认为，对大型云厂商而言，额外的训练成本可能只是可承受的支出；对创业公司而言，同样的成本增长却可能直接影响下一代模型的训练计划。

### 5. 反蒸馏措施的主要作用，是将训练数据生成成本从外部转移到企业自身
大模型训练需要大量高质量数据，例如复杂代码任务的分步求解过程、推理示范、问题与答案，以及其他可用于监督训练的内容。企业可以调用外部先进模型获得这些示范，也可以依靠自身模型反复生成、筛选、验证和改进，但后一种方式需要消耗本公司的计算资源。视频将蒸馏形容为一条捷径：利用其他公司的高性能模型和计算基础设施，为自己的训练过程提供数据。反蒸馏措施限制了这条路径后，企业就需要投入更多算力进行自主数据合成、结果检验和后续训练。
由此产生的核心变化是：原先由外部模型服务承担的部分计算负担，转移到了企业自己的机房或算力账单上。作者认为，反蒸馏机制未必能彻底阻止知识迁移，但能够显著增加相关行为的成本。

### 6. 推理需求爆发式增长，使训练与线上服务争夺有限的显卡资源
视频指出，当年中国大模型市场的调用需求出现高速增长，全国大模型每日调用量相较两年前增长超过1,000倍。智谱自身平台从年初到8月底的调用量增长40倍，API（Application Programming Interface，应用程序编程接口）收入增长27倍，占总收入接近九成。业务规模的迅速扩大意味着，越来越多的 GPU（图形处理器）必须持续投入线上推理，以满足用户调用、保障响应速度和服务稳定性，而这些资源在一定条件下也可以被用于训练。视频举例，智谱在GLM-5发布后曾公开寻求更多显卡、限制部分套餐销售并出现退款；月之暗面的K3上线48小时后也停止接受部分新用户订阅。
因此形成了一个看似矛盾的局面：模型越受欢迎，推理需求越旺盛，企业就越有可能将有限算力优先分配给现有用户，进而压缩下一代模型训练的资源空间。

### 7. 商业化越成功，训练新模型的机会成本反而可能越高
作者进一步指出，算力资源分配不仅是技术问题，也是收入、现金流和经营决策问题。一张 GPU 如果用于向付费用户提供 API 服务，当天就可能产生收入；如果用于训练下一代模型，则需要先支付较高成本，模型能力提升与商业回报可能要几个月以后才能体现。视频称，智谱和 MiniMax 在当年1月上市后，需要定期向资本市场提交经营成绩，进一步增加了收入增长与成本控制的重要性。智谱虽然表示会优先保障关键训练窗口，但同时又不得不限制销售，说明训练和推理两端都存在较强的资源需求。
这种压力可能使企业被迫在短期收入和长期模型竞争力之间作出权衡。当用户增长速度快于算力扩张速度时，商业化成功本身就可能成为研发资源紧张的诱因。

### 8. 过去模型更新频繁，部分原因是反复优化同一个底座，而不是每次都从头训练
作者认为，理解模型发布速度，首先要区分 Pre-training（预训练）和 Post-training（后训练）。预训练需要使用海量数据和大规模计算资源建立基础模型能力，通常是最昂贵、最耗费集中算力的阶段；后训练则在已有底座上进行指令微调、强化学习和能力优化，单次迭代的成本通常相对较低。视频举例，智谱在11个月内推出六代模型，但GLM-5.3与GLM-5.2使用同一个底座，前者主要是在已有基础上额外优化约一个月；DeepSeek上一年的七次更新，也大多围绕V3底座进行。由此，过去看似每隔一两个月就有一代新模型，实际上可能并不对应每次都进行一次全新的大规模预训练。
快速后训练能够不断挖掘已有底座的潜力，但当可提升空间逐渐收窄，进一步扩大模型能力就可能需要重新训练更强的基础模型。

### 9. 重新训练新底座，意味着模型研发进入成本更高、周期更长的阶段
视频认为，当旧底座上的后训练优化接近极限时，单纯增加优化轮次难以继续维持同样幅度的能力增长。智谱高管在业绩会上表达过类似判断：后训练发挥到一定程度后，下一阶段的增长必须重新依赖底座能力。视频以 DeepSeek 从旧底座切换到V4为例，称其经历了接近五个月的间隔，并将发布日期从原计划的2月延后到4月；另据视频，MiniMax 上半年研发支出约3亿美元，是同期收入的2.5倍，主要压力来自训练算力。与这些企业相比，月之暗面原本就采用较长的底座迭代周期，因此近期没有表现出同样明显的节奏变化。
作者由此提出，几家企业不是简单停止研发，而是过去成本相对较低的改进路径逐渐耗尽，接下来必须承担更大规模预训练所需的资金、芯片与时间成本。

### 10. 资金充足也未必能解决问题，高端训练芯片的实际可获得性成为最终瓶颈
作者强调，部分大模型创业公司并不缺资金：视频称智谱当年三轮融资合计超过750亿港元，MiniMax 账面拥有30多亿美元，月之暗面7月单轮融资达到35亿美元。但资金需要先转化为实际可使用的 GPU 才能形成训练能力，而高端算力同时受到供应、租赁价格、产品出口限制以及国产芯片成熟度等因素制约。视频称，NVIDIA（英伟达）H100租赁价格在半年内上涨近40%，H200停止向中国供应；国产芯片虽然能够承担部分推理任务，例如智谱使用超过10万张国产芯片部署服务，并将相关成本降低约80%，但先进国产训练芯片尚未实现足够规模的供应。智谱在8月底预计相关进展还需要3—6个月，因此作者把未来新底座发布时间与国产高端训练芯片的放量联系起来。
其最终判断是：未来决定模型能力迭代速度的，不仅是算法水平、融资能力和研发团队，而是企业能否在需要的时间窗口内获得足够数量、适合大规模训练且能够稳定运行的高端计算芯片。

## 金句摘录
“所以问题不是为什么都哑火了，是五家里为什么偏偏这三家慢了。”

这句话体现了作者的分析方法：不接受笼统叙事，而是寻找相同外部环境下的差异。
“它能证明有人大量调用，证明不了这些回答最后真的被拿去训练了。”

强调外部调用记录与实际蒸馏训练之间存在证据差距，避免把相关性直接理解成因果关系。
“蒸馏是条近路，让别人的卡替你跑。路被堵了，示范就得自己造。”

将抽象的蒸馏机制转化为容易理解的算力成本问题：外部训练示范不可得时，需要自己投入算力生成。
“一张卡给付费用户用，今天就有收入。拿去训练，半年后才有模型。”

揭示推理服务与模型训练之间的商业决策冲突：前者产生即时收入，后者追求未来竞争力。
“卖得越好，留给下一代的卡越少。”

高度概括模型创业公司可能出现的增长悖论：推理业务越成功，训练资源可能越紧张。
“蒸馏被禁，卡不死一家公司。……真正卡人的是显卡，而且是三层叠在一起。”

作者的最终结论：反蒸馏限制不是唯一瓶颈，现有算力被推理占用、低成本迭代空间耗尽、高端训练芯片供给不足，这三层压力叠加才是重点。

## 值得记住的点 / 行动建议

### 1. 判断模型更新速度时，先区分“新底座”与“旧底座升级”
这是理解大模型行业迭代节奏最重要的方法之一。
观察一家企业模型发布是否变慢，不能只比较版本号或发布会次数，而应当区分两种情况：
- 新底座发布： 进行了新一轮大规模预训练，基础模型能力可能有较大变化，通常需要更高的训练算力和更长研发周期。
- 旧底座升级： 在原有基础模型上，通过后训练、强化学习、数据优化等方法提升性能，部分迭代周期可以较短。

例如，视频提到智谱GLM-5.2与GLM-5.3共享底座，DeepSeek过去的多次更新主要基于V3底座。这说明，发布次数并不能直接代表企业完成了多少次底座级研发突破。
实际做法： 建立模型时间线时，单独记录底座训练、后训练升级、轻量版发布和推理优化版本，避免把不同性质的更新混为一谈。

### 2. 判断企业竞争力时，不能只看模型跑分和融资规模，还要看实际算力供给
作者反复强调，“有钱”与“有可用训练算力”是两件不同的事。
一家企业即使获得数十亿美元融资，也不一定能够立即采购到足够的高端训练芯片；即使拥有大量GPU，也可能已经有很大比例被线上推理业务占用。对模型公司而言，训练能力不仅取决于持有多少芯片，还取决于芯片类型、集群规模、互联能力、可用训练时间和运行效率。
实际分析时，可以重点观察企业的算力采购资本开支、芯片租赁费用、算力预付款、训练集群建设，以及国产芯片适配进展。相比单纯看融资新闻，这些指标更接近模型研发所面临的真实资源条件。

### 3. 将“推理需求增长”与“训练能力扩张”放在一起分析
大模型企业的业务增长，并不必然带来同步增强的模型研发能力。
当 API 请求量迅速增加时，企业必须不断增加用于推理的计算资源，否则就会出现响应缓慢、服务排队、限售甚至退款。视频中智谱的调用量增长40倍、API收入增长27倍，以及两家公司的订阅限制，都是理解这一问题的具体线索。
可以建立一个简单的观察框架：

| 观察指标 | 重点关注的问题 |
| --- | --- |
| API请求量 | 用户需求增长有多快？ |
| 推理收入 | 调用量能否转化为现金收入？ |
| 推理成本 | 收入增长是否需要同比例增加计算资源？ |
| GPU供给 | 芯片总量能否跟上业务增长？ |
| 训练资源 | 线上服务扩容后，还剩多少可用于训练？ |
| 新模型发布 | 资源紧张是否伴随旗舰模型延后？ |

核心思路是：增长能力和研发能力必须结合考察，不能只根据其中一项判断企业发展状况。

### 4. 不要把外部蒸馏调用量直接当作模型能力来源的证据
视频提供了一个值得借鉴的证据判断方法。
对于指控模型蒸馏的报告，至少需要区分三个层次：是否存在大量模型调用；调用输出是否被实际用于训练；这些训练数据对最终模型能力贡献了多少。
例如，阿里1.5亿次调用、月之暗面2,300万次调用，能够反映视频所引用报告记录的交互规模，但不能直接计算企业对外部模型的依赖程度。要证明实际影响，还需要训练数据使用证据、具体实验或其他更直接的材料。
因此，阅读类似技术竞争新闻时，应当区分平台记录、外部指控、技术推断和已经证实的事实，不要因为某个数字很大，就默认已经证明全部因果过程。

### 5. 重点关注国产训练芯片能否真正大规模应用，而不只是看发布新闻
作者把国产高端训练芯片的量产与交付，视为未来国产模型迭代节奏的重要影响因素。
视频称，智谱已经使用超过10万张国产芯片承担线上服务，并显著降低推理成本，但这不能直接证明国产芯片能够支撑同等规模的新底座预训练。因为大规模训练还需要大量芯片持续协同工作，对设备可靠性、通信网络、算子支持和软件生态都有很高要求。
因此，后续观察不应局限于“某款国产GPU发布了”或“企业采购了多少张芯片”，而应重点检查其是否形成稳定训练集群、是否完成大规模预训练、是否获得可复现的训练性能，以及实际交付量能否满足企业需求。
判断产业突破的关键，是国产训练芯片从产品发布走向规模化、稳定化、可持续的实际训练应用。

### 6. 未来应当重点跟踪智谱、MiniMax、DeepSeek的新底座发布时间
这是视频结尾给出的第一个直接观察方向。
作者提出，应当重点关注智谱、MiniMax和DeepSeek能否在视频所说的“明年第一季度”推出新底座，而不能仅以轻量版本、旧底座优化或单项能力更新代替判断。
可以同时记录其基础能力变化、模型参数与架构信息、训练硬件披露，以及距离上一代真正新底座的时间间隔。只有把这些信息合在一起，才能判断更新节奏是否确实恢复，以及恢复是否来自训练算力供给改善。
由于文字稿没有明确给出视频发布日期，这个“明年第一季度”应以视频实际发布年份为准，而不能直接作为一个已经核实的绝对日期。

### 7. 把国产高端训练芯片的放量进度作为另一条核心观察线索
这是视频给出的第二个直接观察方向，也是作者认为更具决定性的变量。
智谱高管据视频称在8月底估计，高端国产芯片大规模供应可能还需要3—6个月。如果后续高端芯片能够顺利交付、训练集群能够稳定运行，那么企业就有条件安排更大规模的新底座训练；如果交付延迟，即使融资充足，也可能继续出现模型研发周期拉长的情况。
建议将这条线索与上一条放在同一张时间线上观察：一边记录国产训练芯片的交付和集群部署进度，一边记录三家公司的新底座发布时间及训练规模信息。这样可以检验作者提出的因果解释是否得到后续现实数据支持，而不是只凭模型发布快慢进行推测。

## 我的点评
这期视频最有价值的地方，是没有把国产大模型更新放缓简单归因于美国反蒸馏措施，而是通过五家公司的差异比较，引入算力资源、商业化增长和训练阶段转换等变量，形成了一条较完整的解释链。尤其值得认同的是，它把蒸馏限制理解为训练数据成本的变化，又进一步分析了推理业务与预训练之间的算力分配冲突，使技术问题和商业问题联系起来。不过，视频对算力瓶颈的判断仍主要依赖间接指标，企业真实的GPU分配比例、训练集群规模、模型发布时间调整原因，以及各类融资和资本开支数字的实际口径，都需要进一步验证；模型更新速度也可能受到算法研发、产品战略和模型评估等因素影响。另一个需要注意的地方是，模型长期竞争力不能仅凭发布频率或单次训练投入衡量，更有效的训练方法和工程优化也可能提高单位算力产出。对普通读者而言，最值得借鉴的是这种分析框架：看AI行业竞争时，不仅关注谁发布了新模型，还要同时关注底座是否更新、推理需求是否挤占训练资源，以及新一代训练芯片是否真正具备规模化供给能力。
