## 🤖 AI 分析

## 一句话概括

这个视频系统拆解了“大模型中转站”为什么能把 GPT、Claude 等海外大模型卖到极低价格、这些低价背后的羊毛渠道和灰色逻辑，以及普通用户在不得不用中转站时如何识别风险、降低损失。

## 背景与主题

近几年市面上突然出现了大量“超低价大模型中转站”，号称 GPT 充值 1 元能当 1000 美元用，甚至能做到官方 API 价格的 0.5 折、Claude 的 0.3 折。围绕这些中转站，网上一直有很多争议，比如“掺水降质”“跑路”“偷数据”“假冒官方 API”等，但它们不但没有消失，反而越来越火。视频作者以“实测者”和“行业观察者”的角度，花了几个月时间测试了七八家中转站，试图回答三个问题：这些模型到底“纯不纯”、中转站靠什么赚钱、用户如果真要用该怎么选。作者明确表示不推荐具体平台，只讲方法论，也强调中转站不是官方渠道，天然存在稳定性、质量、安全和合规风险。

## 核心观点

### 1. 中转站本质上是在用户和官方 API 之间加了一层“传话筒”

正常调用大模型时，用户的电脑会直接向官方服务器发送请求，官方服务器根据 API Key 校验身份、确认计费用户，再调用算力生成结果。中转站则是在用户和官方之间插入一个中间服务器：用户拿中转站发的 Key 请求中转服务器，中转站再把请求换成自己的 Key 转发给 OpenAI、Anthropic 等官方或上游渠道。这个过程中，理论上处理的 token 数量并没有变化，只是“左手倒右手”。所以表面看中转站只是“中间商赚差价”，但真正的问题是：如果它真的原样接官方 API，官方价格摆在那里，怎么可能卖到几十分之一甚至几百分之一？视频的核心分析就是围绕这个差价来源展开。

### 2. 早期中转站主要利用海外 API 的“后付费模式”吃霸王餐

早期 GPT 模型计费采用海外常见的后付费模式：用户注册账号后，只要绑定一个 OpenAI 认可的支付方式，不用预充值，就可以先用模型，月底再统一出账单。中转站利用的正是这个时间差：注册账号，绑定一张没有余额或者余额极低的一次性虚拟卡，然后在账单出来前疯狂跑量。月底要扣钱时，账号没钱可扣，号被封了就再注册新的，循环往复。作者提到，账号可以通过开源全自动注册机批量搞，余额 0 美元或 1 美元的一次性虚拟卡也能从卡商处批量购买。后来 OpenAI 开始给不同账号设置使用量限制，要求新账号按时付几个月账单后才能提高限额，最后又转向预付费模式，才基本掐死了第一波“后付费羊毛”。

### 3. 云厂商、教育优惠、创业扶持计划让中转站迎来了第二波狂欢

当 AWS 等传统云厂商开始和 OpenAI、Anthropic 签协议，把模型部署到自己的云平台后，中转站又找到了新的羊毛来源。许多云平台会提供新用户优惠，比如注册送 200 美元试用额度、首月免费等，而且不少云厂商仍然采用后付费模式。除了普通新用户福利，大平台还会给学生、老师提供教育优惠，认证通过后可以拿到几个月甚至一年左右的免费订阅和权益。视频提到，普通羊毛党可能找亲戚朋友帮忙认证，激进一点的会购买教育优惠，更狠的会“手搓学生证和成绩单”。最夸张的是，有人甚至“建学校”：有证书、有官网、有证明材料，公开免费招生，自己建学校、自己入学、自己批量分配邮箱，用来通过教育认证。

### 4. 面向初创公司和非营利组织的扶持计划，也成了大额 API Key 的来源

除了个人用户优惠，大型云服务平台还经常有针对初创公司、非营利组织的扶持计划，给出较高额度的云资源或 API 使用额度。作者认为，这些审核在一些“大手子”面前形同虚设，因此二手市场上那些余额动辄几千、上万美元的 API Key，很大一部分就是这样来的。中转站可以通过批量申请、收购或倒卖这些高额度账号，形成自己的“上游号池”。只要中转服务器能自动把用户请求分配到不同账号上，就可以把这些免费或低成本额度拆开卖给许多普通用户。这个逻辑解释了为什么一些中转站看起来价格极低却还能运转：它们卖的不是按官方价格买来的算力，而是各种优惠、漏洞和账号资源的集合。

### 5. 当前 OpenAI 中转的核心玩法，转向了订阅套餐和 Codex / Coding Plan 额度套利

视频重点解释了一个新的套利模式：用户购买 ChatGPT Plus 后，除了网页端可以用高级模型，还能在开发者工具 Codex 中调用 GPT 模型。Plus 套餐价格是每月 20 美元，但作者根据实测统计，如果 Plus 用户把 Codex 每周额度都拉满，一个月按标准 API 价格计算大约相当于 400 美元额度。对普通用户来说，很多人根本不会用满，甚至完全不用 Codex；对 OpenAI 来说，订阅额度也可以随时调控，因此商业上不一定亏。但对中转站来说，这就变成套利空间：一个号成本 20 美元，理论上能跑出 400 美元额度，相当于 0.5 折；如果再从土耳其、菲律宾等低价区购买订阅，成本还能再降一半。中转站再通过逆向把原本用于 Codex 的接口接到自己的中转服务器上，几十上百个账号组成号池，哪个号没额度或被封就自动切换。

### 6. 极端低价往往来自“日跑号”和免费试用账号，而不一定是假模型

视频开头提到“GPT 充 1 块钱就能当 1000 美元用”，看起来像诈骗，但作者解释说，这种极端低价有时并不是因为接了便宜国产模型，而是因为上游账号成本接近于零。许多订阅制软件为了拉新，会给新账号首月免费试用，只要绑定支付方式就能开通；中转站可以用虚拟卡和注册机批量开号。视频还提到一些具体渠道，比如 2026 年四五月份的印尼 GoPay、美国虚拟卡相关方法，以及有人通过虚拟机强行开启安卓端 Plus 免费试用。极限情况下，一个 Plus 账号成本可能只有几毛钱，但寿命很短，中转圈称为“日跑号”，平均只能活一天。因为这些号明天大概率就被封，所以中转站会在当天把剩余额度用低价甩出去，让用户“使劲跑”，反正不用也是浪费。

### 7. Claude 中转风险更高，掺水、降质和假冒渠道主要集中在 Claude 侧

作者认为，OpenAI 的羊毛渠道相对“耐耗”，成本可以低到比国产模型甚至自部署开源小模型还低，但 Claude 侧就难得多。早期 Claude 曾有一段时间“封号秒退全款”，用户受伤，但对中转站来说反而是致富经：买套餐后使劲跑，怎么容易封就怎么用，封号后退款，扣掉汇损和开卡费用，成本几乎趋近于零。后来 Claude 订阅越来越难买，封号退款变慢，现在甚至需要 KYC 身份认证才能开通套餐，成本上升、量也不够。于是中转站转向一些 AI 开发服务，比如 Trae、Antigravity 等内置大模型接口的产品，通过免费试用、学生优惠等方式注册大量开发者账号，再逆向接口提供给用户。但这类渠道常带有编辑器内置提示词，可能让模型在非 coding 场景下能力明显下降。

### 8. “模型还是那个模型”不等于“能力还是官方满血能力”

视频特别强调，很多通过开发工具逆向出来的接口，底层模型可能确实还是 Claude 或 GPT，但外层系统提示词、工具调用逻辑和使用场景已经不同。比如某个编辑器内置提示词写死了“你是一个写代码的 agent”，用户却想用它做调研、写文章，模型自然表现不顺。如果用户用 Claude Code 或 Codex，提示模型使用 Edit 函数，但某些开发服务内置的又是 Patch 函数，两套指令互相打架，模型就会“蒙”，表现出来就是“智商暴跌，干啥啥不行”。这解释了为什么有些中转站标称 Claude Opus 或官方满血，但实际体验明显降级。作者认为，如果中转站把不同上游渠道明确标出来，用户至少可以按需选择；但如果把质量参差不齐的上游混在一起，却号称“官方满血号池”，这就是真正的“掺水”。

### 9. 中转站不仅有质量风险，还有数据安全和恶意注入风险

作者引用了一项团队调研：研究人员测试了 28 个付费中转和 400 个免费中转，发现其中 9 个中转会在大模型返回的工具调用 JSON 中注入恶意代码，17 个中转会窃取作为诱饵埋入请求中的 AWS 密钥，还有 1 个中转直接从研究人员伪造的对话记录中提取了 ETF 钱包私钥并转移资产。这个例子说明，中转站的风险远不止模型降智或价格波动，而是可能涉及凭证泄露、代码供应链攻击、私钥被盗等严重问题。由于用户请求会先经过中转站服务器，中转站理论上可以看到提示词、上下文、API 返回结果，甚至对返回内容做手脚。对普通聊天可能只是隐私问题，但对写代码、处理商业资料、操作云服务密钥、金融钱包等场景，风险会显著放大。作者因此建议，不要把中转站当官方服务，也不要把敏感信息直接交给它。

### 10. 中转站存在的根本原因，是官方模型贵、难买、不稳定，而市场需求巨大

视频并没有简单把中转站说成“必然要完的灰产”，而是解释了它为什么有市场。早期旗舰模型 GPT-4 32K 的价格非常高，作者称其价格是现在 GPT-5.4 的 20 多倍；现在虽然单价下降，但 coding agent 跑起来 token 消耗极快，几百美元额度在高频开发场景中根本不够用。对国内普通用户来说，直接买 OpenAI、Anthropic 的订阅或 API 也不容易：国内银行卡常常不能用，需要外区账号、虚拟卡等方式，还要担心封号。作者提到，2025 年下半年 Anthropic 封禁了约 145 万个账号，同期 5.2 万份申诉里最后翻盘的只有 1700 件；今年初 Anthropic 还宣布禁止在第三方工具中调用 Claude 订阅，并要求 OpenCode 停止支持和删除调用 Claude 的代码。在官方价格、支付门槛、地区限制和封号风险共同作用下，中转站成了许多人接触全球前沿模型的“廉价粗糙但无可替代的赛博天窗”。

## 值得记住的点 / 行动建议

### 1. 不要把中转模型当成官方模型使用

作者最重要的建议是：中转站提供的模型不能等同于官方 API，也不要期待它有官方的稳定性、质量和安全性。即使中转站声称自己接的是 OpenAI 或 Anthropic 官方接口，也可能经过号池、开发工具逆向、二级中转甚至多级中转。底层模型可能是真的，但系统提示词、上下文、工具调用、速率限制、封号策略和返回结果都可能被改动。更现实的做法是把中转站当成“低价但不稳定的替代渠道”，而不是生产环境里的可靠基础设施。对重要业务、长期开发、严肃评测、涉密数据和金融资产相关操作，最好走官方或更可信的渠道。

### 2. 按使用场景区分：临时、低敏、高消耗任务可以用中转，关键任务走官方

视频中作者提到，他们团队自己的做法是：代码开发中的一些“稳稳处理”或高频消耗场景会用中转解决，但模型评测、长周期开发任务等仍然直接走官方渠道。这个分工很实用：中转适合高 token 消耗、可重试、失败成本低、数据不敏感的任务，比如临时写代码、生成脚本、普通问答、批量改写等。官方渠道则适合需要稳定复现结果、需要严格保密、需要长期上下文连续性、或者失败代价很高的任务。这样可以在成本和风险之间做平衡，而不是极端地“全用中转”或“完全不用中转”。便宜不是免死金牌，尤其当人类又一次试图用几块钱挑战风控系统时，事故通常不会太远。

### 3. 新手不要碰免费中转站

作者明确建议，中转新手第一条就是不要尝试免费中转站。虽然确实可能存在“赛博菩萨”愿意把极低成本的号池免费分享出来，但绝大多数中转站都需要盈利。模型免费，就意味着它可能从别的地方赚钱，比如收集用户数据、注入广告、偷取密钥、转卖请求内容，甚至进行恶意代码注入。视频前面提到的研究案例已经说明，免费和低价中转中确实存在窃取 AWS 密钥、注入恶意 JSON、提取钱包私钥等行为。普通用户如果没有能力审计上游、隔离环境和检查返回内容，免费中转往往不是“薅羊毛”，而是把自己端上桌。

### 4. 优先选择标清楚分组和上游渠道的中转站

很多中转站会设置多个分组，对应不同模型或不同渠道。作者建议优先考虑那些能在分组里写清楚渠道信息的站点，比如明确标注 Windsurf、Cursor、Trae、Antigravity 等开发服务逆向渠道，或标注 Claude Max、GPT Free、GPT Plus、GPT Pro 等不同号池来源。虽然标出来不代表一定真实，但至少比完全不标、只喊“官方满血”的平台更透明。用户可以根据场景选择：coding 场景可能能接受开发服务逆向渠道，写作、调研、评测则要尽量避开带强内置提示词的 IDE 渠道。对 Claude 尤其要谨慎，因为视频认为 Claude 侧更容易出现 Sonnet 冒充 Opus、编辑器逆向冒充官方等问题。

### 5. 看报错信息里的 Request ID，识别“中转套中转”

作者给了一个很实用的识别技巧：留意调用接口出问题时的报错信息。大多数中转面板会在报错里加上当前请求的 Request ID，用来排错；如果你发现报错信息里出现不止一个 Request ID，甚至是一连串 Request ID，就说明请求可能经过了多层中转，也就是“中转套中转”。每多一层中转，就多一层加价、多一层不稳定、多一层掺水或数据泄露风险。作者提到他们遇到过最离谱的一次是“套了八层”的中转。对用户来说，发现这种情况后就不建议继续使用，因为你已经不知道请求到底经过了多少手，也不知道谁在看你的内容。

### 6. 每次少充值，用一点充一点

视频反复强调的低风险原则是：不论你用的是知名大中转站，还是群聊广告里看到的小站，都不要一次性充太多。即使一个中转站当前很稳定、很便宜、口碑不错，也可能因为官方风控、上游策略变化、账号源断供、支付通道失效等原因突然不可用。更糟的是，中转站本身也可能跑路，余额无法退回。少充勤充可以大幅降低损失，把中转站当成“短周期消耗品”，而不是长期账户资产。这个建议朴素，但非常有效，毕竟把钱长期存在灰色渠道里，本质上是在给陌生人发无息贷款，人类金融文明又一次原地绕圈。

### 7. 老手可以优先研究 Sub2 API，但要理解它的单点风险

对更熟悉中转玩法的用户，作者建议可以优先考虑使用 Sub2 API 面板，而不是 New API 系列面板。原因是 Sub2 API 主要针对 Coding Plan 账号逆向对接，使用它的站点自己往往就是号商或直接掌握账号池，不太容易遇到“倒卖上游再倒卖”的情况。New API 则更常见于再套一层上游号池，链路可能更长。但 Sub2 API 也不是没有风险，一旦羊毛渠道变化，号池可能突然全部失效，恢复时间会比较长。除非平台本身有多种账号来源，否则这种看似更直接的方案也可能出现明显的单点故障。

### 8. 定期检查返回 token 数和真实上下文是否匹配

作者建议用户可以定期测试接口返回的 token 数量，看看它和自己真实请求的上下文是否一致。比如你只发了一个“你好”，但面板显示提示词 token 有好几千，那就很可能说明上游带了大量不可见系统提示词。尤其是 IDE 或开发工具逆向渠道，常常会内置很长的 agent 指令、工具说明、函数调用规范，这会挤占上下文，也会影响模型行为。如果你用它做写作、调研、翻译、总结，就可能发现模型莫名其妙地偏向写代码、调用工具或输出奇怪格式。这个检查方法不能证明平台完全可靠，但能帮助你发现明显不适合当前场景的渠道。

### 9. 多买几家中转站轮换使用，不要押注单一平台

作者建议进阶用户不要指望一家中转长期稳定，而是多找几家、多换几家。中转站的稳定性高度依赖上游账号池、官方风控、支付通道、区域价格、免费试用政策等外部因素，任何一个环节变化都可能导致服务中断。多平台轮换能降低单点故障风险，也能帮助用户比较不同站点在价格、速度、上下文、质量和报错处理上的差异。对高频用户来说，这种策略比死守一个所谓“神站”更现实。中转站的世界里，忠诚通常只会换来余额归零，真是现代商业伦理的一座小型纪念碑。

### 10. 有条件可以自建一个小型聚合中转，把多个上游统一管理

视频最后给了一个更硬核的做法：有条件的用户可以自己部署一个 New API，把购买的多家中转站接入进来，按照价格或偏好设置优先级，并开启失败重试功能。这样就相当于搭建了一个只给自己用的“微型中转站”。首选站点故障时，系统可以自动切换到下一个站点，减少人工改配置的麻烦。这个方案适合有一定技术能力、调用量较大、对稳定性有要求但又想控制成本的人。代价是需要自己维护、测试、监控和排查问题，折腾越多，体验越好，但也越不像一个正常人下班后该做的事。

## 我的点评

这期视频的价值在于，它没有简单把中转站妖魔化，也没有替中转站洗白，而是把低价背后的账号套利、订阅额度、云厂商优惠、教育认证、开发工具逆向等逻辑拆得比较清楚。作者关于“中转不是官方”“按场景使用”“少充值”“不要碰免费站”“警惕多层中转”的建议很有实际意义，尤其适合那些因为成本、支付或地区限制不得不用中转的用户。需要保留的是，视频里的许多数据和案例来自作者实测或引用调研，普通观众最好把它们当作风险提示和行业观察，而不是对某个平台的直接判定。中转站确实能降低普通人接触前沿模型的门槛，但它同时处在灰色地带，数据安全、服务稳定、合规性都不应被忽略。更长期看，如果 DeepSeek、Kimi、智谱等国产模型继续提升质量并压低官方 API 价格，中转站的必要性会下降；在那之前，它仍然是一种便宜、粗糙、好用但不能完全信任的临时工具。
