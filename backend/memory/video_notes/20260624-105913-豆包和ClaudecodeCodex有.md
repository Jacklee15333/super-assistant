## 🤖 AI 分析

## 一句话概括

这个视频是在用“小白能理解”的方式区分豆包这类聊天式 AI 和 Claude Code / Codex 这类执行型 AI Agent：前者主要解决“问”，后者真正开始解决“做”。

## 背景与主题

作者看到推特上有人说“Claude Code 这么可怕的东西竟然只有几百万人高频使用”，由此想到很多人其实听过 Claude Code、Codex、AI Agent，但并没有真正理解它们和豆包这类 AI 的区别。视频的核心不是做产品测评，而是做概念扫盲：豆包属于对话入口，Claude Code 和 Codex 属于生产入口或执行入口。作者的立场很明确：普通用户接下来要学的，不只是怎么向 AI 提问，而是怎么把需求拆成可以执行、可以验证的小任务，让 AI 进入工作流真正帮自己干活。

## 核心观点

### 1. 豆包解决的是“回答”，Claude Code / Codex 解决的是“执行”

作者用一句话概括三者区别：豆包“只是会回答”，而 Claude Code 和 Codex 是“会进入你的电脑环境去干活”。豆包这类产品的典型使用方式是聊天、搜索、写一段内容、生成一些文字或图片，它更像一个问答助手。Claude Code / Codex 则不是停留在把答案告诉你，而是可以从你的本地文件夹、目录、项目、代码仓库开始，直接处理文件、修改内容、运行命令。这个差异的关键不在于模型会不会说得更好，而在于它有没有“执行动作”的能力。作者因此把豆包归为 Chat AI，把 Claude Code / Codex 归为 working agent 或工作型 Agent。

### 2. 绝大多数人仍停留在“和 AI 对话”的阶段，还没有进入“让 AI 干活”的阶段

作者提到，虽然很多人每天都在讨论 Claude Code、Codex，但现实里绝大部分用户还只是停留在使用豆包这类聊天 AI 的阶段。他们可能听说过 AI Agent、Claude Code、Codex 这些概念，但没有亲自感受到它们到底能做什么。第一次接触 AI 的普通用户，通常是从“和豆包对话”开始：问问题、搜索资料、让它帮忙写一段内容。这个入口非常自然，但它本质上仍然是“人问、AI 答、人再去做”。作者想强调的是，AI 的使用方式正在从“问答工具”向“工作流执行工具”过渡，而很多人还没有跨过这个认知门槛。

### 3. 豆包是“对话中心”，Agent 是“任务中心”

豆包这类聊天助手以对话为中心：用户提出问题，模型给出答案，用户再把答案复制粘贴到自己需要的地方。整个链条里，AI 主要负责生成信息，而人负责把这些信息拿去执行。Claude Code 和 Codex 这类 Agent 则是任务中心：用户给它一个目标，它会自己读取文件、搜索资料、执行命令、调用工具，并最终产出一个可以验收的结果。换句话说，聊天 AI 的边界停在“输出内容”，而执行型 Agent 的边界延伸到“完成任务”。这也是作者反复强调的核心差异：不是谁更聪明，而是谁能把链路真正打通。

### 4. Claude Code / Codex 能读写本地文件，把结果真实留在电脑里

作者特别强调，Claude Code / Codex 可以打开用户电脑上的项目、文件夹、文件，读取文件内容，也可以修改文件内容。它们的变化不是只停留在聊天窗口里，而是会真实留在你的文件夹、文件、代码或项目仓库中。比如它可以查看一个项目结构，搜索关键词，打开相关文件，理解文档内容，再进行修改。相比之下，豆包通常不能直接操作和读写你的本地文件，也不能直接运行你电脑里的命令。这个能力让 Claude Code / Codex 更像一个“在你电脑里工作的助手”，而不是一个只在聊天框里给建议的助手。

### 5. Agent 的强大来自“大模型 + 工具调用 + 执行反馈”这一整套机制

作者说这类 AI Agent 听起来很神奇，但本质并不复杂：它是让大模型调用一个个工具去执行任务。比如它可以通过命令行查看文件夹里有哪些目录，再打开文件、搜索关键词，像人一样翻资料、理解文档。它也可以执行电脑里的命令，而很多人平时用鼠标完成的点击、复制、粘贴、上下移动，背后其实也对应着计算机命令。Agent 相当于可以直接运行这些命令，从而完成和人工操作类似的动作。更重要的是，它执行之后还能检查结果，比如看文本是否符合要求、看截图、看代码运行输出，如果失败还能继续修正。

### 6. Agent 的完整工作过程是“读文件—执行动作—检查结果—交给人验收”

作者把 Agent 的工作方式总结成一种很接近人类助理的流程：用户给目标，Agent 先读文件、理解上下文，然后执行动作，执行完之后再检查结果，最后由用户验收。这个流程和普通聊天 AI 非常不同，因为聊天 AI 往往只给出“你应该怎么做”的说明，而 Agent 可以真的去做。比如代码运行失败，它不是只告诉你“可能哪里错了”，而是可以根据报错继续修改，直到输出可以被验收的结果。作者认为，这种“执行—反馈—修正”的闭环，才是 AI Agent 真正强的地方。它不只是生成答案，而是在接近一个可交付成果。

### 7. 有些任务豆包能给建议，但很难直接替你完成

视频里举了几个很具体的例子：批量改 200 个文件名、搜索并下载网页资料、生成一个可运行的网页。豆包可以告诉你思路、步骤、脚本怎么写，甚至可以生成一段代码，但你还需要自己复制、运行、调试、整理结果。Claude Code / Codex 这类 Agent 更适合这些需要进入文件系统、网页、脚本、项目仓库的任务。因为它们不只是提供方案，而是可以把方案落到文件、命令和项目里。作者借这些例子说明：当任务涉及多个步骤、多个文件、需要验证结果时，Agent 的优势会明显放大。

### 8. 是否需要 Agent，取决于你的需求是不是已经进入“工作流”

作者并没有说所有人都必须使用 Claude Code 或 Codex，而是强调要看具体需求。如果你的需求只是写一段话、问一个问题、做简单搜索，那么豆包这类聊天 AI 已经足够。只有当你希望 AI 进入文件系统、网页、脚本、仓库，融入日常工作流时，才真正需要学习 Claude Code / Codex 这类执行型 Agent。也就是说，Agent 不是为了替代所有聊天 AI，而是面向更复杂、更可执行、更可验证的任务。作者最后建议，普通用户接下来真正要学的，不只是“怎么提问”，而是“怎么把需求变成可执行、可验证的小任务”。

## 值得记住的点 / 行动建议

### 1. 先判断你的需求是“问答型”还是“执行型”

如果你的任务只是想了解一个概念、写一段文案、总结一段材料、搜索一个普通信息，那么豆包这类聊天 AI 通常已经够用。它的优势是入口简单、上手成本低、适合快速获得答案。但如果你的任务需要进入文件夹、处理多个文件、修改代码、运行脚本、下载资料、生成项目成果，那就已经不是简单问答，而是执行型任务。此时更适合 Claude Code / Codex 这类 Agent，因为它们可以把任务真正落到电脑环境里。判断标准很简单：如果你拿到 AI 的文字答案后还要自己复制、粘贴、运行、检查很多步，就可以考虑让 Agent 接手。

### 2. 不要只学“提示词”，还要学会拆“可执行任务”

作者最重要的提醒是：普通用户接下来要学的，不只是怎么提问，而是怎么把需求变成一个可执行、可验证的小任务。比如“帮我整理电脑”太大、太模糊，但“把这个文件夹里所有带日期前缀的文件改成统一格式，并保留原文件名关键词”就更适合 Agent 执行。再比如“帮我做网页”也很泛，而“基于这个文件夹里的素材生成一个可运行的单页网页，包含标题、图片区、按钮和说明文字”就更清晰。任务越具体，Agent 越容易执行；验收标准越明确，结果越容易判断。未来使用 AI 的关键能力，会从“会不会问”升级为“会不会定义任务和验收标准”。

### 3. 第一次尝试 Agent，可以从低风险的小任务开始

作者建议，如果你对 AI Agent 感兴趣，可以第一次尝试让它做一些很简单的任务，例如整理电脑文件夹。这个建议很重要，因为 Agent 能读写文件、运行命令，能力更强，也意味着用户需要逐步建立信任和边界感。低风险任务可以帮助你感受它的完整过程：它如何读取目录、理解文件、提出修改方案、执行操作、检查结果。不要一上来就把重要项目、核心代码、不可恢复的文件交给它处理。先从可备份、可回滚、影响范围小的任务开始，体验“AI 真正干活”的流程。

### 4. 给 Agent 的任务要包含目标、素材、范围和验收标准

作者最后举了自己用 Codex 做 PPT 的例子：他提供了需要的素材、做 PPT 的 skill，以及具体要求，Codex 就直接帮他做出来了。这个例子说明，Agent 不是凭空变魔术，它需要明确输入和工作边界。比较好的任务描述应该包含：要做什么、使用哪些素材、输出成什么格式、哪些内容必须保留、哪些地方不能改、最终如何验收。比如做 PPT 时，可以明确页数、风格、内容结构、图片来源、标题层级和导出格式。这样 Agent 才能从“听懂你的想法”进一步走到“交付你能用的结果”。

### 5. 把 Agent 当成“会操作电脑的助理”，而不是单纯聊天机器人

视频里最值得记住的类比是：Agent 像一个会操作电脑的助手。它能看文件、改文件、执行命令、观察输出、发现失败并修正，这些动作已经超出了传统聊天 AI 的范围。使用它时，用户的思维方式也要改变：不是问“这个怎么做”，而是说“请你在这个范围内帮我做完，并告诉我改了什么”。这会让 AI 从咨询工具变成生产工具。真正掌握 Agent 的人，工作方式可能会从“自己做每一步”变成“设计任务、监督过程、验收结果”。

## 我的点评

这个视频的核心判断是有道理的：豆包这类聊天 AI 和 Claude Code / Codex 这类 Agent 的关键差异，确实不只是模型能力，而是有没有进入环境、调用工具、执行任务和形成结果闭环的能力。作者用“问”和“做”来区分，非常适合小白理解，也抓住了 AI 产品形态演进的重点。需要注意的是，执行型 Agent 虽然强，但并不等于适合所有任务，尤其涉及重要文件、隐私数据、线上系统、批量删除或不可逆操作时，仍然需要用户设置边界、备份文件并逐步验收。视频略微弱化了使用 Agent 的风险和学习成本，比如权限管理、误操作、结果校验、环境配置等问题。对普通人来说，最实用的启发是：先用豆包解决信息和表达问题，再用 Claude Code / Codex 解决文件、代码、脚本、网页、PPT 等可执行任务，逐步把 AI 接入自己的真实工作流。
