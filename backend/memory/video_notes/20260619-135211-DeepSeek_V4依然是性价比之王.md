## 🤖 AI 分析

## 一句话概括

这期视频的核心是：**DeepSeek V4 的单项能力未必全面超过 GPT 5.5 或 Opus 4.7，但它以接近前沿模型的能力和极低价格，重新定义了 AI Agent、自动化工作流和编码代理的性价比。**

## 背景与主题

视频围绕 **DeepSeek V4 发布**展开，作者认为这是过去一年半最受期待的 AI 模型之一，并把它放在 OpenAI GPT 5.5、Anthropic Opus 4.7 等前沿模型的竞争格局中比较。作者的视角不是单纯看榜单第一，而是重点关注一个更现实的问题：**当一个开源模型达到前沿模型 90% 以上能力、但价格低 7 倍甚至 40 倍时，用户和企业会不会迁移工作流。**

文字稿中有不少语音识别误差，以下按上下文统一整理：DeepSec / DeepSeq 统一理解为 **DeepSeek**，GPD 统一理解为 **GPT**，OPOS / Open 多处应为 **Opus**，Anstropic 应为 **Anthropic**，OLMA 应为 **Ollama**。视频后半部分是实操演示：作者通过 OpenCode 同时启动 4 个终端，用 DeepSeek V4 Pro 并行生成网页应用、SVG 动画、卡丁车游戏、系外行星项目，并统计成本。

## 核心观点

### 1. DeepSeek V4 的真正卖点不是“绝对最强”，而是“前沿能力 + 极低成本”

作者一开始就把情绪拉满，说“四个不同的终端都在运行 DeepSeek V4 Pro，同时并行构建四个不同的项目，而且只花了几分钱”，并感叹“我们真的生活在未来了”。但他后面也明确承认，DeepSeek V4 在多数困难基准上并不一定超过 GPT 5.5 或 Opus 4.7，甚至在某些长上下文任务上明显落后于 Opus。视频真正强调的是性价比：如果一个模型能以约 1/7 的价格提供约 97% 的性能，或者比 GPT 5.5 Pro 便宜 40 倍，那么它对真实生产环境的吸引力会非常强。这里的逻辑不是“谁榜单最高谁赢”，而是“谁能以最低成本承担大量 Agent、自动化、编码和定时任务，谁更可能进入日常工作流”。作者最后也总结说，这个模型在能力上“不算革命性”，真正革命的是它的价格与性能比。

### 2. DeepSeek V4 被作者视为目前最强、最大的开源模型之一

视频中称 DeepSeek V4 是“有史以来最大的开源模型，也是有史以来最强的开源模型”。文字稿前段出现“1600亿参数”，但后文又说“专业版有 1.6 万亿参数”，并且前面提到“之前最大的模型大概是 1 万亿参数，这个大了 60%”，所以按上下文应理解为 **1.6 万亿参数**。它采用专家混合架构，也就是并不是每次推理都激活全部参数，实际每次大约只激活 **470 亿参数**。作者还提到它拥有 **100 万上下文窗口**，但也提示“这里有一些注意事项”，说明长上下文能力不能只看标称窗口大小。换言之，DeepSeek V4 的规模和架构让它具备前沿模型的基础能力，但真实效果仍要看推理、长上下文、Agent 控制和成本表现。

### 3. 架构创新集中在长上下文、注意力压缩和推理效率上

作者提到 DeepSeek V4 的架构有不少创新，包括用于长上下文的“压缩吸收注意力”、强压缩注意力机制、MHC 残差变化、FP4 / FP8 推理，以及多教师的 policy 蒸馏。视频还说它使用了类似 Kimi 的优化器，可能受 Kimi 2.5 启发，作者借此强调开源社区的优势：开源模型之间可以互相借鉴思想，因为研究和实现更透明。后面的网页演示中，作者让 DeepSeek V4 做了一个“交互式 DeepSeek 架构讲解器”，里面解释了原始注意力的复杂度问题，即 Vanilla Attention 的复杂度是 **O(n²)**。生成的页面还展示了 CSA、HCA 等压缩注意力机制：例如“每 M 个 Token 被压缩成一个条目”，再通过索引器或混合架构参与注意力计算。作者不假装自己完全理解论文细节，但认为这种交互式网页比直接读技术报告更容易学习模型架构。

### 4. 在基准测试上，DeepSeek V4 已经能和前沿闭源模型正面对比

视频把 DeepSeek V4 Pro 与 GPT、Opus 等模型放在大约 20 种基准中比较，并把测试分为知识推理、代码、智能体、浏览器控制和经济价值任务等类别。在 MMLU 上，作者称 DeepSeek V4 表现接近 GPT 5.4，非常高，略低于 Opus 4.6；在 SimpleQA 上，它甚至比 Opus 和 GPT 更好；在 GPQA Diamond、人文学科终极考试等任务上则略差。在 LiveCodeBench 和另一个代码测试中，作者认为它表现更好，甚至在多个热门基准上可以说是“世界上最好的 AI 模型”。不过他也提醒，在长上下文任务上，DeepSeek V4 远远落后于 Opus。整体结论是：DeepSeek V4 不是一个低一档的模型，而是已经能与一两个月前的最前沿闭源模型“相媲美”。

### 5. 对 AI Agent 和自动化工作流来说，成本下降可能比能力提升更关键

作者特别关注 DeepSeek V4 在 Agent 场景中的意义。他提到终端控制、浏览器控制、SWE-bench Pro、BrowseComp、GDP VAL 等测试，整体判断是 DeepSeek V4 有些地方略逊于 Opus 或 GPT，有些地方反而更好，但总体已经达到“可媲美”的水平。真正让他震动的是成本：如果 Agent 自动化需要长时间运行、大量调用 API，那么每个 Token 的价格会直接决定能不能规模化使用。作者说自己目前每月在 Anthropic API 上花 **5000 到 6000 美元**，如果把部分工作流迁移到 DeepSeek V4，可能降到 **1000 美元甚至 500 美元**。这说明 DeepSeek V4 对美国 AI 实验室的冲击，不只在技术声誉上，更在收入结构上：一旦用户把高频自动化任务迁走，Anthropic / OpenAI 的 API 收入会被直接分流。

### 6. 作者认为 DeepSeek V4 可能再次冲击美国 AI 公司和科技股叙事

视频提到，2025 年 1 月 DeepSeek 相关发布曾导致英伟达和美国大型科技公司的股价暴跌，作者认为类似冲击“现在同样可能发生”。这里的因果逻辑是：如果中国开源模型不仅能力接近美国闭源模型，而且价格便宜得多，那么市场会重新评估美国 AI 实验室的护城河。过去闭源模型的竞争优势主要来自能力领先、生态绑定和推理服务，但 DeepSeek V4 这种模型会削弱“能力领先”的稀缺性，并进一步压低推理价格预期。作者明确说，这对美国 AI 实验室是“坏消息”，因为模型不仅开源，而且比美国模型便宜得多。即便 DeepSeek V4 稍微弱于 GPT 5.5 或 Opus 4.7，只要价格优势足够夸张，商业选择仍可能倾向 DeepSeek。

### 7. OpenCode 被作者当作当前使用 DeepSeek V4 做代理编码的最佳入口之一

由于 DeepSeek V4 当时还不在 Claude Code、Codex 或 Cursor 中，作者选择用 **OpenCode** 来演示。他说 OpenCode 上线速度非常快，安装方式也很简单：进入 OpenCode.ai，复制命令，在终端里粘贴执行即可。作者把 OpenCode 类比为 Claude Code 的开源替代品，并强调它本身是完全开源的，可以配合 OpenRouter 使用，也可以用 Ollama 在本地运行部分模型。对于 DeepSeek V4 Pro 这种 1.6 万亿参数级别模型，作者认为本地运行基本不现实；但 Flash 版本可能约 **2600 亿参数**，未来若有优化或量化版本，也许能在 **128GB 内存的 MacBook** 上尝试运行。也就是说，OpenCode 在视频中扮演的是“把高性价比模型接入真实开发工作流”的工具层。

### 8. 实操演示显示 DeepSeek V4 Pro 可以同时承担多个不同类型的项目生成

视频后半段，作者同时打开 4 个终端，让 DeepSeek V4 Pro 并行构建 4 个项目：一个 DeepSeek 架构交互式讲解网页、一个 SVG 植物生长动画、一个卡丁车街机赛车游戏、一个系外行星相关项目。SVG 项目要求用 HTML、CSS、JS 做单文件演示，用 SVG 模拟植物生长，包括茎干延伸、叶片和发芽，结果作者认为“动画效果很不错”“非常干净”。卡丁车项目生成了一个名为 Turbo Car Dash 的街机赛车游戏，支持 WASD 控制、空格漂移、Shift 加速，甚至有音效、小地图、护盾等元素。虽然作者承认它不是 3A 大作，也不算革命性创新，但它是一个能运行的游戏，并且所有内容都在一个 HTML 文件里完成。这个演示的重点不是作品多精美，而是说明低成本模型已经能在多终端并行完成相当复杂的原型构建。

### 9. 使用 DeepSeek V4 时，推理强度设置会显著影响速度和成本

作者在 OpenCode 中提到可以用 Ctrl + T 在任务之间切换，也可以选择 DeepSeek V4 的不同推理强度：低、中、高、最高。他一开始使用了较高强度，但后来认为这是“想太多了”，因为 DeepSeek 会真的在高强度下花大量时间推理，导致速度变慢、成本增加。作者建议大多数任务用 **中等推理强度** 起步，只有确实需要更强推理时再切换到高或最高。这个建议背后的逻辑很实用：很多编码、网页原型、自动化任务并不需要最强推理，只需要足够可靠和快速。对于大规模 Agent 工作流来说，推理强度本质上是一个成本—速度—质量的旋钮，调得太高可能浪费预算。

## 值得记住的点 / 行动建议

### 1. 不要只看模型排行榜，要看“你的任务成本”

作者反复强调，DeepSeek V4 的关键不是在每个基准上都第一，而是能否用更低价格完成你的真实任务。对于个人开发者、独立创业者或公司内部自动化团队来说，API 成本往往比单次回答质量更重要，因为 Agent、批处理、自动化任务会持续调用模型。一个模型即便略弱于 GPT 5.5 或 Opus 4.7，只要足够稳定，并且成本低 7 倍到 40 倍，就可能成为默认工作流模型。普通用户可以把任务分层：高风险、高复杂任务继续用最强模型；大量重复、结构化、可验证的任务用 DeepSeek V4 这类高性价比模型。这样既不牺牲关键质量，又能显著压低总体开销。

### 2. 把 DeepSeek V4 优先用于高频 Agent、自动化和编码原型任务

视频中最有价值的实操信息是：DeepSeek V4 适合并行运行多个 Agent 来做原型开发、网页生成、自动化脚本、可视化演示和重复性工作流。作者演示了同时启动 4 个终端，让模型分别做架构讲解网页、SVG 动画、卡丁车游戏和行星项目。这里的启发是，低成本模型不一定要替代所有最强模型，但特别适合作为“工作流底座”。比如定时任务、代码重构、网页 demo、数据整理、简单内部工具、文档生成、自动化检查，都可以先用低成本模型跑。只有当结果不够好或任务涉及复杂推理时，再切换到更贵的模型补救。

### 3. 使用代理编码工具时，一定要在专门文件夹里启动

作者特别提醒，无论使用 OpenCode 还是其他 Agent 工具，都应该先进入一个专门的项目文件夹，再启动代理。原因很简单：如果在系统根目录或不合适的位置运行，Agent 可能会误读文件结构，甚至有操作风险。视频中作者一开始发现 OpenCode 在系统根目录下运行，随后终止进程，重新进入目标文件夹后再启动。这个实践非常重要，尤其是在让 Agent 自动创建、修改、删除文件时。更好的做法是为每个实验单独建文件夹，例如 explain、svg、kart、planets，这样上下文清晰、风险可控，也方便复盘和清理。

### 4. 提示词不用复杂，关键是明确目标、文件形式和验收标准

作者的提示词并不花哨，例如让模型“构建一个含 HTML、CSS 和 JS 的单文件演示，用 SVG 模拟植物生长，包含茎干延伸、叶片与发芽”。这个提示包含了几个关键要素：技术栈、交付形式、核心功能、视觉表现。后面修复页面问题时，他直接上传截图并说“页面主体没有居中对齐，把它修好”，这比写一大段抽象要求更有效。对于 Agent 编码来说，好的提示不一定长，而是要把问题边界讲清楚。实操时可以采用“目标 + 技术限制 + 功能清单 + 可视化要求 + 错误截图”的方式，逐步迭代。

### 5. 默认使用中等推理强度，不要一上来就开最高

视频里作者一开始使用较高推理强度，后来发现模型会“想太多”，导致速度慢、成本上升。对于大多数网页 demo、简单代码、UI 修复、脚本生成任务，中等推理强度已经足够。只有遇到复杂架构设计、困难 bug、长链路推理、多文件重构或基准测试类任务时，才有必要切换到高强度或最高强度。这个建议本质上是成本控制策略：先用便宜、快速的设置得到可运行版本，再针对关键问题加推理预算。不要把最高推理强度当默认配置，否则会浪费 DeepSeek V4 的性价比优势。

### 6. 对模型输出要以“可运行结果”而不是“看起来聪明”来验收

作者在演示中并不是只看模型回答，而是实际启动本地服务器、打开页面、测试 SVG 动画、进入卡丁车游戏、尝试控制、漂移、加速、偏离赛道。这个过程说明，AI 编码任务最重要的验收标准是产物能不能运行、交互是否符合预期、明显 bug 能否修复。比如架构讲解网页一开始主体没有居中，作者直接截图反馈，让模型修复；卡丁车游戏虽然不完美，但能启动、有控制、有地图、有音效，就算原型成立。普通用户使用 AI Agent 时也应该建立这种验收意识：不要被模型的解释骗过，要运行、点击、测试、截图反馈。尤其是低成本模型，更适合“快速生成—人工验收—局部修复”的循环。

### 7. 开源模型的透明性是一个额外优势

作者批评 OpenAI 和 Anthropic 隐藏推理层，认为用户只能看到输出 Token，却看不到模型的思考链路。相比之下，他认为 DeepSeek 这类开放模型的优势之一是透明度更高，用户可以看到更多推理过程。虽然实际产品中展示完整推理链也有安全、隐私和可靠性争议，但从开发者调试角度看，更透明的中间过程确实有助于理解模型为什么犯错、为什么卡住、为什么“想太多”。对于研究者和工程团队来说，开源生态还有另一个价值：架构、优化器、注意力机制、蒸馏方法可以被学习、复用和改进。作者借 Kimi 与 DeepSeek 的例子强调，开源社区会加速模型能力扩散。

### 8. 企业应准备“多模型路由”，而不是把所有任务绑死在一家闭源 API 上

作者用自己的 Anthropic API 花费举例，说明只要替换一部分工作流，每月成本就可能从 5000—6000 美元降到 500—1000 美元。这个观点对企业尤其重要：模型采购不应只选一个供应商，而应按任务类型建立路由策略。高价值、高风险任务用最强模型，低风险、高频任务用高性价比模型，代码原型和内部工具可优先用开源或低价模型。这样不仅降低成本，也减少对单一模型厂商的依赖。DeepSeek V4 这类模型出现后，企业真正需要建设的是评测集、任务分级、调用路由和成本监控，而不是盲目追逐最新模型名。

## 我的点评

这期视频的判断有相当现实的价值：在 AI 应用落地阶段，**单位成本**往往比“榜单第一”更能决定模型是否被大规模采用。作者用自己的 API 开销和四终端并行实操展示了一个关键趋势：只要模型能力达到可用阈值，价格优势就会快速转化为迁移动力。不过视频也有明显需要保留的地方，比如部分模型名称、基准名称和成本数字来自口播转写，且内部有“1.22 美元”和“0.2 美元”等口径不一致，不能当作严谨测评结论直接引用。作者对美国 AI 公司冲击的判断有道理，但也偏市场叙事，实际影响还取决于部署稳定性、延迟、合规、安全、生态集成和企业采购习惯。普通人最实用的做法不是立刻“全量迁移”，而是把 DeepSeek V4 当作高性价比工作流模型，用真实任务测试它能替代哪些昂贵 API。总体来说，这个视频最值得记住的一句话是：**DeepSeek V4 的革命性不在于能力绝对领先，而在于把接近前沿的能力变得足够便宜。**
