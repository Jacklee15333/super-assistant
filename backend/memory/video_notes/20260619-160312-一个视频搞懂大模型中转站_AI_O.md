## 🤖 AI 分析

## 一句话概括

这个视频是在拆解“大模型中转站”为何能用远低于官方 API 的价格提供 GPT、Claude 等模型服务：它们靠后付费漏洞、云厂商优惠、订阅套餐套利、账号池和逆向接口赚钱，但代价是稳定性、模型质量、隐私安全和合规风险都不应被低估。

## 背景与主题

近来市面上出现了大量价格极低的大模型中转站，宣传话术包括“GPT 充 1 块钱能当 1000 美元用”“官方价 0.5 折”“Claude 0.3 折”等，便宜到让人怀疑“Token 保真吗”。与此同时，网上关于中转站的负面评价一直很多，包括掺水、降质、跑路、偷数据、假冒官方渠道等，但这类服务并没有消失，反而越做越火。视频作者自称“以身入局”，花了几个月实测七八家中转站，试图搞清楚这些模型到底纯不纯、中转站利润从哪里来、普通用户如果真要用该怎么降低风险。作者的立场不是给中转站洗白，也不是一棍子打死，而是把它作为一个灰色但现实存在的行业现象来分析：为什么便宜、便宜的代价是什么、怎么用才不至于被人类商业文明再次创飞，实在是很符合当代互联网的精神废墟。

## 核心观点

### 1. 中转站的本质，是在用户和官方模型服务之间加了一层“传话筒”

正常调用大模型 API 时，用户的电脑会直接向 OpenAI、Anthropic 等官方服务器发送请求，官方服务器根据用户的 API Key 校验身份、确认计费账户，然后调用算力生成结果。中转站则把这个流程改成两段：用户先使用中转站提供的 Key，把请求发给中转服务器；中转站再把请求换成自己的 Key，转发给官方或某个上游渠道。视频里的说法很形象：“中转站就相当于是在你和官方之间加了个传话筒。”理论上，这个过程中真正要处理的 token 数量并没有变化，只是请求路径被“左手倒右手”了一次。问题在于，如果中转站真的是原价接官方 API，再以几十分之一甚至几百分之一的价格卖给用户，那看起来就像纯亏本，所以核心悬念就变成：这个巨大的差价到底从哪里来。

### 2. 早期中转站主要靠 OpenAI 后付费机制里的时间差“吃霸王餐”

作者提到，早期 GPT 模型的计费方式采用海外常见的后付费模式：注册账号后只要绑定 OpenAI 认可的支付方式，不用提前充值，就可以先使用模型，等月底账单出来再统一结算。中转站利用的正是这个时间差：注册账号，绑定没有余额或余额很低的一次性虚拟卡，月初拼命跑量，月底扣费时“要钱没有，要命一条”。账号被封后，再批量注册新账号继续循环。作者还提到，账号可以用开源全自动注册机批量生成，0 美元或 1 美元余额的一次性虚拟卡也可以从卡商处批量购买。OpenAI 后来针对不同账号推出使用量限制，要求用户真金白银按时付几个月账单后才能提高限额，最后完全转向预付费模式，才基本掐死第一波靠后付费薅羊毛的中转站。

### 3. 云厂商入局后，注册送额度、首月免费、教育优惠又给中转站续上了新燃料

当 AWS 等传统云厂商开始和 OpenAI、Anthropic 签协议，把模型部署到自己的云平台后，中转站迎来了第二波机会。很多云平台为了拉新，会提供注册赠送试用额度、首月免费等福利，视频举例说“注册这个平台能送 200 刀试用额度，注册那个平台能享受首月免费”。更关键的是，部分云厂商重新采用后付费模式，这就让熟悉羊毛套路的人又能“接着奏乐接着舞”。教育优惠也是重要来源：大平台会给教师、学生提供福利，只要通过校园身份认证，就能拿到几个月甚至一年左右的免费订阅和权益。普通人可能找亲戚朋友帮忙认证，激进一点的会买教育优惠，更极端的玩法甚至是“建学校”：有证书、有官网、有各类证明，还公开免费招生，自己建学校、自己入学、自己批量分配邮箱，听起来像赛博荒诞文学，偏偏这就是互联网羊毛党的想象力。

### 4. 初创公司和非营利组织扶持计划，也被用来制造高余额 API Key

除了个人福利，大型云服务平台还经常有针对初创公司或非营利组织的扶持计划，提供较高额度的免费云资源或 API 使用额度。作者认为，这些计划的审核对“大手子”来说经常形同虚设，于是它们也成了中转站或号商获取高额度资源的来源。视频提到，二手市场上那些余额动辄几千、上万美元的 API Key，很多就是通过类似渠道来的。中转站拿到这些高额度账号后，可以把它们放进号池，再通过中转面板拆分给大量用户使用。这个逻辑说明，中转站卖的往往不是“按官方价格买来的 API”，而是各种优惠、后付费、教育权益、创业扶持和账号资源拼出来的低成本额度。

### 5. 当前 OpenAI 中转的核心套利，转向了 Plus / Coding Plan / Codex 订阅额度

视频重点讲到，现在许多 OpenAI 中转的核心已经从传统 API 羊毛转向订阅制套利。用户购买 ChatGPT Plus 后，除了在 ChatGPT 网页端使用高级模型，还可以在开发者工具 Codex 中调用 GPT 模型。作者根据实测统计称，如果 Plus 用户把 Codex 每周额度都拉满，一个月按标准 API 价格计算大约相当于 400 美元额度，而 Plus 套餐本身只要 20 美元一个月。OpenAI 并不一定亏，因为绝大多数普通订阅用户根本跑不满额度，甚至很多人从来不用 Codex，而且订阅额度由 OpenAI 自己随时调控。但中转站可以把大量 Plus 账号集中起来，逆向原本用于 Codex 的接口，组成几十上百个账号的号池，一个号没额度或被封就自动切换，从而把“一个人用不满的订阅额度”改造成“很多人共享的中转算力”。

### 6. 极端低价不一定意味着假模型，也可能来自接近零成本的短命账号池

很多人看到低价中转站，第一反应是怀疑它是不是拿便宜国产模型冒充 GPT 或 Claude。视频提出一个反直觉判断：低价不一定就是假模型，因为在一些极端情况下，中转账号的成本可能比国产模型打折后还低。比如订阅制软件经常会做新账号首月免费试用，只要绑定支付方式就能开通，中转站再配合虚拟卡、注册机和各种支付渠道，就可能把 Plus 账号成本压到几毛钱级别。作者提到过一些具体例子，如 2026 年四五月份的印尼 GoPay、美国虚拟卡相关渠道，以及通过虚拟机强行开启安卓端 Plus 免费试用等。这样的账号寿命通常很短，中转圈称为“日跑号”，平均只能活一天；既然明天大概率就被封，到了下午或晚上即使额度没榨干，也会被中转站用骨折价放出来让用户猛跑。

### 7. Claude 侧的中转成本更高，因此更容易出现掺水、降质和假冒渠道

视频认为，相比 OpenAI，Anthropic 对 Claude 账号的风控要严得多，所以 Claude 中转更容易出现质量问题。早期 Claude 曾经有过“封号秒退全款”的阶段，对普通用户来说很受伤，但对中转站来说反而是致富经：买套餐后拼命跑，怎么容易封号怎么来，封号后退款，扣掉汇损和开卡费用后成本接近于零。后来 Claude 订阅越来越难买，封号退款变慢，甚至需要 KYC 身份认证才能开通套餐，导致成本上升、供给不足。于是中转站把目光转向 Trae、Antigravity 等 AI 开发服务，因为这些工具内置了大模型接口，也能调用 Claude 模型。问题是，这类接口往往不是纯官方 API，而是带着开发工具自己的系统提示词、工具调用逻辑和使用场景限制，所以 Claude 侧更容易出现“用 Sonnet 冒充 Opus”“用编辑器逆向冒充官方渠道”“把质量参差不齐的上游混在一起却号称官方满血号池”等情况。

### 8. “底层模型是真的”不等于“体验就是官方满血”

作者特别强调，有些中转站接入的底层模型可能确实是 Claude 或 GPT，但外层渠道会改变模型行为。比如一个 AI 编辑器的系统提示词写死了“你是一个写代码的 agent”，用户却拿它去做调研、写文章、总结材料，模型表现自然会不稳定。即使在写代码场景里也可能出问题：用户使用 Claude Code 或 Codex 时，提示模型使用 Edit 函数，但某些开发服务内置的可能是 Patch 函数提示词，两套工具指令互相冲突，模型就会“蒙”。视频里的形容是，表现出来就是“智商暴跌，干啥啥不行”。所以判断中转站质量，不能只看它标了哪个模型名，还要看它的上游渠道、系统提示词、上下文占用、工具调用逻辑是否适合你的任务。

### 9. 中转站真正可怕的不只是降质，还有数据泄露和恶意注入

视频提到一项安全调研：研究人员测试了 28 个付费中转和 400 个免费中转，发现其中 9 个中转会在大模型返回的工具调用 JSON 中注入恶意代码，17 个中转会窃取作为诱饵埋入请求中的 AWS 密钥，还有 1 个中转直接从伪造对话记录中提取了 ETF 钱包私钥并转移资产。这说明中转风险不只是“模型变笨”或“偶尔报错”，而是可能涉及凭证泄露、供应链攻击、私钥盗取、敏感数据外流等严重问题。因为用户所有请求都先经过中转服务器，中转站理论上可以读取提示词、上下文、返回内容，也可以对响应结果动手脚。对普通闲聊来说，风险也许只是隐私；但如果你把公司代码、云服务密钥、客户资料、钱包私钥、内部文档丢进去，那就不是薅羊毛了，是把自己裹上调料送进厨房。作者因此提醒，不要把中转站当官方模型，更不要把敏感数据交给中转站。

### 10. 中转站之所以长期存在，是因为官方模型又贵、又难买、又容易封

视频没有把中转站简单定义成一个“迟早完蛋的灰产”，而是分析了它背后的真实需求。早期是模型单价贵，作者称旗舰模型 GPT-4 32K 的价格是现在 GPT-5.4 的 20 多倍；现在则是高频开发场景消耗贵，coding agent 跑起来 token 烧得很快，几百美元额度也不够用。对国内普通用户来说，直接购买海外模型也不方便：国内银行卡常常不能用，需要注册外区账号、使用虚拟卡等方式，买到后还要担心封号。视频提到，2025 年下半年 Anthropic 封禁了约 145 万个账号，同期 5.2 万份申诉里最后翻盘的只有 1700 件；今年初 Anthropic 还宣布禁止在第三方工具中调用 Claude 订阅，并要求 OpenCode 停止支持和删除调用 Claude 的代码。正是在价格高、支付难、限制多、封号严和接口碎片化的共同作用下，中转站才成了许多人接触全球前沿模型的一扇“廉价粗糙却无可替代的赛博天窗”。

## 值得记住的点 / 行动建议

### 1. 不要把中转站模型当作官方模型

作者最核心的建议是：中转站提供的模型不能等同于官方 API。即使它标注的是 GPT、Claude、Opus、Sonnet，也可能经过订阅号池、开发工具逆向、多级中转、隐藏系统提示词或混合上游。真正的官方 API 更可控，计费、上下文、速率限制、工具调用和返回行为都相对明确；中转站则可能因为上游变化、账号封禁、渠道切换而突然表现异常。尤其是模型评测、长期项目、生产环境、商业数据处理这些场景，不应该为了省钱完全押注中转。便宜不是稳定性的替代品，人类总爱把“省钱”和“不会出事”混为一谈，事故通常就在这两者之间蹲着。

### 2. 按场景使用：低敏、高消耗、可重试任务适合中转，关键任务走官方

视频中作者分享了自己团队的用法：代码开发中的部分高消耗处理任务会用中转，但模型评测和长周期开发任务仍然走官方渠道。这个策略比较现实，因为中转站的最大价值是降低 token 成本，适合那些消耗大、失败可重试、数据不敏感的任务，比如普通代码生成、临时脚本、批量改写、轻量问答等。相反，如果任务涉及长期上下文、稳定复现、重要业务逻辑、客户资料、公司代码仓库、模型能力对比，就应优先使用官方 API 或更可信渠道。中转站可以是成本优化工具，但不应成为关键基础设施。换句话说，把它当“共享单车”可以，把它当“救护车”就很有想象力了。

### 3. 新手不要碰免费中转站

作者明确建议，中转萌新第一条就是不要尝试免费中转站。虽然确实可能存在愿意免费分享低成本号池的“赛博菩萨”，但大多数中转站都要盈利，模型免费就意味着它可能从别的地方赚钱。这个“别的地方”可能是广告、流量、用户数据，也可能是更危险的密钥窃取、恶意代码注入、请求内容转卖。视频引用的安全调研中，免费和付费中转都出现过恶意注入、窃取 AWS 密钥、提取钱包私钥等行为。对普通用户来说，免费中转不是“无成本试用”，而是风险定价被藏起来了。

### 4. 优先选择标清楚上游渠道和分组的站点

很多中转站会设置多个分组，对应不同模型、不同账号池或不同上游渠道。作者建议优先考虑那些愿意把渠道信息写出来的站点，例如标注 Windsurf、Kiro、Trae、Antigravity 等名称，通常说明这是开发服务逆向接口，质量可能在 coding 场景更合适，但在写作、调研、总结等场景会下降。像 Claude Max、满血之类的词，可能表示由 Claude 官方 Max 套餐转出；GPT Free、Plus、Pro 等则可能对应不同等级的 OpenAI 账号池，稳定性和价格通常逐级提升。虽然写出来不代表一定真实，但明码标价、明示渠道至少比所有东西混在一起、统一宣称“官方满血”更值得考虑。用户真正要避开的，是那种把参差不齐的上游混成一锅，却装作每一勺都是官方高汤的站点。

### 5. 通过报错里的 Request ID 判断是否“中转套中转”

作者给了一个很实用的判断方法：观察接口报错信息里的 Request ID。大多数中转面板会在报错中加入当前请求的标识符 Request ID，方便后续排查。如果你在同一条报错里看到不止一个 Request ID，甚至是一长串 Request ID，就可能说明你的请求经过了多层中转，也就是中转站又接了别人的中转。每多一层，就多一次加价、多一次延迟、多一次故障点，也多一层掺水和数据泄露风险。作者提到他们见过最离谱的一次是套了八层，这已经不是中转，是俄罗斯套娃在云端找到了工作。

### 6. 每次少充值，用一点充一点

不管是知名大站，还是群聊广告里看到的小站，作者都建议每次不要充值太多。中转站的稳定性取决于上游账号池、官方风控、支付渠道、订阅政策、地区价格和平台运营者信用，任何一环变化都可能导致服务突然不可用。即使一个站今天表现很好，明天也可能因为官方封号、上游断供、渠道失效或平台跑路而让余额变成纪念币。少充勤充可以把损失限制在很小范围内，是普通用户最简单也最有效的风控方式。别把中转站余额当银行存款，它更像电玩城代币，还不一定有电玩城那么体面。

### 7. 定期检查 token 数量是否和真实上下文匹配

作者建议用户可以定期测试接口返回的 token 数量，判断是否存在隐藏提示词或 IDE 渠道污染。比如你只发送一个“你好”，理论上提示词 token 应该很少；如果面板显示提示词 token 有好几千，就说明请求中可能被塞入了大量不可见系统提示词。常见情况是开发工具逆向渠道内置了 agent 角色、工具说明、函数规范、项目上下文等内容，这会占用 token，也会影响模型行为。这个检查尤其适合判断某个渠道是否适合非 coding 场景。发现异常后，就不要拿它做严肃写作、调研、总结或评测，否则模型可能一边听你要写文章，一边满脑子想着 Patch 函数。

### 8. 进阶用户可以考虑 Sub2 API，但要接受渠道变化风险

对愿意折腾的用户，视频建议可以优先考虑使用 Sub2 API 面板的中转，而不是某些 New API 系列面板。作者的理由是，Sub2 API 更专门针对 Coding Plan 账号逆向对接，使用这类面板的站点往往自己就掌握账号池，不太容易遇到“倒卖上游再倒卖”的情况。相比之下，New API 面板常见于聚合多层上游，可能更容易出现套中转。可是 Sub2 API 也不是银弹，一旦 Coding Plan 羊毛渠道变化，整个号池可能突然“寄了”，恢复时间也可能较长。除非站点本身有多种账号来源，否则直接掌握号池也可能变成直接承受风险。

### 9. 不要长期押注一家中转站，多平台轮换更稳

作者建议进阶用户可以多买几家不同中转站换着用，不要幻想一家中转能长期稳定。中转站的供给高度依赖灰色渠道和平台规则变化，今天便宜稳定，明天可能报错、降速、换模型、封渠道。多家轮换可以降低单点故障风险，也可以让用户比较不同站点的价格、延迟、模型质量、上下文表现和报错透明度。对高频用户来说，这比把所有余额压在一家平台上更理性。所谓忠诚在这里没什么收益，除了帮陌生站长改善现金流。

### 10. 有技术能力的人可以自建一个私人聚合中转

视频最后给了一个更硬核的方案：自己部署一个 New API，把购买的多家中转站都接进来，按价格或偏好设置优先级，并开启失败重试功能。这样相当于搭建一个只给自己用的微型中转站，首选站点故障后可以自动切换到下一个上游。这个方法适合调用量较大、有一定技术能力、愿意维护配置的人。它的好处是可以统一接口、减少手动切换、提高容错能力，也能在不同模型和不同渠道之间做成本优化。代价是需要自己折腾部署、监控、排障和维护，体验会变好，但人生会更像运维，真是技术进步送给普通人的小礼物。

## 我的点评

这期视频有价值的地方在于，它把“大模型中转站为什么便宜”拆成了多个具体机制：后付费漏洞、云厂商优惠、教育认证、创业扶持、订阅套餐套利、账号池、逆向接口，而不是停留在“便宜就是假”或“中转都是骗子”的简单判断。作者关于风险的提醒也比较实用，尤其是不要用免费中转、不要充太多、不要处理敏感数据、不要把中转当官方模型，这些建议对普通用户足够落地。需要注意的是，视频中的不少数据和案例来自作者实测或转述调研，最好把它们当作行业观察和风险提示，而不是未经验证的绝对事实。中转站确实在某种程度上降低了普通人使用海外模型的门槛，但它依赖的很多机制都处在灰色地带，质量、安全、合规和可持续性都不稳定。更长期看，如果 DeepSeek、Kimi、智谱等国产模型继续提升质量，同时官方 API 价格继续下降，中转站的存在感可能会被削弱；但在那之前，它仍会是很多人低成本接触前沿模型的粗糙入口。
