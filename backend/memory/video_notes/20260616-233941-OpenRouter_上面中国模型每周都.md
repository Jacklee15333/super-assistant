## 🤖 AI 分析

## 一句话概括

这个视频主要解释了为什么中国大模型虽然普通用户日常感知不强，却能在 OpenRouter 等平台持续霸榜：它们正在被大量企业用于低成本、高频率、自动化的行业智能体流水线中。

## 背景与主题

视频围绕一个学员提出的问题展开：OpenRouter 上中国模型每周都排在前列，比如混元、MiniMax、Mimo/Memo、Kimi 等，但普通用户似乎并不常用，那么到底是谁在用？作者的回答是：这些模型并不是主要出现在普通人的聊天窗口里，而是深入到了企业内部的自动化业务流程中。作者以律所合同审查、文档翻译产品、全球观众网等例子说明，不同模型在实际业务中承担不同层级的任务。整体立场是：顶级模型适合复杂推理和开发，但大量企业级、高频、标准化任务，更适合用便宜、快、质量足够好的国产模型。

## 核心观点

### 1. 中国模型在 OpenRouter 霸榜，背后不是普通用户，而是企业流水线在调用

视频开头指出，中国模型“每周都霸榜”，基本上每周排在最前面的常见模型包括混元、MiniMax、Mimo/Memo、Kimi 等。作者抛出一个关键问题：“你不用，我不用，到底是谁在用呢？”他的解释是，普通用户可能没有在日常聊天、写代码、做软件开发时频繁感知到这些模型，但企业自动化流程正在大量调用它们。也就是说，榜单上的高调用量并不一定来自 C 端用户，而可能来自 B 端场景中的批量任务、自动化任务和后台智能体调用。这解释了为什么用户体感和平台数据之间会出现错位：用户看到的是前台产品，企业消耗的是后台 API。

### 2. 律所合同审查是典型场景：量大、页数多、不能全部交给顶级模型

作者举了一个律所的例子：每周客户发来需要审查的合同可能有几千份，小合同几页，大合同几十页、上百页，甚至几百页。面对这种规模，不可能把所有合同都丢给最顶级的 Agent，例如 Codex、Claude 这类强推理模型。一方面，重度推理模型速度慢；另一方面，合同页数越多，输入输出 token 消耗越大。作者特别提到，一份 100 页合同的输入输出可能就是几十万 token，如果一个月有几千份合同，订阅账户或预算根本扛不住。因此，企业会更倾向于搭建自己的行业智能体，把不同环节分给不同价格和能力层级的模型。

### 3. 顶级通用模型不等于专业行业智能体，行业任务需要自建流程

视频强调，Claude、Codex 这类顶级模型虽然能力强，但它们并不是“专业合同审查智能体”。合同审查不仅是读懂文本，还涉及合同范例库、条款标准、签署完整性、权利义务对等、违约责任、判例匹配等专业流程。作者认为，律所真正需要的是根据自身业务搭建一套合同审查智能体，而不是简单把合同上传给一个通用大模型。这个观点背后的逻辑是：行业智能体的价值不只在模型本身，还在工作流设计、知识库建设、任务拆解和模型选型。也就是说，模型只是底座，真正决定效率和质量的是企业如何把模型嵌入业务流程。

### 4. 合同审查流程会拆成多步，不同任务调用不同层级模型

作者详细拆解了合同审查智能体的第一步：先建立合同范例库或知识库，这就需要做向量嵌入，可能会用到“签问/千问的 embedding 模型”。进入合同审查流水线后，又会分成多个步骤，例如先检查基础错误：甲方乙方是否签字、是否漏掉免责声明、是否缺少不可抗力等格式化条款。这类任务不需要很强推理能力，因此可以使用轻量、便宜、速度快的模型，例如视频中提到的 DVC V4 Flash、Memo/Mimo V2.5 等。只有到复杂环节，比如判断甲乙方权利义务是否对等、根据合同追究违约责任、去判例库检索相关判例并判断匹配程度时，才需要启用深度推理模型。这个例子说明，企业并不是“一个模型打天下”，而是把任务拆细后按性价比分配模型。

### 5. 真正的大规模消耗来自简单但高频的任务，而不是最复杂的推理任务

视频里一个重要判断是：轻量模型的消耗“非常非常多”。因为在企业流程中，基础检查、格式识别、字段抽取、简单分类、条款缺失检查等任务虽然单次难度不高，但调用频率极高。比如律所每周几千份合同，每份合同都要检查签字、条款、格式和基础风险点，这些环节加起来就是巨大的 token 和 API 调用量。相比之下，真正需要复杂推理模型的环节可能只占少数，例如权责分析、违约责任判断、判例匹配等。作者因此认为，国产轻量模型霸榜并不奇怪，因为企业自动化流水线最需要的恰恰是“够用、便宜、快、稳定”的模型。

### 6. 作者自己的翻译产品也采用分层模型策略

作者用自己的文档翻译软件举例：文档翻译中，最重要、最复杂的环节其实是“文档解析”，而不只是翻译本身。他说文档解析阶段用的是 Gemini 3.5 Flash；如果遇到复杂表格，比如泰文、扫描版、跨页表格，就会用 Gemini 3.5 Pro。原因是解析阶段要处理版式、表格、跨页结构和 OCR 复杂情况，一旦解析错了，后续翻译再好也没有意义。但当文档已经被解析成 Markdown 之后，翻译本身就可以交给更轻量的模型，比如以前使用 Gemini 3 Flash Preview，现在则大量替换成 Memo/Mimo V2.5。这个案例进一步说明：企业产品会根据流程环节的难度，把高成本模型用在关键节点，把低成本模型用在高频环节。

### 7. 作者认为 Memo/Mimo V2.5 这类中国模型在质量、速度、价格上很有竞争力

视频中作者明确说，他发现 Memo/Mimo V2.5“质量非常高，速度很快，价格又超级便宜”。因此，他已经把几个产品里原来使用的 Gemini 3 Flash 基本都换成了 Memo/Mimo，包括“全球观众网”和自己的翻译软件。这个说法体现了作者对国产轻量模型的核心评价：不是在所有能力上都超过顶级模型，而是在特定业务任务中具备很强的性价比。对于文档翻译、内容处理、标准化任务来说，只要质量达到要求，速度和价格就会成为非常关键的商业指标。换句话说，模型竞争不只是“谁最聪明”，也是“谁最适合被大规模调用”。

### 8. 顶级模型仍然适合编码和复杂开发，但不是所有业务都需要它

作者并没有否认 Claude、Codex 等顶级模型的价值。他明确说，如果是日常编码、软件开发、复杂 Agent 工具，肯定还是要用 Codex、Claude 这些全球最强模型。但如果企业要搭建自己的行业智能体和公司内部流水线，大部分情况下国产模型更划算。即便是需要重度推理的场景，作者观察到很多业务也很少直接使用 Opus 4.8 或 GPT-5.5，而是用 DeepSeek V4 Pro 一类模型就够了。原因很现实：价格差距太大，而企业追求的是任务整体成本、稳定性和交付效率，不是单次回答的最高智商。

### 9. 搭建行业智能体的关键能力，是理解模型特性并建立标准化测试集

视频最后给出的核心建议是：如果想搭建自己的行业智能体，就必须了解不同模型的特性，并学会通过标准化测试集进行精准、高效的模型选型。所谓模型特性，不只是看排行榜，而是要知道哪个模型适合文档解析、哪个适合翻译、哪个适合条款检查、哪个适合复杂推理。标准化测试集则是把自己行业中的真实任务样本整理出来，用统一标准测试不同模型的质量、速度、价格和稳定性。这样才能避免凭感觉选模型，也能避免盲目使用最贵的模型。作者认为，这会成为非常重要的技能，因为未来企业智能体不是单模型竞争，而是模型组合和工作流竞争。

## 值得记住的点 / 行动建议

### 1. 不要只看模型排行榜，要看模型实际被用在哪些业务环节

OpenRouter 这类平台的榜单能反映模型调用热度，但不能直接等同于普通用户的主观体感。普通用户可能每天使用 Claude、ChatGPT、Codex 做写作或编程，因此觉得中国模型存在感不强；但企业后台可能正在用国产模型处理合同、翻译、客服、分类、抽取、审核等大量高频任务。判断一个模型有没有商业价值，不应只看它在聊天窗口中的表现，还要看它能不能被嵌入企业流程。真正决定模型调用量的，往往是自动化流水线中的稳定任务，而不是个人用户的一次性问答。

### 2. 搭建智能体时，要先把业务流程拆成多个子任务

作者反复强调，一个行业智能体不是简单调用一个大模型，而是要把流程拆成多个环节。例如合同审查可以拆成知识库建设、向量嵌入、签署完整性检查、条款缺失检查、权利义务分析、违约责任判断、判例匹配等。每个环节对模型能力要求不同，有些只需要识别和匹配，有些需要严肃推理和专业判断。只有拆清楚任务，才能知道哪些地方可以用轻量模型，哪些地方必须上强推理模型。这种拆解能力，本质上就是 AI 产品经理和行业智能体架构师的核心能力。

### 3. 高频简单任务优先考虑便宜、快、稳定的模型

企业应用中，最烧钱的未必是最难的任务，而是调用次数最多的任务。比如合同签字检查、免责声明检查、不可抗力条款检查，这些任务单次看起来很简单，但如果每周处理几千份合同，累计 token 和调用次数会非常大。对这类任务而言，顶级模型可能是“性能过剩”，使用轻量国产模型反而更符合商业逻辑。选型时应重点比较单次成本、并发能力、响应速度、稳定性和错误率，而不是只看模型综合榜单。能用便宜模型解决的环节，就不要浪费昂贵推理模型。

### 4. 把最贵、最强的模型留给真正复杂的关键节点

作者并不是主张所有任务都用国产轻量模型，而是主张“分层使用”。例如在合同审查中，判断甲乙方权利义务是否对等、根据合同追究违约责任、匹配判例库，这些任务对推理能力、法律知识和上下文理解要求更高，应该使用更强模型。再如文档翻译中，复杂扫描版、跨页表格、泰文表格的解析，比普通翻译更关键，因此作者会使用 Gemini 3.5 Pro。这样的策略可以把预算集中在真正影响结果质量的环节。企业部署 AI 时，正确做法不是全流程省钱，而是把钱花在最容易出错、最影响成败的位置。

### 5. 建立自己的标准化测试集，而不是凭感觉选模型

作者最后特别强调“标准化测试集”的重要性。对于企业来说，通用评测榜单只能提供参考，真正可靠的测试应该来自自己的业务数据。例如律所可以整理一批真实合同样本，标注签字缺失、条款缺漏、权责不对等、违约责任争议等标准答案；翻译产品可以整理扫描版、复杂表格、跨页表格、多语言混排等测试材料。然后用同一批样本测试不同模型，比较准确率、速度、成本、稳定性和输出格式可控性。这样选出来的模型才适合自己的业务，而不是适合媒体宣传或通用榜单。

### 6. 做 AI 产品要关注“模型组合”，而不是迷信单一最强模型

视频的核心启发之一是，未来企业级 AI 应用很可能不是由一个模型完成所有任务，而是由多个模型组合完成。一个流程中可能同时使用 embedding 模型、轻量生成模型、文档解析模型、强推理模型、判例匹配模型等。每个模型负责自己最擅长的部分，最终形成一个成本可控、质量稳定、速度足够快的自动化系统。对创业者或企业负责人来说，重要的不是追逐“哪个模型最强”，而是设计“哪个任务用哪个模型最划算”。这种模型编排能力，会比单纯会调 API 更有长期价值。

### 7. 评估国产模型时，要放到具体场景里看，而不是抽象地说能不能打

作者反对一种简单判断：因为日常写代码还要用 Claude、Codex，所以中国模型“完全不能打”。他的观点是，不同模型适合不同地方，顶级模型在编码和复杂 Agent 上确实强，但国产模型在大量企业流程中可能更划算、更好用。尤其是轻量任务、批量任务、结构化任务、翻译和文本处理任务，国产模型的速度和价格优势会被放大。因此评价一个模型时，不能脱离任务场景。正确问题不是“这个模型是不是世界第一”，而是“在我的任务里，它的效果、速度和价格是不是最优解”。

## 我的点评

这个视频的核心判断是有道理的：企业级 AI 应用往往追求整体工作流效率，而不是单点模型能力最强，所以轻量、便宜、速度快的模型确实会有巨大调用量。作者用律所合同审查和文档翻译产品举例，把“为什么中国模型能霸榜但普通用户感知不强”解释得比较清楚，尤其是任务分层、模型分层、成本控制这几条逻辑很实用。不过，视频中的部分模型名称和版本可能受到语音识别影响，比如 DBC/DVC、Mimo/Memo、Gemini 3.5 等，实际引用时最好再核对原视频或官方信息。另外，作者的判断明显带有个人产品经验色彩，适合用作选型思路参考，但不应直接等同于所有行业的通用结论。普通人最值得借鉴的是：不要盲目迷信最贵模型，而要根据自己的任务建立测试集，用结果、速度和成本来决定模型组合。
