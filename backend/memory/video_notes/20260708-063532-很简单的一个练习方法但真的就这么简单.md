## 核心观点

### 1. 想成为厉害的人，首先要培养主动发现问题的能力
作者开头提出一个问题：「如何成为一个厉害的人呢？」他的答案不是多读多少书、掌握多少理论，而是从日常生活中有意识地发现值得思考的问题。比如，当你看到别人抱怨某件事时，不要只是听完或者跟着抱怨，而应该进一步追问：这个人为什么抱怨？他究竟遇到了什么问题？是什么原因让他产生不满？ 这些抱怨背后往往隐藏着某种没有得到满足的需求、没有被解决的困难，或者现有方案存在的缺陷。长期进行这种训练，就能逐渐从被动接受信息转变为主动识别问题，培养对真实需求和现实矛盾的敏感度。
深层逻辑： 大量有价值的解决方案，最初并不是来自一个完美的创意，而是来自对某个现实问题的准确识别。发现问题，是解决问题的前提。

### 2. 听到抱怨时，不要停留在情绪层面，而要主动思考解决方案
视频强调，发现别人遇到问题后，还要进一步问自己：「如果是你的话，你该怎么解决？」这一问题能够让你从旁观者转变为问题的解决者，开始主动寻找可能的方案。比如，有人抱怨某个工作流程繁琐，你不仅应该理解他为什么不满，还可以思考流程中哪些步骤是多余的、哪些环节可以简化，以及有没有更高效的替代方式。即使最终没有机会真正实施这些方案，思考过程本身也能锻炼你分析问题、权衡选择和设计解决路径的能力。关键在于，不要只形成「这里有问题」的判断，而要继续走向「我能怎么解决」的思考。
深层逻辑： 抱怨描述的是问题带来的负面体验，解决方案则要求你识别原因、明确目标并提出行动。两者之间的转换，正是成长为主动解决问题者的重要一步。

### 3. 看到一件事情成功，要倒过来研究它究竟解决了什么问题
作者提出，面对成功的事情，不要仅仅感叹它做得好，而要分析：「这件事解决了什么问题？它是怎么解决的？」这里包含两个层次：第一个是理解成功的价值来源，第二个是理解价值是如何被创造出来的。比如，某项服务受到用户欢迎，真正值得研究的并不只是它的外在表现，而是用户原本遇到了什么困难、现有方案有什么不足，以及新服务为什么能够更有效地解决问题。这样的分析方式可以帮助人们从成功现象深入到成功机制，避免简单模仿表面形式。真正有价值的学习，不是记住别人做了什么，而是理解别人为什么这样做，以及这样做为什么有效。
深层逻辑： 成功案例往往可以被视为一个已经得到一定程度验证的解决方案。通过逆向分析，可以提炼其中能够迁移到其他场景的方法，而不是机械复制结果。

### 4. 分析成功产品，要明确「谁在什么场景下遇到了什么问题」
视频中特别强调了一个非常重要的产品分析问题：「如果一个产品成功了，这个产品解决了什么人在什么场景下的什么问题？」这句话实际上提供了一套简洁的产品思维框架：目标人群、使用场景、真实问题、解决方式。 同一款产品对不同用户可能具有完全不同的价值，而相同需求在不同场景下也可能需要不同的解决方案。例如，一款收纳产品的价值可能不只是能够存放物品，而是在特定空间里帮助某类用户减少杂乱、提高取用效率或节省空间。理解这些具体因素，才能进一步解释产品为什么受到欢迎、哪些设计值得学习，以及哪些地方仍有改进机会。
深层逻辑： 产品价值并不只来自功能数量或外观设计，而来自产品与用户真实需求之间的匹配程度。分析成功产品时，必须把它放回实际使用场景。

### 5. 学习成功案例之后，还要进一步思考「如果由我来做，能否改进」
作者并没有把学习成功案例停留在理解和模仿，而是继续提出：「如果是你的话，可以怎么改进？」这意味着真正有效的学习，不应该以知道别人为什么成功作为终点，还应该进一步寻找现有解决方案的不足。例如，一款产品虽然功能优秀，但可能存在操作繁琐、使用不便、安装困难或某些细节体验不佳的问题。通过主动寻找这些缺陷，你就不再只是学习别人已经完成的成果，而是在尝试提出自己的判断、设计选择和解决方案。这种训练能够逐步培养独立思考能力，让你从借鉴者向改进者转变。
深层逻辑： 理解优秀案例主要训练分析能力，而提出改进方案还需要判断力和创造力。两者结合，才更容易形成能够应用到实际工作的知识体系。

### 6. 发现有趣的事情，可以先模仿并完成一个「60分版本」
视频中一个非常实用的建议是：「如果你发现一个有趣的事情的话，你可以尝试去复制它，做到60分。」这体现的是一种先完成、再完善的实践思维：当你发现值得学习的产品、方法或作品时，不必等到完全理解所有细节、具备全部能力以后才开始行动。可以先尝试按照自己的理解做出一个基本版本，即使它只达到自己心目中60分的水平，也比长期停留在观看、收藏和研究阶段更有价值。因为实际动手时，你往往会遇到观察阶段无法发现的问题，例如知识不足、步骤不清楚、工具不熟悉或现实条件不允许。一个已经完成的60分作品，能够暴露真实问题；一个始终停留在脑海中的100分构想，却很难提供有效反馈。
深层逻辑： 实践不仅是检验学习成果的手段，本身也是获得新知识的重要方式。「60分」并非客观评分标准，而是作者用来强调先做出可用版本的形象表达。

### 7. 从60分到90分，是通过持续优化建立真正的能力
作者进一步提出：「如果觉得有意思，把它做到90分。」这句话说明，初次完成并不是学习的终点，而只是下一轮优化的起点。第一版通常可以帮助我们理解基本结构和实现方法，而后续优化则要求我们重新检查哪里存在不足、哪些细节影响效果，以及如何通过调整让成果更接近理想状态。与单纯重复制作不同，从60分提高到90分需要有意识地识别差距、提出改进假设，并通过实际修改验证效果。真正的能力提升，往往发生在你面对不理想的结果、分析原因并持续修正的过程中。
深层逻辑： 初次模仿训练的是复现能力，持续优化训练的是诊断能力、判断能力和独立改进能力。两者共同推动一个人从「知道怎么做」走向「知道怎么做得更好」。

### 8. 长期坚持「发现—解决—实现—优化」的闭环，才能形成可迁移的综合能力
视频最后总结：「长期地去练习，发现问题，解决问题，把它做出来，看看能不能去优化，长此以往你会成为一个非常厉害的人。」这里最重要的不是某个单独技巧，而是建立一套持续重复的完整训练流程。发现问题让你明确努力方向，设计解决方案让你训练思维，动手实现让你接触真实约束，持续优化则帮助你从反馈中积累经验。当这套方法被反复应用在不同工作、产品和生活场景中，你所积累的就不只是零散知识，而是一套能够迁移到新问题上的方法。作者所说的「厉害」，更接近一种面对陌生问题时，能够主动分析、尝试解决并不断改善结果的综合能力。
深层逻辑： 知识只有进入实际应用和反馈循环，才更容易转化为稳定能力。决定长期成长效果的，不仅是接触多少信息，还包括是否反复完成思考与行动的闭环。

## 值得记住的点 / 行动建议
以下是根据视频方法进一步整理的可执行训练方案。具体的训练时长、记录模板和示例属于实践延伸，并非作者在视频中逐项规定。

### 1. 建立「每日一个问题」练习，每天用10分钟训练问题意识
每天从工作、生活、购物、学习或网络内容中寻找一个值得研究的问题，不需要特别重大，普通的小问题就可以成为训练素材。
可以固定回答五个问题：
**1. 发生了什么？ 用一句话描述观察到的现象。**
**2. 谁受到了影响？ 明确遇到问题的人。**
**3. 为什么会出现这个问题？ 尝试分析真正原因。**
**4. 目前有哪些解决方式？ 判断已有方案的优缺点。**
**5. 如果由我处理，我会怎么解决？ 至少提出一种具体方案。**

例如，同事经常抱怨开会效率低，可以进一步分析会议是否缺少议程、决策责任人或明确结论，并尝试提出会前共享资料、限定讨论时间、会后明确待办事项等改进方案。
这个练习的目标不是每天解决一个重大问题，而是让主动分析逐渐成为思维习惯。

### 2. 看到优秀作品时，强迫自己回答「它为什么有效」
不要只是收藏优秀的文章、产品、设计、视频或商业案例，而要把它们当作研究对象。
推荐使用下面的分析模板：

| 分析维度 | 具体问题 |
| --- | --- |
| 目标对象 | 它主要服务谁？ |
| 核心需求 | 对方最想解决什么问题？ |
| 使用场景 | 用户会在什么情况下需要它？ |
| 解决机制 | 它具体使用什么方法解决问题？ |
| 竞争优势 | 它相比其他方案好在哪里？ |
| 不足之处 | 目前仍存在哪些问题？ |
| 我的改进 | 如果由我重新设计，会修改什么？ |

关键要求：不能只描述作品优秀在哪里，还要尝试解释它为什么能够产生这些效果。
这种方式可以将日常接触的信息逐渐转化为有结构的知识和经验。

### 3. 把「用户—场景—问题—方案」作为分析产品的固定公式
对于任何产品，都尝试完整地写出一句话：
这个产品帮助【某类用户】，在【特定场景】下，解决【具体问题】，通过【某种方案】实现【某种价值】。
例如，下面是一个用于练习的假设案例，并非视频原有案例：
一款免打孔浴室收纳架，帮助租房用户在不方便钻孔的浴室环境中解决洗浴用品摆放杂乱的问题，通过免打孔安装和分区收纳提升空间利用率和使用便利性。

之后再继续追问：
- 是否所有租房用户都有这个需求？
- 胶贴是否适用于不同墙面？
- 承重能力是否足够？
- 安装步骤能否进一步简化？
- 是否能够在不明显提高成本的情况下改善体验？

通过这种分析，就能从「这款产品卖得不错」深入到「它为什么可能受到目标用户欢迎，以及有哪些可以改进的地方」。

### 4. 遇到想学习的技能，优先做出一个「60分成果」
不要把所有时间都投入学习资料，而迟迟没有实际作品。
可以采用以下流程：
**1. 选择一个具体对象。 例如一篇好文章、一张优秀设计图、一个数据分析表格或一套工作流程。**
**2. 拆解它的结构。 搞清楚它由哪些部分组成，每一部分有什么作用。**
**3. 尝试独立复现。 尽量按照自己的理解完成一个基本版本。**
**4. 记录遇到的问题。 找出自己在哪些地方无法理解、无法完成或效果不好。**
**5. 提交或展示成果。 通过对照原作品、实际使用或他人反馈判断基本完成度。**

这个阶段最重要的目标不是完美，而是让学习产生可观察、可评价的成果。
判断是否达到所谓的60分，不应该只靠主观感觉，而应该看成果是否已经实现最基本的目标。

### 5. 将60分成果提升到90分时，一次重点改善一个问题
很多人完成第一版之后，要么直接放弃，要么同时想修改太多地方，最终失去改进方向。
更有效的办法是进行有重点的迭代：先确定当前成果中最影响使用效果的一个问题，分析原因，提出改进方式，再完成一次修改。
例如，完成一份产品介绍页面后，可能发现标题不够明确、图片顺序不合理、重要卖点不突出、文字过于密集等问题。此时可以先优化标题和信息层级，再检查用户是否更容易理解产品价值，而不是一次性推翻所有内容。
建议每轮记录三个信息：修改了什么、为什么这样修改、修改后效果如何。
如果条件允许，还可以使用实际数据、测试结果或用户反馈验证优化是否有效，避免把个人偏好误认为客观改进。

### 6. 建立「问题—方案—实践—复盘」知识库，而不是普通资料收藏夹
视频标题中提到「打造用得出来的知识体系」，它与作者提出的实践方法高度一致。
普通的资料收藏往往只保留知识内容，却没有留下应用场景和实践结果。更有价值的记录方式，是把知识与它解决过的问题关联起来。

 复制本次练习记录填写后可复制到自己的笔记工具中长期保存。
当你积累了足够多这样的记录，就可以按问题类型、使用场景、解决方法进行归类，逐渐建立属于自己的案例库。
真正值得保存的，不只是「我知道什么」，更包括「我在哪种情况下使用过什么方法，以及最终产生了什么结果」。

### 7. 每周复盘一次，判断自己是否真的在提升
每天观察和实践能够形成积累，但如果缺少定期复盘，可能会不断重复同样的错误。
建议每周找出本周最有价值的两到三个问题，分别检查：
- 是否准确识别了真正的问题，而不是只看到了表面现象？
- 提出的解决方案是否可行？
- 是否真正动手尝试，而不是只停留在想法？
- 哪项改进产生了实际效果？
- 有没有一种方法可以应用到其他相似问题？

如果连续几周都发现自己能够更快定位问题、更准确判断原因，或者能够独立完成过去无法完成的事情，就说明这种训练可能正在产生实际效果。
不要仅用每天做了多少练习衡量成长，还要关注解决问题的质量是否提高。

### 8. 用30天建立完整的能力训练循环
可以将视频中的方法扩展为一个30天实践计划，先培养稳定的训练习惯，再逐步提升完成度。
30天训练计划
0/4 阶段完成

第1周：训练发现问题
每天观察一个抱怨、障碍或不便，记录问题及可能的原因
阶段目标：完成7条问题观察记录

第2周：拆解成功案例
每天分析一个成功产品、作品或方法，明确用户、场景、问题与解决机制
阶段目标：完成7份简短案例拆解

第3周：动手复现到60分
选择一个最有学习价值的案例，拆解结构并制作自己的初步版本
阶段目标：完成一个可展示、可测试的成果

第4周：迭代优化到90分
针对初版中最重要的不足持续修改，收集反馈，记录每次改进
阶段目标：完成至少两轮优化和一次复盘

这份计划的价值不在于30天必然产生某种能力飞跃，而在于确保自己真正经历从观察、分析到实践、优化的完整过程。
30天结束后，最重要的复盘问题是：我现在能不能独立发现并解决一个以前没有能力处理的问题？

## 我的点评
这段视频最值得认同的地方，是它把「提升自己」这个抽象目标转化为可以每天练习的具体行为，尤其强调从观察现实问题出发，而不是漫无目的地囤积知识。作者提出的「成功案例逆向分析」和「先做60分、再优化到90分」具有很强的实践价值，因为它们把理解、模仿、行动和反馈连接成了一个完整过程。需要注意的是，现实问题往往涉及成本、资源、专业知识和外部条件，并不是只要反复思考就一定能找到正确答案，因此还需要事实核查、实际测试和他人反馈。视频中的60分与90分也只是形象化表达，不应被理解为客观、可量化的能力等级，更不意味着所有作品都值得投入大量时间打磨。对于普通人而言，最有价值的应用方式，是选择一个自己熟悉的领域，持续记录真实问题、研究优秀解决方案、完成具体作品，并根据结果不断修正。 长期来看，这种方法最可能带来的变化，是从被动接收知识，逐渐转向主动识别需求、独立解决问题和创造实际价值。

最后值得记住的一句话：
不要只做一个知道很多方法的人，要努力成为一个能够发现问题、想出办法、动手解决，并且不断把事情做得更好的人。

建议从今天开始，先挑选一个真实的小问题，完成一次「观察—分析—解决—复盘」的练习；积累30次这样的经历，比单纯收藏30条成长建议更有实践意义。
