## 🤖 AI 分析

## 一句话概括

这个视频用「记忆、技能、自我训练」三层机制解释 Hermes（爱马仕）智能体为什么不只是一个更好用的 Agent，而是在尝试让 Agent 的工作经验反过来成为模型进化的数据来源。

## 背景与主题

视频讨论的是近期很多人关注的 **Hermes / 爱马仕智能体**，尤其是它被称为“会自主进化、越用越聪明”的原因。作者认为，很多人只从体验层感受到它“好像变聪明了一点”，但说不清它和 OpenClaw / 小龙虾这类 Agent 工具到底有什么本质区别。视频的核心不是简单做产品测评，而是从底层机制解释 Hermes 的「自主成长」：它会自主沉淀记忆、自主创建和修复技能，并把 Agent 的工作轨迹转化为训练数据。作者同时也提醒，Hermes 目前仍然更像研究项目和开源项目，商品化体验、生态完整度并不如 OpenClaw。

## 核心观点

### 1. Hermes 和 OpenClaw 的基础能力差距并不大，真正差异在“自主成长”

作者一开始强调，如果只看基础能力，Hermes 和 OpenClaw / 小龙虾几乎是同一档：记忆、搜索、技能系统等功能两边都有。甚至用户可以通过“一条命令”把小龙虾里的所有数据搬到 Hermes 中，这说明它们在用户资产迁移和基础 Agent 功能上并非代际差距。真正让 Hermes 不同的，不是它多了某个单点功能，而是多了一个叫做「自主成长」的属性。所谓自主成长，视频将其拆成三个层面：自主记忆、自主建技能、自主反补训练。也就是说，Hermes 的重点不只是完成当前任务，而是把任务过程中的经验变成以后可复用的记忆、技能，乃至训练模型的数据。

### 2. Hermes 的自主记忆机制不是打断用户，而是在后台定期回顾对话

视频里最具体的第一个机制是「自主记忆」：Hermes 会在对话过程中自己停下来“想一想”，判断刚才这段对话或经历有没有值得记住的东西。它不是像一些简单产品那样，在主对话中插一句“要不要保存记忆”，而是每经过 **10 轮对话或 10 次工具调用**，给自己设定一个类似“闹钟”的回顾触发点。触发后，系统会在后台克隆出一个完整的智能体副本，再配上一段用于回顾的提示词，让这个副本判断用户是否暴露了偏好、预期，或者是否经历了反复试错才完成某个操作。如果没有值得沉淀的内容，它就结束；如果有，它可以调用 memory 工具保存记忆，也可以调用 skill manager 工具创建技能。这个设计的关键好处是：主对话上下文窗口不被占用，用户不被打扰，Agent 却能默默把知识和经验沉淀下来。

### 3. Hermes 的记忆判断更接近“工作总结”，而不是机械保存聊天记录

作者用了一个很形象的比喻：Hermes 像一个勤奋员工，白天在办公室里正常干活，晚上不占用工作时间，自己回去加班写工作总结。这个比喻说明，Hermes 的记忆并不是把所有聊天内容原封不动存起来，而是有选择地判断哪些信息值得记录。它会关注用户的偏好、预期、反复试错的操作路径，以及某些未来可能复用的经验。这样做的价值在于，记忆不再只是被动仓库，而是经过筛选和抽象后的经验沉淀。对长期使用 Agent 的用户来说，这种机制有可能让智能体逐渐适应个人工作流，而不是每次都从零开始。

### 4. Hermes 不只是会“使用技能”，还会在合适时机自主创建技能

视频第二个重点是「自主建技能」。作者指出，OpenClaw / 小龙虾也有一个叫 **skill creator** 的能力，但它本质上更像一份“写技能的操作指南”，教用户如何写 `skill.md` 文档、目录结构应该怎么组织。也就是说，小龙虾的技能创建通常需要用户明确提出：“我需要你帮我创建一个技能。”Hermes 的区别在于，它的后台 Agent 在回顾对话时，会主动判断刚才是否存在“经过反复试错、反复中途修改方案，最后才搞定”的任务。如果有，它就会自动在 skill 文件夹下生成一个完整技能目录，等下次遇到类似任务时自动匹配、自动加载。这里的核心逻辑是：一次复杂任务的解决过程，不应该只成为一次性的上下文消耗，而应该被抽象成可复用的能力模块。

### 5. Hermes 的技能系统形成了“自己写、自己用、自己改”的闭环

作者认为，Hermes 创建技能本身还不是最厉害的，更关键的是它的技能有自我修复、自我优化机制。视频提到 Hermes 在系统提示词里硬编码了一条指令，大意是：当它使用某个技能时，如果发现步骤过时，比如 API 版本变了、参数改了，就应该当场修复，不要等用户发现，也不要等用户主动要求。这一点把 Hermes 和传统技能系统区分开来：过去的技能系统更像执行者，只按照已有步骤执行；Hermes 则更像技能作者，能够写、用、改自己的技能。作者用“主人翁精神”来形容这种机制，强调它不只是执行用户命令，而是在维护自己的能力资产。最终形成的是一个持续修正技能、优化技能的闭环。

### 6. Hermes 也意识到自建技能的安全风险，因此引入 Skills Guard 做扫描和分级

自主创建技能虽然强大，但也会带来安全风险，比如数据外泄、提示词注入、破坏性命令等。视频说，Hermes 对这类问题也有设计：所有 Agent 自建技能都会通过一个叫 **Skills Guard** 的 Python 文件进行扫描。扫描内容包括是否存在数据泄露风险、提示词注入问题、破坏性命令等。系统还会把信任等级分成四档，其中 Agent 自建的技能属于 **agent created / agent creator** 这一档。若触发危险模式，Hermes 会暂停所有执行，并要求用户确认，这说明它并不是无条件让 Agent 自我改写和执行，而是试图在自主性和安全性之间加一层防护。

### 7. Hermes 最重要的野心不是让单个 Agent 变强，而是把 Agent 经验变成训练数据

视频第三部分被作者称为 Hermes 最重要的部分：训练模型。前面的记忆和技能机制，本质上都是为了让单个智能体在使用中变得更强；但 Hermes 更进一步，要把 Agent 的工作经验编成训练数据，用来训练更强的模型。作者认为，这可能才是 **NOS Research / Noise Research** 开发 Hermes 项目的根本目的。也就是说，Hermes 不只是一个面向终端用户的 Agent 产品，它还是一个收集、整理、压缩、训练 Agent 行为数据的研究管线。这个思路的转变很重要：Agent 不再只是大模型的下游消费者，也可以成为上游的数据供应商。

### 8. Hermes 的训练流程包括“批量刷经验、压缩数据、强化学习”三步

视频将 Hermes 的训练流程拆成三步。第一步叫“批量刷经验”：准备一批任务，可能是几百道编程题、应用题、搜索题等，然后同时开启上百个 Agent，让每个 Agent 完整执行任务，并记录解题过程、调用了什么工具、返回了什么结果、最终有没有解决。第二步是压缩训练数据，因为一条完整对话动辄几万到十几万 token，直接训练成本太高，所以保留开头和结尾，中间反复调试部分交给小模型压缩成几百 token。第三步是强化学习：例如给模型编程题，让它写代码、跑测试，通过就高分，不通过就低分；搜索任务答对给分，如果用多个搜索员交叉验证还可以加分，工具调用太复杂太多则扣分。通过大量打分反馈，模型会逐渐调优自己的策略。

### 9. Hermes 代表的是“群体经验进化模型”的路线，而不是单个 Agent 的养成

作者在视频中做了一个对比：过去两个月很多人在讨论“怎么养好一只小龙虾”，本质上是如何把一个 Agent 调教得更适合自己。而 Hermes 的路线更像是“用所有小龙虾的经验去进化一个新的物种”。这句话揭示了 Hermes 更深层的方向：它不是只让某一个用户的某一个智能体变聪明，而是试图收集大量 Agent 的工作轨迹，再把这些经验反馈给模型训练。这样产生的模型再反过来驱动更好的 Agent，形成“Agent 积累经验 → 经验变训练数据 → 训练出更强模型 → 更强模型驱动更好 Agent”的循环。这个闭环如果成立，Agent 系统就不仅是工具层创新，而可能成为模型迭代的数据飞轮。

### 10. Hermes 当前仍有明显短板，尤其是产品化和生态不如 OpenClaw

作者最后也没有把 Hermes 过度神化，而是明确指出：普通用户不必急着从小龙虾或各种 Claude / Cloud 工具切换过去。Hermes 骨子里仍然是研究项目、开源项目，商品化程度完全不如 OpenClaw。视频举了几个生态差异：小龙虾有 **macOS 原生客户端**、**WebUI**、**类型安全的插件 SDK**，还有 **40 多个大模型供应商**被封装成独立扩展，而这些是 Hermes 目前缺少的。对普通小白用户来说，如果缺少这些产品化能力，使用门槛会明显更高。作者自己的实际体验是，两者日常使用差不多，Hermes 在记忆上可能稍好一点，生态上不如小龙虾，但这种差异对普通个人用户感知并不大。

## 值得记住的点 / 行动建议

### 1. 判断 Agent 产品时，不要只看前台体验，要看有没有经验沉淀机制

视频最重要的提醒是：很多 Agent 产品表面体验相似，都会搜索、记忆、调用工具、执行技能，但底层是否能沉淀经验，决定了长期使用价值。对于普通用户来说，短期内 Hermes 和 OpenClaw 的日常体验可能“差不多”，甚至生态更成熟的 OpenClaw 更顺手。但如果你关注的是长期工作流自动化，就要看系统是否会把反复出现的问题抽象成记忆或技能。一个真正有成长性的 Agent，不应该每次都依赖上下文临时解决问题，而应该能从任务历史中提炼可复用资产。

### 2. 设计自己的智能体时，可以借鉴“后台回顾”而不是“前台打断”

Hermes 的自主记忆机制很值得开发者参考：它不是在对话中不断询问用户“是否保存记忆”，而是定期在后台运行一个回顾 Agent。这个设计降低了交互噪音，也避免主对话上下文被大量总结和判断占用。若自己搭建 Agent，可以设置类似触发条件，比如每 N 轮对话、每 N 次工具调用、每次任务完成后，运行一个独立总结器。总结器的职责不是保存全部内容，而是判断是否存在用户偏好、稳定约束、反复试错路径、成功解决方案等高价值信息。这样可以让记忆库更干净，也更接近真正的个人化系统。

### 3. 不要把技能系统做成静态说明书，而要让它能从失败和调试中生成

视频对 OpenClaw 的 skill creator 和 Hermes 的自主建技能做了鲜明对比。前者更像教用户怎么写技能，后者则能从已完成任务中自动抽象技能。对开发者来说，这意味着技能系统的重点不只是“如何执行一个固定流程”，而是如何识别“这个流程值得被固化”。例如，一个任务如果经历了多次错误、参数调整、工具替换、API 兼容处理，最终才成功，就很适合被沉淀为技能。因为这类经验最容易被遗忘，也最能在下次复用时节省成本。

### 4. 自建技能必须配套安全扫描，不能只追求自主性

Hermes 引入 Skills Guard 的意义在于提醒：Agent 自主写技能不是纯收益，它同时会扩大风险面。自建技能可能包含危险命令、无意的数据上传、恶意提示词注入，甚至在后续自动执行时造成破坏。因此，如果开发者给 Agent 开放写文件、执行脚本、调用 API 的权限，就必须有权限分级、静态扫描、危险操作确认等机制。尤其是 Agent 自己生成的技能，不应该默认拥有和人工审核技能一样的信任等级。视频里提到的“四档信任等级”和危险模式暂停执行，就是一种可借鉴的设计方向。

### 5. 对模型训练感兴趣的人，应重点关注“Agent 轨迹数据”而不只是最终答案

Hermes 的训练思路提示了一个关键方向：真正有价值的数据不只是题目和答案，而是 Agent 解决问题的完整轨迹。它包括任务如何被拆解、第一次调用了什么工具、中间遇到什么失败、如何调整方案、最后如何验证结果。这样的过程数据比单纯答案更能教模型“怎么做事”。不过原始轨迹通常非常长，视频中提到动辄几万到十几万 token，因此必须进行结构化压缩。保留开头、结尾和关键决策节点，压缩中间冗余调试过程，是一种兼顾成本和信息量的训练数据处理方式。

### 6. 普通用户不必急着迁移，除非你明确需要 Hermes 的研究型能力

作者明确说，已经在用小龙虾或其他 Claude / Cloud 类工具的用户，不必急着切换到 Hermes。原因很现实：Hermes 目前还不是高度商品化产品，生态短板明显，普通用户可能更在意客户端、WebUI、插件 SDK、大模型供应商扩展等成熟能力。OpenClaw 在这些方面更完整，尤其对非技术用户更友好。如果你只是日常写作、搜索、轻量自动化、调用工具，那么 Hermes 的底层优势未必会直接转化成明显体验提升。更适合尝试 Hermes 的人，是智能体开发者、研究者、关注 Agent 训练数据闭环的人，或者愿意折腾开源项目的人。

### 7. 关注 Hermes 的核心，不是“它是不是更聪明”，而是“它是不是打开了新数据飞轮”

视频最后的判断很重要：Hermes 真正值得关注的地方，不是它比小龙虾聪明一点，而是它提出了一条新路线。传统上，大模型先被训练好，然后 Agent 调用模型完成任务，Agent 是模型能力的下游使用者。Hermes 的思路是，Agent 在真实任务中的执行轨迹可以反过来成为训练数据，让模型变强，再让更强模型驱动更强 Agent。这就形成了类似飞轮的结构：执行越多，经验越多；经验越多，训练越好；模型越好，Agent 执行质量越高。对研究者来说，这比单个产品功能更有长期意义。

## 我的点评

这个视频的判断总体有道理，尤其是把 Hermes 的价值从“前台体验”转移到“经验沉淀与训练闭环”，这是一个更接近 Agent 系统长期演化的问题。它对自主记忆、自主建技能、自我修复、安全扫描、轨迹数据压缩和强化学习的拆解比较清楚，也能解释为什么 Hermes 被称为“会自主进化”。不过需要注意，视频主要基于作者对项目机制的理解和解读，部分名称如 Open Cloud / OpenClaw、NOS Research / Noise Research、pepperlite 等可能受语音识别影响，后续引用时最好再查项目原始文档确认。另一个需要保留的点是：自主生成技能和训练数据闭环听起来很强，但实际效果高度依赖评估质量、安全边界、数据清洗和任务分布，不是有了机制就一定能稳定进化。普通用户可以把它当作选型参考：重生态和稳定体验，OpenClaw 这类成熟工具可能更合适；重研究、自动化架构和 Agent 数据飞轮，Hermes 的思路更值得深入研究。
