## 一句话概括
真正想做成一件事，不要一开始就追求完美的方案、完整的系统和成熟的条件，而是先找到其中最简单、最小、能够立即执行的一步，马上动手，通过实际行动验证想法，再逐步完善。

## 背景与主题
这条视频围绕一个非常实用的行动原则展开：从简单处开始（Start with the simplest thing）。作者通过三个层次的故事来证明这个原则：首先讲 Netflix 和 Airbnb 两家公司的创业故事，说明成功的商业模式往往从一个极其简单的实验开始；其次讲述自己开发第一个商业软件项目、从零开始拍摄抖音视频的经历，说明自己也曾通过这种方式把想法变成现实；最后把这个方法落到普通人的日常生活中，例如打扫卫生、开始写作等。作者想传达的不是如何制定一份完美的计划，而是如何突破行动前的犹豫、准备和过度设计。整条视频最核心的主张是：不要等到一切准备好了才开始，而是先做最简单的那一步，让事情真正启动起来。

## 核心观点

### 1. 真正重要的不是一开始就设计完整方案，而是先找到最小的可执行动作
很多人想做一件事时，第一反应往往是思考整个事情应该如何完成，而不是立刻开始行动。
例如，想打扫房间的人，可能先考虑应该从哪里开始、需要准备什么工具、如何安排清洁顺序；想成为作家的人，可能先去买写作书籍、寻找写作课程、研究写作技巧。
这些准备本身并没有错，但问题在于：准备很容易变成行动的替代品。
作者强调，真正有效的做法是把宏大的目标缩小到一个可以立即执行的动作。打扫房间，不需要先研究完整的清洁方法，只需要拿起扫把，先扫一个角落；想写作，不需要先学习所有写作理论，只需要打开记事本，写下第一句话。
一个目标只有变成实际动作，才算真正开始。
因此，开始阶段最重要的不是方案有多完善，而是能否跨越从想法到行动的第一道门槛。

### 2. Netflix 的创业故事：一个 40 美元的罚款，最终变成了一个商业机会
作者首先讲述了 Netflix 创始人 Reed Hastings（里德·哈斯廷斯）的故事。
故事的起点非常普通：他曾经租过一盘录像带，内容是一部 Tom Hanks（汤姆·汉克斯）主演的电影，但归还时却找不到录像带了。因为无法按时归还，他最终被收取了 40 美元的费用。
这件事让他很不满意，于是他开始思考：
- 为什么租录像带会有这么麻烦的流程？
- 如果自己来做这个生意，有没有更好的方式？
- 能不能让用户不用亲自跑到实体店，就能获得想看的影视内容？

当时互联网已经出现，他预见到未来网络速度和带宽会不断提高，影视内容有可能直接通过互联网传输。但在当时，网络条件还不足以支持这种模式。
于是，他考虑用邮寄的方式解决内容交付问题：用户在线选择内容，商家通过邮政系统把光盘寄给用户。
但这又带来了很多新的问题：
- 光盘在邮寄过程中会不会损坏？
- 光盘是否适合通过普通邮政系统运输？
- 包装成本和邮寄成本是否合理？
- 用户收到光盘后，如果不归还怎么办？
- 这种配送方式能否形成稳定的商业模式？

面对这些问题，他没有先建立一个庞大的系统，也没有试图一次性解决所有问题，而是选择了一个极其简单的实验：先寄一张光盘给自己。
具体过程是：
**1. 买了一张二手 CD，考虑到测试过程中可能损坏，所以没有选择昂贵的光盘。**
**2. 他走到另一条街上的商店，买了一个包装。**
**3. 把 CD 放进包装里，贴上邮票。**
**4. 将这张 CD 寄给自己。**
**5. 第二天，他收到了自己寄出的 CD，而且光盘完好无损。**

这个实验看起来非常简单，甚至有点可笑，但它验证了一个关键假设：光盘可以通过邮政系统安全地寄送。
于是，一个原本还停留在脑海中的商业构想，终于获得了现实中的验证。
作者借此说明：Netflix 后续可以逐步完善物流、用户体验、产品和商业模式，但最初让它成为可能的，并不是一套完整的商业系统，而是一次简单的邮寄实验。
先验证最关键的事情能不能做，再考虑如何把它做得更好。

### 3. Airbnb 的创业故事：先拍一张照片、做一个简单网页，就能验证商业需求
第二个创业案例是 Airbnb（爱彼迎）。
作者讲述的故事是：当地曾经举办过一次设计大会，每次设计大会期间，附近的酒店都会住满，很多参会者找不到合适的住宿。
与此同时，城市里有很多人的公寓或房间是空着的。
于是，创业者产生了一个想法：
既然酒店已经没有空房，而很多普通人的家里又有空闲空间，能不能把这些空闲空间开放出来，让有住宿需求的人租住？
这个想法后来发展成了 Airbnb 的商业模式。
但创业者最初并没有先建立一个复杂的住宿预订平台，也没有一开始就解决所有问题，例如：
- 如何处理房东和房客之间的信任问题？
- 如何保证房屋质量？
- 如何处理付款？
- 如何解决住宿纠纷？
- 如何建立完整的房源管理和预订系统？

他们采取的方式非常简单：
**1. 找到一套可以出租的空置公寓。**
**2. 把房间腾出来，准备好住宿空间。**
**3. 给房间拍一张照片。**
**4. 制作几个非常简单的网页。**
**5. 把房间发布到网站上，告诉有需要的人可以租住。**

最终，他们收到了 3 个付费用户。
注意，这里最值得关注的是：最初只有几个简单网页和一套可以出租的房间，却已经有人愿意付钱。
这意味着他们不再只是凭空猜测市场需求，而是获得了真实用户的反馈和付费行为。
三个付费用户看起来不多，但对于一个刚刚起步的商业构想来说，意义非常大。
它证明了至少存在一群人，愿意为这种新的住宿方式付费。
作者想强调的是：创业最初不需要拥有一个成熟的平台，先让一个真实用户愿意使用、愿意付费，就已经是非常重要的进展。

### 4. 第一个商业软件项目：先让程序能够运行，界面和体验可以以后再完善
作者接下来讲述自己的经历。
他人生中的第一个商业项目，是开发一个数据迁移工具。
这种软件如果按照成熟产品的标准来设计，会涉及很多复杂的功能，例如：
- 图形化操作界面。
- 通过拖拽来建立数据映射关系。
- 把一个数据字段拖到另一个数据字段上。
- 双击字段或组件，进一步配置具体操作。
- 支持编写各种代码。
- 处理字段之间的转换、传输和映射关系。

如果一开始就按照这些要求开发，就意味着需要设计完整的交互系统、界面系统和底层程序逻辑。
但作者没有这样做。
他回忆说，自己最早完成的那个程序，实际上非常简陋，甚至只有他自己能看懂。
他没有考虑拖拽操作，没有考虑图形化界面，也没有考虑双击配置、代码编辑等复杂功能。
他采用了一种特殊的编码方式：
- 先把需要执行的数据迁移任务表示出来。
- 使用一些特殊符号，把不同的数据字段和操作内容分隔开。
- 通过这种特殊格式描述数据应该如何迁移。
- 最后让程序逐行读取这些指令并执行。

也就是说，原本需要用户通过图形界面完成的操作，他先用一套只有自己看得懂的特殊文本格式来表示。
这个版本虽然不够漂亮，也谈不上良好的用户体验，但它已经可以完成最核心的任务：执行数据迁移。
当这个程序真正运行起来、成功完成迁移时，作者就知道了一件非常重要的事：
OK，这个东西是可以做出来的。
接下来，所谓的 GUI（Graphical User Interface，图形用户界面）、拖拽交互、字段配置、代码编辑等功能，都可以在这个基础上逐步完善。
这里有一个非常值得注意的产品开发思路：
先让核心功能成立，再让产品体验变得优秀。
很多人容易把最终产品的完整形态，当成第一版产品必须达到的标准。但实际上，第一版只需要解决最核心的问题。

### 5. 拍摄抖音视频：没有灯光、收音设备和定位规划，也可以先发布第一条视频
作者还分享了自己开始拍摄抖音视频的经历。
他说，大家可以去看看他的第一条视频、第二条视频，就能发现当时的拍摄条件非常简单。
没有专业灯光设备，没有专业收音设备，也没有各种复杂的拍摄器材。
甚至没有一开始就认真考虑：
- 账号应该如何定位？
- 内容应该采用什么风格？
- 应该吸引什么样的用户？
- 视频应该怎样拍摄和剪辑？
- 如何建立长期的内容体系？
- 怎样才能让账号逐渐形成影响力？

他做的事情只有一件：拿起手机，开始拍摄。
先拍一条视频，先把内容发布出来。
至于账号定位、内容风格、拍摄质量以及其他需要完善的东西，都是在后面逐渐考虑和调整的。
作者借此强调，很多人想做自媒体，却容易陷入准备阶段：
- 先研究拍摄设备。
- 再研究灯光和收音。
- 再研究剪辑软件。
- 再研究账号定位。
- 再研究流量机制。
- 最后可能还没有发布过一条视频。

但作者的做法恰好相反：先拿手机拍，先让账号拥有第一条内容。
等真正开始拍摄之后，才有机会通过实际体验发现问题，并逐渐改善。
你不需要在发布第一条视频之前，就拥有一个成熟创作者的全部能力和装备。

### 6. 不要把准备工作误认为真正的行动
从 Netflix、Airbnb 到作者自己的软件项目和抖音账号，这些案例其实都在说明一个共同问题：人们经常会把准备工作当成行动本身。
例如：

| 想实现的目标 | 容易陷入的准备工作 | 真正应该做的第一步 |
| --- | --- | --- |
| 创办一家企业 | 反复研究商业模式、商业计划书 | 做一个最小实验，验证核心假设 |
| 开发一个软件 | 先设计完整界面和所有功能 | 写出一个能完成核心任务的程序 |
| 做自媒体 | 研究设备、定位、流量和剪辑 | 拿起手机，拍摄并发布第一条视频 |
| 成为作家 | 买书、报课、研究写作方法 | 打开记事本，写下第一句话 |
| 打扫房间 | 反复思考整理顺序和清洁方案 | 拿起扫把，先打扫一个角落 |

为什么准备工作容易让人停下来？
因为准备阶段往往会带来一种自己正在做事的感觉，但实际上，它不一定会产生任何真实成果。
研究如何写作，不等于写出了一篇文章；研究如何拍视频，不等于拍出了一条视频；研究如何创业，也不等于获得了一个真实用户。
作者实际上是在提醒大家区分两个概念：
- 思考和准备： 让自己知道应该做什么。
- 实际行动： 真正产生一个可以观察、检验和改进的结果。

准备当然有价值，但如果一直没有行动，准备就失去了意义。

### 7. 完成一个粗糙版本，比脑海中拥有一个完美方案更有价值
作者的几个案例还有一个共同特征：他们都允许第一版非常粗糙。
Netflix 的最初实验，只是寄一张 CD 给自己。
Airbnb 的最初尝试，只是把一个空置房间拍照，再通过几个简单网页寻找用户。
数据迁移软件的第一个版本，只有开发者本人能够看懂。
抖音账号的第一条视频，也没有专业设备和成熟的内容定位。
这些事情都有一个共同点：它们都没有试图在起点就达到最终产品的质量。
为什么这样做反而有效？
因为一个粗糙但能够运行的版本，可以产生真实反馈。
例如：
- 光盘寄出去之后，可以知道邮寄方式是否可行。
- 房间发布出去之后，可以知道是否有人愿意付钱。
- 数据迁移程序运行之后，可以知道核心逻辑是否正确。
- 视频发布出去之后，可以开始积累拍摄经验，观察用户反馈。

而一个只存在于脑海中的完美方案，虽然看起来很完整，却无法产生这些现实反馈。
因此，作者主张不要过早追求完整性。
在事情刚开始时，最重要的是建立一个能够工作的雏形，而不是追求最终形态。

### 8. 真正开始行动，会让事情进入一个新的发展阶段
作者最后把前面的故事落到了普通人的生活中，并且提出了一个非常直接的行动原则：
如果你想做一件事，现在就去做这件事最简单的那一步。
例如，你想打扫房间，真正应该做的第一件事不是坐在那里思考如何打扫，而是拿起扫把，先扫一个角落。
你想成为一名作家，真正应该做的第一件事不是去买写作书籍、参加写作课程、寻找老师，而是立刻关掉视频，找到记事本或手机备忘录，开始写字。
作者甚至给出了一个非常有趣的具体做法：
打开记事本，写下：
今天我看了一条视频，然后那个傻叉博主说，现在让我关掉视频，马上就开始写作。

这句话本身甚至可以成为你写作的第一句话。
它不需要有多么高的文学价值，也不需要有多么精妙的结构。
关键在于，你已经开始写了。
从这一刻起，你不再只是一个想成为作家的人，而是已经实际写下文字的人。
作者想传达的是：行动不只是完成目标的手段，它本身就是让目标从想象变成现实的起点。

| 作者建议 | 可以回看他的第一条、第二条视频，观察最初的状态 |

核心启示： 不必等设备齐全、定位清晰、拍摄技术成熟之后才开始创作。

### 五、普通人的生活案例
**1. 打扫卫生： 不要先思考整个房间应该如何打扫，而是拿起扫把，先扫一个角落。**
**2. 成为作家： 不要先买写作书籍或参加课程，而是马上打开记事本或手机备忘录，写下第一句话。**
**3. 立即行动： 如果想写作，现在就开始写；如果想打扫卫生，现在就开始打扫。**

## 值得记住的点 / 行动建议

### 9. 把一个宏大的目标，拆解成一个两分钟内就能开始的动作
当你想做一件事情，却迟迟没有行动时，不妨问自己：
如果我现在就要开始，最简单的一步是什么？
不要问怎样才能把整件事情做好，而要问怎样才能让这件事真正启动。
例如：

| 目标 | 可以立即执行的最小动作 |
| --- | --- |
| 写一本书 | 打开文档，写下一个标题和第一句话 |
| 学习英语 | 打开英语材料，读出第一段 |
| 开发软件 | 写一个最简单的程序，让核心功能运行一次 |
| 做自媒体 | 拿手机录制一段 30 秒的视频 |
| 创业 | 找到一个潜在用户，询问他是否有这个需求 |
| 打扫房间 | 拿起扫把，清理一个角落 |
| 健身 | 换上运动服，做一组简单的动作 |
| 学习编程 | 打开编辑器，写出并运行第一段代码 |

这个方法的重点不是要求你每件事只能花两分钟，而是让你不要因为整件事情太大，就连第一步都不愿意迈出去。

### 10. 先做一个能够运行的最小版本，不要一开始就追求完美
如果你正在做一个产品、软件、项目或商业计划，可以借鉴 Netflix 和作者开发数据迁移工具的思路。
先明确你的最终目标，再找出其中最核心的功能。
然后尝试做一个最小版本：
- 不需要漂亮的界面。
- 不需要完整的功能体系。
- 不需要自动化所有流程。
- 不需要一次性解决所有边缘问题。
- 不需要提前考虑所有未来可能发生的情况。

你只需要回答一个问题：
这个东西最核心的价值，能不能通过一个简单的版本实现？
例如，如果你想开发一个数据迁移软件，先不必做完整的拖拽界面，可以先用文本配置实现一次数据迁移。
如果你想做一个住宿预订平台，先不必开发复杂的预订系统，可以先通过一个简单网页发布一个房源，看看是否有人愿意预订。
如果你想做一个内容账号，先不必建立完整的内容生产体系，可以先发布几条视频，看看自己能否持续创作。

### 11. 优先验证最关键的假设，而不是同时解决所有问题
Netflix 的 CD 邮寄实验和 Airbnb 的三个付费用户，都体现了一个非常重要的思维方式：
不要同时解决十个问题，先解决那个决定整个事情能不能成立的问题。
例如：
- Netflix：光盘能不能通过邮政系统安全寄送？
- Airbnb：有没有人愿意为普通人的空置房间付钱？
- 数据迁移软件：程序能不能真正完成数据迁移？
- 抖音账号：自己能不能真正拍摄并发布视频？

这几个问题都比产品的完整程度更重要。
建议在开始一个项目之前，先写下三个问题：
**1. 这件事最核心的价值是什么？**
**2. 目前最大的未知因素是什么？**
**3. 我可以通过什么最简单、最便宜的实验验证它？**

把资源集中在验证关键假设上，可以避免在一个尚未证明可行的想法上投入过多时间和金钱。

### 12. 允许第一版很粗糙，把完善留给后续迭代
很多人迟迟不开始，是因为对第一版的要求太高。
他们希望第一次写作就写得很好，第一次拍视频就有专业水准，第一次开发软件就有成熟产品的体验。
但这恰恰容易成为行动的障碍。
可以给自己建立一个原则：
第一版只负责实现核心功能，第二版再考虑改善体验，第三版再考虑完善细节。
例如：
- 写作第一版：先把想表达的内容写出来，不急着修改每一句话。
- 视频第一版：先保证内容表达清楚，不急着追求专业灯光和剪辑。
- 软件第一版：先保证程序能够正确运行，不急着实现完整的 GUI。
- 商业项目第一版：先找到真实用户，不急着建立复杂的组织架构和管理体系。

这里要注意，粗糙不等于随意，更不等于忽视基本质量。
第一版应该在成本可控、风险可接受的前提下，尽可能快地验证核心价值。

### 13. 不要继续消费关于行动的知识，立即执行一个具体动作
这是整条视频最直接、也最值得实践的建议。
如果你正在观看一条关于写作的视频，那么看完之后，最好的结果不是再去找十条写作技巧，而是打开记事本写几句话。
如果你正在观看一条关于创业的视频，那么看完之后，最好的结果不是再收藏十篇创业经验，而是联系一个潜在用户，了解真实需求。
如果你正在观看一条关于健身的视频，那么看完之后，最好的结果不是继续研究训练计划，而是换上运动服，完成第一次训练。
可以采用一个非常简单的行动规则：
- 看完一条有启发的内容。
- 找出其中一个可以立即执行的建议。
- 不再继续搜索相关资料。
- 直接花几分钟完成第一步。
- 完成后，再决定下一步应该做什么。

作者甚至建议观众关掉视频，马上开始写作。
这实际上是一种非常有效的学习方式：把知识消费转化为实际产出。
看过多少内容并不重要，真正重要的是这些内容有没有改变你的行为。

## 我的点评
这条视频最有价值的地方，是把一个容易被忽视的行动规律讲得非常具体：很多事情的真正障碍并不是缺少知识，而是迟迟没有跨出第一步。Netflix 邮寄光盘、Airbnb 获得三个付费用户，以及作者开发简陋的数据迁移程序的故事，都很好地说明了最小化实验和快速验证的价值。尤其值得认同的是，作者没有把创业、开发软件和内容创作讲成复杂的方法论，而是强调先产生一个真实结果，再根据反馈不断改进。不过，也需要注意，简单开始不意味着可以完全不做规划，对于涉及资金投入、法律责任、人身安全和重大决策的事情，必要的风险评估仍然不可缺少；而且成功案例也不能证明所有简单实验都一定会成功。对普通人而言，最值得吸收的不是盲目追求速度，而是降低开始的门槛，减少无效准备，用小成本行动换取真实反馈，再通过持续迭代把一件事做好。
最后，可以把整条视频浓缩成一个值得长期实践的原则：
不要等到自己准备好才开始，而是先开始，然后在行动中逐渐变得更好。
