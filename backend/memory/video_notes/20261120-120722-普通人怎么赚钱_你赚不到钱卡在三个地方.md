# 普通人怎么赚钱 你赚不到钱，卡在三个地方。第一个不是能力，是羞耻。
很多人一谈钱就不好意思。这观念谁给你的？袁隆平先生每天只工作8小时，你工作16小时。假如他挣的比你多100倍，你觉得合理吗？应该合理——他解决的是上亿人吃饭的问题。所以只要你的钱是给别人创造了价值换来的，每一分都站得正。这不是可耻，这是光荣。
第二个卡点，是路径。两点之间直线最短。但大多数人一想到赚钱，第一反应是考证、攒资历，去排那条最长的队。学历是敲门砖：招聘的人没办法知道你有没有能力，才需要证书。可如果你已经被证明过了呢？你帮谁解决过问题、做过什么产品，就是证明。还非得排队吗？
赚钱这件事，你不需要自己种地。别人要吃饭，买现成的菜回来做就行。你也不需要从零造一个产品。两条路：你以前帮别人解决过问题，人家还很感激，那就把那个问题做成产品去卖；你还没做成过，那就拿市面上已经被证明、人们已经在买的东西，去做对接。眉山的橙子成本从6毛降到2毛，过了季节就烂在地里。你不用种，卖出去，农民有了销路，你也赚到钱。
第三个，怎么做大。我2003到2011年做软件公司。别人写需求说明书、架构设计、详细设计，我们不干：先跟用户聊，找出他最需要的功能，其他都不做，做个很简单的模型给他。他说这不对那不对，改；再给他，再改。最后验收，别人的项目经常不过，我们肯定过——因为验收之前，那东西已经在现场用了好几个月。验收不是评审，是确认。
现在拍视频也一样。我不带货也不做陪跑，卖的是专栏和书。我分享经验，大家在评论里问问题，我看出问题集中在哪，就调整方法再拍。所以我的视频有时候重复，但每次重复都是升级。理解再往前一步，我就写专栏；再有反馈，再改；最后写成书。上一本书印了18次。我没做过营销，人们会买，因为对他真有用。
真正决定学习速度的，不是你读了多少书、上了多少年学，是你多久拿到一次真实反馈，以及拿到之后改了什么。一周没人用你，你就是在自学。
今晚做一件：写下你帮别人解决过的一个问题，谁的问题，他怎么谢你的。那就是你的第一个产品。

## 背景与主题
这是一段围绕普通人如何赚钱、如何寻找赚钱机会，以及如何把一门生意逐步做大的经验分享。作者结合自己从2003年到2011年经营软件公司的经历，以及后来从事短视频创作、付费专栏和图书出版的实践，试图解释为什么有些人学习很多、努力很久，却始终无法真正开始赚钱。
作者认为，普通人的赚钱障碍主要来自三个方面：心理上认为赚钱不体面，行动上习惯沿着传统路径做漫长准备，经营上缺少快速反馈与持续迭代。
整段视频并没有重点讨论投资技巧、暴富机会或者某种具体的赚钱项目，而是从商业认知、价值交换、市场需求、产品验证和客户信任等角度，提出一套适用于个人创业、小生意和知识产品的基本方法。
作者的核心立场是：赚钱的起点不是拥有多少知识，而是能否发现需求、解决问题，并让市场愿意为解决方案付费；赚钱能力的成长，则取决于一个人能够多快地从市场获得反馈并持续改进。

## 核心观点

### 1. 普通人赚钱的第一道障碍，可能不是能力不足，而是对金钱的羞耻感
作者首先提出一个带有冲击性的判断：很多人一谈到赚钱，就会产生羞耻、不好意思，甚至觉得赚钱是一件不够体面的事。这种心理会让人不敢公开讨论价格、不敢主动销售、不敢为自己的服务收费，也不愿意承认自己想获得更多收入。作者观察到，当他分享赚钱经验时，有些人会立即质疑他是不是又想赚听众的钱，而不是先判断这些经验或服务究竟有没有价值。在作者看来，这反映出部分人把商业交易和欺骗、占便宜等负面行为混为一谈，导致还没有进入市场，就已经在心理上排斥了正常的商业活动。如果一个人无法正视金钱和交易，就很难主动建立稳定的收入来源，因为赚钱本身需要报价、销售、交换和收款。
这里真正值得关注的，并不是作者对质疑者的尖锐态度，而是他指出的一个现实问题：许多人愿意付出劳动，却不习惯向别人明确表达自己的劳动价值，更不擅长要求合理报酬。

### 2. 赚钱是否正当，关键在于价值创造，而不是收入金额的高低
为了打破赚钱羞耻感，作者以袁隆平先生作为一个假设性例子：假如袁隆平每天工作8小时，而一个普通人每天工作16小时甚至24小时，那么袁隆平获得更高的收入是否合理？作者进一步追问，如果袁隆平的收入是普通人的10倍、100倍，大家是否仍然认为合理，而他的预设答案是肯定的。这个例子想说明，社会价值与收入不应该简单按照工作时长来衡量，因为不同的人解决的问题、影响的人群以及创造的成果存在巨大差异。袁隆平通过农业科研对粮食生产和社会发展作出重要贡献，因此作者认为，即便他获得远高于普通人的报酬，也不应被认为可耻。由此引出的商业原则是：不要只问自己投入了多少时间，还应该问自己为别人解决了多重要的问题、创造了多大的价值。
需要注意，作者在这里使用的是价值判断和假设性收入对比，并没有提供袁隆平的实际收入数据；同时，社会贡献和市场收入之间也不总是严格成正比。

### 3. 学历、证书和系统学习只是证明能力的一种方式，不一定是赚钱的必经路径
作者认为，许多人一想到赚钱，首先想到的就是考证、提升学历、参加课程、学习新的方法论，仿佛必须完成一整套准备流程，才有资格进入市场。他以私营企业招聘市场岗位为例，假设一位传媒大学的博士毕业生与他本人竞争同一个岗位，企业未必一定选择学历更高的人，因为作者认为自己已经拥有相关项目和商业成果。学历和证书之所以重要，是因为企业面对大量陌生求职者时，无法直接判断每个人的真实能力，需要借助学历、证书等信号降低筛选成本。但如果一个人已经通过真实项目、业绩或者作品证明自己能够解决企业的问题，那么在某些岗位和场景中，实际成果可能比学历更有说服力。作者要反对的并不是学习本身，而是将学习和获得资格当成无限延迟行动的理由。
这一观点尤其适用于销售、营销、内容创作、设计和部分项目型服务等重视实际结果的领域，但并不能推导出学历、资质对所有职业都不重要。

### 4. 赚钱要寻找最短路径，而不是机械模仿大多数人的成长路线
作者用“两点之间直线最短”的数学常识，解释自己提倡的商业思维：明确目标以后，应当首先寻找达到目标所需的最直接、最有效的方法，而不是自动沿用别人习惯走的路线。他还使用了“大门”和“角门”的比喻：大多数人都排队从同一个大门进入，实际上也许存在另一条合法、正常但很少被注意到的入口。对应到赚钱，传统路径可能是先学习几年、获得证书、积累资历，再尝试开展业务，而更直接的路径可能是先发现一个具体需求，然后提供现成的解决方案。作者指出，很多人之所以坚持漫长准备，是因为害怕失败，希望通过不断学习获得安全感，但市场是否愿意付费，最终仍然需要通过实际行动验证。因此，赚钱思维应该从“别人通常怎么做”转向“要解决这个问题，最少需要完成哪些关键步骤”。
这里的“最短”并不意味着可以跳过法律规定、专业资质或必要的质量控制，而是强调减少与客户价值无关的准备和重复劳动。

### 5. 不一定要自己生产产品，销售和整合现有资源也能够创造商业价值
作者反复使用做饭和种地的例子说明，满足用户需求与亲自完成所有生产环节，是两件完全不同的事情。如果顾客需要吃饭，经营者不必自己种植粮食和蔬菜，而是可以购买已经生产出来的食材，通过加工、搭配和服务满足顾客需求。作者认为，这种逻辑同样适用于更广泛的商业活动：如果市场已经存在能够解决某个问题的成熟产品，普通人完全可以先负责寻找客户、完成销售和对接，而不是从零开始研发。真正有价值的环节可能是发现需求、降低选择成本、提供便利、解决信息不对称，或者把分散的资源组织成客户更容易购买的服务。因此，普通人进入商业市场时，可以优先考虑已经被验证存在需求的产品，而不是一开始就追求原创产品、完整品牌和复杂的商业系统。
这种模式的核心不是简单赚取差价，而是通过渠道、服务、匹配效率和客户体验提供额外价值。

### 6. 农产品销售案例说明：需求匹配和销售渠道本身就能够产生价值
作者分享了近期前往“梅山”（地名为语音识别结果，待核实）的经历，提到一些同行者帮助当地农民销售豆子、橙子等农产品。按照他的讲述，橙子的成本曾从六毛钱降到四毛钱，后来又降到两毛钱，但视频没有明确这些数字对应的是每斤、每个还是其他计价单位。价格不断降低的背景是农产品销售具有季节性，如果错过销售窗口，农民可能面临商品卖不出去的问题。作者认为，这个时候帮助农民找到消费者，让更多人买到需要的水果，本身就是一种可以创造价值的商业活动，而且不需要销售者亲自去种植橙子。这个案例说明，有些商业机会并不来自创造新产品，而是来自解决现有产品的流通困难，将已经存在的供给与尚未被满足的需求连接起来。
进一步理解，这种生意的真实价值可能体现在客户开发、运输组织、库存处理、商品筛选和交付效率上，而不只是低价进货、高价卖出。

### 7. 做产品不要一开始追求完美，而要尽早交给用户使用、根据反馈不断修改
作者结合2003年至2011年经营软件公司的经历，介绍了自己早期做项目的方法。传统软件项目通常需要先完成需求规格说明书、架构设计说明书、详细设计说明书，再进入编码和后续实施阶段，但作者在实践中更关注用户真正需要的核心功能。他会先和客户沟通，找到最重要的需求，做出一个简单的初始模型，然后让客户实际体验，指出不合理之处，再根据反馈进行修改。经过多轮“使用—反馈—修改”，软件会逐步贴近真实业务，有些项目在正式验收之前，客户就已经使用了几个月，因此最终验收相对顺利。这个案例的本质，是用真实使用过程代替单纯依靠前期预测，让用户在产品形成过程中不断参与，从而减少开发出无用功能的风险。
这种思路与精益创业中的最小可行产品（MVP）、快速原型和迭代开发有相通之处，不过作者强调的是自己的实际项目经验，而非正式介绍这些理论。

### 8. 从免费短视频到付费专栏、图书出版，本质是同一套知识产品的持续升级
作者把自己现在的内容业务，与早年开发软件的经历联系起来，认为两者背后使用的是同一套工作方法。他首先在短视频中分享开公司、自媒体、投资、产品开发、营销、小生意和赚钱等经验，随后观察观众提出哪些问题，以及哪些问题反复出现。对于高频问题，他会重新思考原来的经验是否适用于不同的人，再根据反馈调整解决方案，拍摄新的短视频，因此有些视频虽然讨论相同主题，但实际上是对旧方法的升级。当某一问题经过足够多轮验证和完善之后，他会把内容整理成收费专栏，继续收集付费用户反馈，再逐步深化为图书；作者提到，自己此前出版的一本书已经印刷了18次。这展示了一条从公开分享、市场反馈、方法优化、知识产品化，到扩大产品形态的商业路径。
值得注意，18次印刷说明作品存在持续出版或补印行为，但不能仅凭这一数字判断具体销量、版税收入或利润。

### 9. 真正让生意做大做强的，是快速获取反馈、持续迭代和长期积累信任
作者把赚钱方法的第三部分总结为“反馈与改进”，并认为学习速度不应该只用读了多少本书、上了多少年学来衡量。他在软件业务中通过不断让客户使用、修改产品，提高产品与真实需求的匹配程度，从而获得客户信任，并进一步取得数量更多、规模更大的项目。在内容业务中，他通过短视频发现问题，通过付费专栏验证方法，再通过持续积累形成图书产品，实际上仍在重复这一过程。作者认为，用户持续购买产品的根本原因，是产品对他们确实有用，而真实价值又能够带来重复购买、信任积累和更多商业机会。因此，商业能力不是一次学习就获得的固定技能，而是在与真实客户不断接触、解决问题、获取反馈、改进方案的过程中逐步形成的。
不过，产品有用只是商业成功的重要条件之一，能否被客户发现、是否具有合理价格、能否稳定交付，以及成本能否得到控制，同样会决定生意能否持续扩大。

### 四、软件创业案例的完整过程
作者在视频中介绍的软件开发流程可以整理为：
**1. 与客户沟通：了解实际业务场景和客户想解决的问题。**
**2. 筛选核心需求：优先识别最重要、最急需的功能，而非一次完成全部需求。**
**3. 制作简单模型：快速开发可演示、可试用的初始版本。**
**4. 交给客户使用：通过真实使用发现需求理解偏差和功能问题。**
**5. 反复收集反馈：客户提出问题，开发团队调整，再次交付测试。**
**6. 持续现场使用：软件在验收前已投入客户的实际业务场景。**
**7. 完成正式验收：由于已经反复优化，正式验收相对顺利。**
**8. 积累信任与新项目：客户逐渐愿意交付更多、规模更大的软件项目。**

这个过程的关键不是简单缩短开发周期，而是尽早发现错误、提高客户参与度，把产品的正确性建立在真实使用证据之上。

### 五、知识产品商业化的具体链条
作者提到的内容业务涉及：
- 短视频：公开分享经验、观察观众反应、识别高频需求。
- 针对性答疑：根据不同用户的现实情况，对原有经验进行调整。
- 重复主题的视频更新：针对同一个问题提出更加成熟的解法，不只是追求新选题。
- 收费专栏：当某个主题逐步形成完整方法后，整理为付费知识产品。
- 图书出版：在经验、方法和反馈积累到一定程度后，形成更系统的作品。
- 持续反馈：即使已经进入付费阶段，仍继续改进内容及解决方案。

涉及的具体话题包括开公司、自媒体、投资、产品、营销、小生意和赚钱方法等。
这一链条可以概括为：
免费内容获取需求信息 → 重复验证与优化 → 形成付费解决方案 → 持续改进 → 沉淀为更系统的产品。

### 六、视频中的重要概念

| 概念 | 在视频中的具体含义 |
| --- | --- |
| 金钱羞耻感 | 将谈钱、报价、销售或赚钱与不体面联系起来的心理障碍 |
| 价值创造 | 通过产品、劳动或服务解决他人的实际问题 |
| 最短路径 | 减少不必要的准备环节，直接寻找可以验证需求和创造收入的方法 |
| 敲门砖 | 学历、证书等用来证明能力、帮助筛选人才的信号 |
| 现成产品销售 | 不必自己生产，通过销售、服务和资源对接创造价值 |
| 用户反馈 | 客户在购买、使用过程中提出的问题、意见和需求 |
| 迭代 | 根据反馈不断修改产品、服务或解决方案 |
| 客户信任 | 通过反复有效交付形成的稳定商业关系 |
| 知识产品化 | 把实践经验和解决问题的方法整理为可以销售的专栏、书籍等产品 |

## 金句摘录
以下摘录保留原文的核心表达，仅对部分口语重复和明显的语音识别错误作轻微整理。
“只要你能给这个社会、给他人创造价值，那你挣的每一分钱都站得正、立得直。”

这句话对应作者对赚钱正当性的解释：收入不应该仅仅因为金额较高就受到道德否定，而应该看其获取方式与实际价值。
“不是别人怎么走，我就怎么走，而是想一想这件事情有没有最短路径。”

这是整个视频中最值得记住的商业思维之一，强调不能把大多数人的习惯路径等同于唯一可行的路径。
“你不需要自己去种田的，你就直接买现成的菜回来，做给人家用户就可以了。”

作者通过做饭与种田的对比，指出生产环节和满足需求是不同的事情，销售、加工、组合和服务同样可能创造价值。
“我每次重复实际上是升级，是方法的升级，是对这个问题的理解的升级。”

这句话解释了作者为什么反复制作相同主题的视频：真正的内容迭代不一定要不断换话题，也可以针对同一个问题不断改善答案。
“真正的学习速度，并不取决于你看了多少本书，你上了多少年学，而取决于你的获取反馈的速度，以及你如何去更好地复盘，然后迭代和改进。”

这是视频关于学习和商业成长最重要的论断，强调实践反馈对提升实际能力的作用。
“当你的东西对别人真的有用的时候，真的有用的东西，人们就会购买，而且你会把这个事情做得越来越大。”

这句话反映了作者的价值导向：产品必须真正帮助用户，而不能只靠宣传或包装。不过现实中，有价值的产品还需要合理的定价、渠道和交付能力，才能持续获得购买。

## 值得记住的点 / 行动建议
以下将视频中的方法整理为可以实际执行的步骤，并在必要处补充商业验证和风险控制方法。

### 1. 改变赚钱观念：从“我敢不敢收费”转变为“我是否真的解决了问题”
很多人不敢收钱，不完全是因为产品没有价值，而是因为不习惯向别人提出交易。可以尝试把收费理解为一次明确的价值交换：客户有问题，你提供解决方案，双方自愿接受约定的价格，交易就有其商业基础。
实际行动时，可以先回答三个问题：客户具体遇到了什么困难？我提供的服务能够为他节省多少时间、成本或麻烦？如果没有我的服务，他需要付出什么代价？
例如，一个人帮助小商家整理产品图片、优化商品介绍、制作宣传素材，不应该只从“自己花了几个小时”来理解服务价值，也要看这些工作是否替商家解决了原本需要投入精力和预算的问题。
但要注意，不能因为自认为有价值，就认定客户必须接受报价。合理收费需要真实交付、透明价格和客户自愿，而不是单方面宣称自己的价值。

### 2. 从自己已经解决过的问题中，挖掘第一个可以收费的产品
作者提出，如果一个人曾经帮助别人解决某个问题，并获得对方认可，那么这个解决过程就值得被重新审视。
具体可以整理过去半年或一年中自己帮助别人完成过的事情，例如制作表格、整理资料、设计图片、搭建网站、解决软件问题、策划活动、编写文案或者完成某项流程。重点寻找那些重复出现、别人不擅长处理、又能明确判断最终结果的问题。
随后将原本随意提供的帮助，整理为标准化服务：

| 需要明确的内容 | 示例：商品详情页优化服务 |
| --- | --- |
| 客户是谁 | 有商品但缺乏设计和文案能力的小商家 |
| 具体问题 | 商品卖点不清晰，展示素材不够专业 |
| 提供什么 | 商品文案、卖点提炼、详情页排版 |
| 交付结果 | 一套可以直接使用的商品展示素材 |
| 服务范围 | 明确图片数量、修改次数、交付格式 |
| 怎么收费 | 根据工作量、交付标准和市场价格报价 |
| 如何验证 | 让首批客户试用，收集反馈和满意度 |

最重要的是，把抽象的“我会做设计、会写文案”，转变成清楚的“我能帮哪类客户解决哪种问题”。

### 3. 没有独特技能时，可以先从销售成熟产品和资源对接开始
作者认为，如果一个人暂时没有成熟的产品或者特别突出的专业能力，可以考虑直接销售市场上已经存在的商品或服务。
第一步是寻找有稳定需求的商品，而不是寻找自己觉得很新奇的东西。第二步是了解可靠供应商的价格、质量、供货能力、售后条件以及销售授权；第三步是找到对这些商品有真实需求的客户，测试自己能否建立有效的销售渠道。
例如农产品案例所体现的机会，就是帮助生产者接触消费者，从而改善销售效率。但实际经营时还应考虑生鲜损耗、运输成本、食品质量、退换货以及库存积压等问题。
销售现成产品并不等于没有门槛，只是把主要难点从生产研发转移到了渠道建设、客户获取、交付和服务上。

### 4. 不要为了准备而准备，给每一次学习设定明确的商业目标
作者提醒，很多人不断学习、考证、购买课程，并不一定是缺少知识，也可能是在回避真正进入市场的风险。
一个比较有效的调整方式，是在每次学习前先明确它要解决的实际问题。例如，不是笼统地说“我要学习营销”，而是明确“我要学会写出能够让目标客户理解产品价值的介绍文案”；不是泛泛地说“我要学习网站开发”，而是明确“我要在有限时间内做出一个可以让客户提交需求的页面”。
可以用以下判断标准筛选学习任务：这项知识是否直接影响接下来要完成的业务？如果现在不学，是否真的无法启动？有没有更简单的方法达到同样结果？
对于不影响当前验证的知识，可以暂时延后；对于专业资质、安全、法律等必要前提，则不能省略。
这套方法的目标不是反对学习，而是建立**“任务驱动学习—立即应用—获得反馈”**的节奏。

### 5. 做产品时先找到最关键的需求，再开发最小可用版本
作者的软件创业经历说明，真正重要的不是一开始拥有多少功能，而是先解决客户最迫切的问题。
例如，准备做一个面向商家的管理工具，不一定要从客户管理、库存管理、财务分析、报表导出、会员体系等全部功能同时开始。可以先找到用户目前最影响效率的一项工作，设计一个足以解决这个问题的简单版本。
接下来，让真实用户使用，而不是只给朋友看界面是否漂亮。重点观察他们是否能够完成任务、哪里容易出错、哪些功能没人用、哪些问题反复出现。
如果客户反馈某个功能毫无必要，应当考虑删除；如果客户不断要求某种核心能力，则说明可能需要调整开发优先级。
第一版的主要任务不是证明自己多么优秀，而是尽早发现产品与真实需求之间的差距。

### 6. 建立稳定的反馈机制，不要只凭自己的判断改产品
作者不断强调“反馈、调整、反馈、再调整”，但普通人实际操作时，最好把这个过程形成固定的记录和复盘机制。
可以建立一张简单的用户反馈表，每次与客户交流后记录以下信息：

| 记录项目 | 应当记录的内容 |
| --- | --- |
| 用户类型 | 客户所属行业、实际使用场景 |
| 原始需求 | 客户最初希望解决什么问题 |
| 实际行为 | 客户购买、使用或放弃了什么 |
| 反馈内容 | 客户明确提出的困难和不满 |
| 问题频次 | 同类问题出现过多少次 |
| 改进措施 | 准备怎样调整产品或服务 |
| 验证结果 | 调整以后是否真正改善了体验 |
| 商业结果 | 是否提升成交、复购、满意度或效率 |

建议每周固定一次复盘，把用户意见分成高频且影响较大、低频但影响严重、个别偏好等不同类型。
不要把所有意见都当成产品必须增加的新功能，更重要的是判断哪些反馈反映了真实、普遍且有付费可能的需求。

### 7. 把重复出现的问题，逐步变成能够反复销售的标准化产品
作者从短视频到收费专栏，再到图书出版的经历，提供了一条值得借鉴的知识产品化路径。
如果你经常为不同客户解答同一类问题，就应该考虑是否能够把解决过程沉淀下来。例如，多次帮助客户制作相似的文案，可以逐渐整理出标准化的需求问卷、文案模板、修改规范和交付流程。
如果提供的是咨询类服务，可以先积累真实案例和共性问题，再形成一套可以重复使用的方法，最终发展为咨询服务包、培训材料、教程或者知识产品。
这种方式的好处是，前期通过实践获得经验，后期通过标准化降低重复劳动，让相同的知识和能力能够服务更多客户。
不过，产品化之前必须确认客户愿意付费，而不是仅仅因为有人提问，就认定该问题存在足够大的付费市场。

### 8. 做大生意之前，先证明自己能够稳定交付结果
作者在软件公司经营中的一个重要经验，是因为产品在正式验收前就已经获得较长时间的实际使用，客户对交付能力形成了信任，后来愿意把更多项目交给他。
对普通人而言，初期不一定需要大量客户。先找到少数真实客户，把需求沟通、报价、交付、修改和售后做完整，通常更容易积累可信的服务案例。
当一套服务已经可以稳定完成，再考虑增加客户数量、提高订单金额、发展合作渠道或者拓展服务范围。
如果客户数量增加后，交付质量迅速下降，反而可能损害此前建立的信任。
因此，做大生意的合理顺序应该是：验证需求 → 做好交付 → 形成可复制流程 → 积累口碑 → 扩大规模。

### 9. 把“学习速度”改为“完成有效商业反馈的速度”
作者最有价值的一点，是重新定义了学习效果：不是只看掌握了多少理论，而是看能否利用反馈不断改进实际结果。
可以为自己设定一个简单的执行周期，例如以30天为一轮，完成一次小规模的商业验证：
30天商业验证行动表
这是根据视频方法整理的实践示例，并非作者给出的原定时间安排。
**1. 第1—5天：发现需求**
选定一类客户，与至少5位潜在用户交流，了解他们正在为什么问题付出时间或金钱。
**2. 第6—10天：确定方案**
从问题中选择一个需求明确、自己具备交付能力的方向，设计一个简单的产品或服务。
**3. 第11—15天：测试销售**
向目标客户介绍具体交付内容、价格和服务边界，观察是否有人愿意真实付费。
**4. 第16—23天：交付并收集反馈**
完成首批订单，记录客户满意之处、实际困难、成本消耗和需要改进的环节。
**5. 第24—30天：复盘与调整**
分析是否存在稳定需求、毛利是否合理、客户是否愿意推荐，再决定扩大、调整或停止。

30天结束后，真正值得统计的不是自己看了多少篇文章、购买了多少门课程，而是完成了多少次有效客户沟通、是否获得真实订单、交付是否成功，以及下一轮应该如何改进。

### 10. 用商业指标判断是否真的在成长，而不是只看忙碌程度
作者强调通过反馈让生意做大，但如果希望方法更可操作，还需要建立基本的商业衡量标准。
对于销售商品的人，可以重点观察订单数、成交转化率、每单毛利、退货率和重复购买情况；对于提供服务的人，可以观察有效咨询数、成交率、交付耗时、客户满意度和老客户推荐比例。
例如，一项服务收入500元，直接费用100元，另外需要投入10小时，那么在计算自己的实际收益时，不能只看到400元的差额，还需要考虑时间成本、税费、获客成本以及售后风险。
同样，一项产品即使能够获得许多咨询，如果没有真实成交，也不能直接判定为市场验证成功。
学习和迭代必须最终体现在更好的客户结果以及更健康的商业数据上，而不能仅仅停留在自己感觉有所进步。

## 我的点评
这段视频最值得认同的地方，是把赚钱从抽象的欲望转化为一个可以实践的商业过程：发现问题、提供价值、验证付费、收集反馈、持续优化，而不是把赚钱能力神秘化。作者反对过度准备、强调尽早接触真实客户，这一点对个人创业者、小生意经营者和知识服务提供者尤其有启发性，也与精益创业、客户开发和迭代式产品管理的基本理念相吻合。
但视频也有明显的简化：能创造价值，不等于一定能获得与价值相对应的收入，因为市场竞争、支付能力、渠道控制、议价权和资源条件都会影响最终收益；同样，“最短路径”也不意味着学历、专业能力和长期积累可以随意省略，某些领域的资质和基础能力本身就是必要条件。作者说“只要产品真的有用，人们就会购买”，这一判断作为价值导向有意义，但作为商业规律并不充分，因为产品能否被发现、价格是否合适、交付是否可靠，都会影响成交。
对普通人而言，最适合借鉴的不是盲目追求快速赚钱，而是以较低成本完成一次真实的需求验证，然后不断改进，逐渐建立可以被市场认可的能力与产品。
进一步提炼，这段视频可以形成一个值得长期使用的商业判断公式：
从需求到收入的商业闭环

客户是否愿意购买，收入能否覆盖成本？

根据视频观点补充整理的商业模型；能否形成持续盈利仍需检验。
整个视频最值得记住的不是“赚钱其实很简单”，而是另一个更有实践价值的道理：
不要一直停留在准备赚钱的阶段。先找到一个真实的问题，尝试提供一个别人愿意付费的解决方案，再让每一次交付和反馈帮助自己变得更好。
