中文标题：用 Codex + HyperFrames 搞定你的口播剪辑

一句话概括

这期视频讲的是如何用 Codex / Claude Code 这类 AI Agent + HyperFrames，把口播视频从设计资产、字幕脚本、分镜故事版到最终 MP4 渲染，做成一套工程化、自动化、可复用的 AI 剪辑工作流。

背景与主题

作者前面做过一期 Codex + Remotion 实战，帮助很多人入门用 Agent 制作高级感动画视频，据他说那期内容已经有 80 万人看过。这一期则转向一个更适合口播剪辑的新工具：HyperFrames，作者称它是“口播剪辑机最严厉的父亲”。视频的核心问题是：HyperFrames 到底是什么？它如何配合 Codex / Claude Code 这类 Agent，一句话生成科技感视频？又如何进一步服务完整的口播剪辑流程？作者从一个“Codex 安装指南”的测试案例讲起，再扩展到更完整的口播剪辑生产链路：设计原型、Design.md、SRT 字幕、storyboard.md、HyperFrames 代码和最终渲染。

核心观点
1. HyperFrames 是一个用 HTML / CSS / JS 构建视频的开源框架

作者首先解释，HyperFrames 是一个开源框架，可以让你用构建 HTML 网页的方式来构建视频。这意味着理论上只要是 HTML、CSS、JavaScript 能实现的视觉效果，都可以用 HyperFrames 渲染成视频。相比传统剪辑软件，它更像是把视频制作变成一个前端工程：页面布局、动效、配色、文字、图层都可以通过代码生成。这个特点非常适合 AI Agent，因为大模型本来就擅长生成、修改和组织结构化代码。也正因为如此，作者说 HyperFrames 从设计之初就是“专为 Agent 打造”的：内容由 HTML 构建，大多数大模型都能比较轻松地“驾驶”它。

2. Codex + HyperFrames 可以做到“一句话出片”，但背后其实是工程化流程

作者用一个简单案例测试 HyperFrames 是否能一句话出片。他直接在 Codex 里输入提示词：“请使用 HyperFrames 创建一个 Codex 安装指南，要求 1920×1080，包含参考图配色的科技感视频。” 然后 Agent 开始自动执行任务。表面看是“一句话生成视频”，但作者拆解后指出，背后并不是随便生成一个网页然后录屏，而是 HyperFrames Skill 中内置了一套明确的工作流要求。Agent 会先确认制作规范，再联网搜索资料、检查环境、初始化项目、建立视觉风格，最后编码并渲染。这说明真正可靠的 AI 视频生产，不是单条提示词魔法，而是“自然语言指令 + 标准化工作流 + 工程化约束”的结果。

3. Agent 会先联网查资料，确保视频内容不是凭空编造

在第一个案例中，视频主题是 Codex CLI 安装指南，所以 Agent 并没有直接编一个安装流程，而是先进行联网搜索，读取 Codex 官方文档，确认当前视频里需要展示哪些安装步骤。这个动作很关键，因为教程类视频最怕内容错、步骤旧、命令过时。作者强调，Agent 在生成视频前会先理解任务内容，这使得视频不仅有视觉效果，也有信息准确性。对于 AI 视频工作流来说，内容来源和视觉制作同样重要。尤其是技术教程、安装指南、工具使用类视频，最好让 Agent 先查官方文档，再进入脚本和画面生成阶段。

4. HyperFrames 渲染依赖 Node.js、FFmpeg、Chrome 等基础环境，但 Agent 可以辅助补齐

作者介绍，HyperFrames 的渲染过程需要一些基础依赖，包括 Node.js、FFmpeg、Chrome 等。如果本地没有安装过这些依赖，普通用户可能会被环境配置卡住。过去这种门槛会让不会编程的人直接放弃，因为看到项目目录、命令行、依赖安装、渲染脚本会很头疼。但现在有了 Codex / Claude Code 这类 Agent，它会先做环境检查，根据检查结果继续帮你完善环境。也就是说，Agent 不只是写代码，还承担了“工程助理”的角色：检查依赖、初始化项目、处理目录、运行命令、调试渲染。作者想传达的是：HyperFrames 虽然是代码化视频框架，但普通创作者可以通过自然语言把复杂编码细节交给 Agent。

5. Design.md 是 HyperFrames 工作流里的视觉风格说明书

在第一个案例中，Agent 会新建一个 Design.md 文件。作者后面解释，Design.md 本质上是一份“给 AI Agent 看的设计说明书”，它用于描述视频的视觉风格、配色、布局、组件、氛围和设计规则。HyperFrames 会在项目根目录中优先寻找这个文件，并把它作为当前视频制作的视觉风格依据。作者还提到，Design.md 的文档标准由 Google Stitch 开放，并正在逐步成为 Agent 时代的设计入口。这个点非常重要：在 Agent 工作流里，设计不只是给人看的图，而要转化成 AI 可读取、可执行、可复用的规范文件。Design.md 就像视觉风格的“宪法”，后续所有镜头、组件和动画都围绕它展开。

6. 口播剪辑不能只靠视频框架，还要先准备设计资产

作者说，如果只是让 Codex + HyperFrames 做一个简单演示，它生成的东西可能更像 PPT 风格的视频；如果想让口播视频更高级，就需要先处理设计环境。由于 HyperFrames 是用 HTML 构建视频，所以可以像设计网页一样，先确定整个视频的视觉风格。作者推荐了两个设计工具：如果习惯使用 Claude，可以直接用 Claude Design 来设计网页原型；如果觉得 Claude Design 成本太高，也可以尝试开源平替 Open Design。在 Open Design 中选择“原型设计”，把提示词和参考图投喂进去，Agent 就能自动设计网页原型。最后把这些设计资产导入 HyperFrames 项目根目录，后续视频就可以沿用这个视觉系统。

7. 口播脚本最好不是普通文案，而是带时间轴的 SRT 字幕

作者强调，对于口播视频来说，脚本最好不只是普通文案，而应带有清晰的时间轴。这里他常用的是 OpenAI Ambassador，用于把口播音频转换成带时间轴的 SRT 字幕文件。有了 SRT 文件，Agent 就能知道整期节目到底讲了什么，以及每句话出现在第几秒。这个信息对口播剪辑非常关键，因为画面、字幕、图标、动效、转场、强调词都要跟口播节奏同步。普通文案只能告诉 Agent “讲了什么”，SRT 才能告诉 Agent “什么时候讲”。所以口播剪辑的自动化前提，是把音频内容转成可计算、可定位、可对齐的时间轴文本。

8. storyboard.md 是给 HyperFrames 的视频制作详细说明书

设计资产和 SRT 脚本准备好后，作者会创建 storyboard.md 分镜故事版文件。他说自己经过“一整天的打磨”，把能稳定生成分镜视频的经验整理成了一个专门的 Skill。这个 Skill 会自动搜索项目根目录下的设计资产和文案脚本，然后生成 storyboard.md。这个文件里包含视频规格、设计摘要、分镜节奏、画面布局，以及每个镜头需要呈现什么内容。作者把 storyboard.md 理解成“给 HyperFrames 准备的视频制作详细说明书”。换句话说，Design.md 管视觉风格，SRT 管口播时间轴，storyboard.md 管镜头拆分和画面安排，三者组合后，Agent 才能比较稳定地写出 HyperFrames 代码并渲染成视频。

9. 完整工作流是：设计资产 → 时间轴脚本 → storyboard → Agent 写代码 → HyperFrames 渲染

作者最后总结了自己这期视频中使用的完整流程。第一步，准备设计资产，明确视频视觉风格；第二步，准备带时间轴的口播脚本，也就是 SRT 字幕文件；第三步，生成 storyboard.md 分镜文件，把内容节奏、镜头安排、画面布局写清楚；第四步，让 Agent 根据分镜写 HyperFrames 代码；第五步，启动 HyperFrames Studio 预览，并渲染生成 MP4 文件。这个流程和传统口播剪辑并没有本质冲突，只是把原来人工在剪辑软件里做的事情，拆成了 Agent 可执行的工程文件。作者展示的重点不是“一个神奇工具”，而是一套可复用的视频生产流水线。

10. AI 剪辑真正的价值，是把创作者经验变成可复用 Skill

视频里有一个隐含重点：作者不是只展示一次成功案例，而是把自己的稳定经验整理成 Skill。比如用于生成 storyboard.md 的 Skill，会自动读取设计资产和脚本，并输出适合 HyperFrames 的分镜说明。这说明在 AI Agent 时代，真正有价值的不只是提示词，而是把某类任务拆成标准输入、标准流程、标准输出。口播剪辑不再只是“让 AI 帮我剪一下”，而是变成一种工程化能力：什么文件放在哪里、什么文档给谁看、什么格式触发什么操作、什么阶段需要人工迭代。作者最后说“智能只手段，人类才是答案”，也正好呼应这一点：AI 能执行，但流程设计、审美判断、内容策略仍然来自人。

值得记住的点 / 行动建议
1. 不要把 HyperFrames 当传统剪辑软件，而要把它当“代码化视频引擎”

HyperFrames 的关键不是拖拽剪辑，而是用 HTML / CSS / JS 构建视频。它适合那些需要批量化、模板化、工程化的视频类型，比如科技感口播、教程视频、数据可视化、产品介绍、动画解释视频。你可以把它理解为“视频版网页工程”：视觉层由代码控制，内容层由脚本和分镜控制，渲染层输出 MP4。这样一来，AI Agent 就能直接参与视频制作，而不是只能给剪辑建议。

2. 先用一句话测试出片能力，再逐步加入工程化约束

作者第一个案例不是一上来做复杂口播，而是先让 Codex 根据一句提示词生成一个 1920×1080 的 Codex 安装指南视频。这个做法很适合新手：先验证环境能不能跑通、Agent 能不能理解任务、HyperFrames 能不能渲染出 MP4。只有跑通最小闭环后，再增加设计资产、SRT 字幕、storyboard 分镜和复杂动效。不要一开始就追求完整大片，否则很容易卡
