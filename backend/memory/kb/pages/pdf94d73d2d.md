# AI连接器与外部工具集成
AI连接器是帮助人工智能应用接入第三方软件、服务和数据源的能力，使AI能够在获得授权的情况下读取外部信息、调用业务工具并执行受支持的操作。〔S54〕

## 要点

### 一、连接器解决什么问题
- AI模型自身的知识不等于实时外部数据，模型无法仅凭已有知识准确掌握所有实时交通、酒店库存和未来天气信息。〔S54〕
- Connector（连接器）的核心作用是为AI建立与第三方应用、服务和数据源之间的交互通道。〔S54〕
- 连接器可以帮助AI读取地图、天气、邮件、日历、数据库及企业办公系统中的信息。〔S54〕
- 在获得相应权限的情况下，连接器还可以帮助AI调用外部应用的功能并执行受支持的操作。〔S54〕
- 连接器解决的是AI如何获得外部信息、如何使用外部系统的问题，而不是直接决定AI应该采用什么分析方法。〔S54〕

### 二、连接器与MCP、CLI、API的关系
视频介绍了几种AI调用外部能力的技术途径。〔S54〕

| 技术 | 全称 | 含义 |
| --- | --- | --- |
| MCP | Model Context Protocol，模型上下文协议 | 用于标准化AI应用与外部工具、数据源之间的连接和能力调用〔S54〕 |
| CLI | Command-Line Interface，命令行界面 | 通过输入命令与软件、操作系统或其他服务交互〔S54〕 |
| API | Application Programming Interface，应用程序编程接口 | 通过约定的程序接口实现不同软件或服务之间的交互〔S54〕 |

- MCP是一种协议，CLI是一种交互方式，两者不是同一种技术。〔S54〕
- AI在具备相应执行环境和权限时，可以通过CLI调用外部工具。〔S54〕
- 连接器并不只能通过MCP或CLI实现，也可以通过API或其他集成方式实现。〔S54〕
- 对普通使用者而言，理解连接器能够访问什么数据、执行什么操作，比单纯记忆技术名称更重要。〔S54〕

### 三、北京旅游规划案例
视频使用北京自驾旅游规划说明连接器的实际价值。〔S54〕
旅游规划涉及多种需要外部数据支持的任务：
- 地图服务：获取景点位置、道路路线和行驶距离。〔S54〕
- 交通信息：辅助判断行程路线和交通情况。〔S54〕
- 天气服务：获取出行期间的天气和温度信息。〔S54〕
- 酒店服务：查询住宿位置及可用信息。〔S54〕
- 餐饮服务：查询沿途餐厅和就餐地点。〔S54〕

- 视频以高德地图（Amap）作为地图连接器的具体案例。〔S54〕
- AI负责理解用户需求、整合不同来源的信息、比较方案并生成旅游规划。〔S54〕
- 地图连接器负责提供地图、路线和地点等外部信息。〔S54〕
- 天气、酒店库存和实际预订需要对应服务的数据接口及操作权限，不能认为地图连接器天然拥有这些能力。〔S54〕

### 四、连接器与AI工作流
连接器通常需要与AI模型、Skill及其他工具协同工作。〔S54〕

| 组成部分 | 主要职责 |
| --- | --- |
| AI模型 | 理解需求、推理分析和制定计划〔S54〕 |
| Skill | 提供任务执行方法、操作规范和输出标准〔S54〕 |
| Connector | 提供外部数据及第三方应用访问能力〔S54〕 |
| AI工作流 | 将需求、方法、数据获取、分析和交付组织成连续任务〔S54〕 |

- 只有Skill而没有必要的外部连接时，AI可能知道应该怎么做，却无法获取所需的实时数据或操作目标系统。〔S54〕
- 只有连接器而缺少明确的工作规范时，AI虽然能够获取数据，却不一定能够按照用户要求的标准完成任务。〔S54〕
- 将工作方法和外部数据能力结合，可以让AI的输出从单纯依赖模型已有知识，转向利用实际外部数据辅助决策。〔S54〕

### 五、连接器的使用场景
- 个人办公：接入邮箱、日历和个人文件，帮助整理邮件、安排日程和查询资料。〔S54〕
- 企业知识管理：连接内部数据库、企业文件系统和办公软件，获取业务资料。〔S54〕
- 旅游规划：连接地图、天气、住宿和餐饮服务，辅助制定旅行方案。〔S54〕
- 软件开发：连接代码仓库及其他开发工具，支持程序开发和相关操作。〔S54〕
- 数据分析：连接业务数据库，获取最新经营数据并交给AI分析。〔S54〕
- 浏览器操作：通过支持浏览器交互的工具获取网页信息并执行相应操作。〔S54〕

### 六、连接器的权限与安全边界
- 连接器不仅增加AI的外部信息获取能力，也可能让AI接触更多个人或企业数据。〔S54〕
- 邮箱连接可能涉及私人通信，企业文件系统可能涉及商业机密，日历连接可能涉及个人行程。〔S54〕
- 具备写入能力的连接器还可能修改文件、发送邮件或者执行其他外部操作。〔S54〕
- 使用连接器应遵循Least Privilege（最小权限原则），只授权完成当前任务所必需的权限。〔S54〕
- 信息查询权限和外部操作权限应该加以区分，不能因为AI能够读取某项数据，就默认它也应该拥有修改数据的权限。〔S54〕
- 对付款、预订、删除文件和发送重要消息等操作，应设置必要的人工确认环节。〔S54〕
- 成熟的连接器应用需要同时考虑准确性、安全性、可控性和操作结果的可验证性。〔S54〕

### 七、如何判断是否需要连接器
- 如果AI不知道最新的实际数据，应优先考虑接入相应数据源。〔S54〕
- 如果AI无法读取邮箱、日历或企业文件，应检查是否存在对应连接器以及访问权限是否正确。〔S54〕
- 如果AI知道操作步骤但无法实际执行，应检查外部工具是否支持该操作以及是否获得相应授权。〔S54〕
- 如果任务涉及多个外部系统，应考虑将多个连接器组合进统一工作流。〔S54〕
- 如果问题只是AI不理解用户要求，则应该先优化提示词，而不是盲目增加连接器。〔S54〕

## 关联
- [[AI智能体与企业应用]]：连接器为AI智能体提供外部数据和软件操作能力，使其能够参与真实业务流程。〔S54〕
- [[AI Skill（技能）与可复用工作流]]：Skill提供任务方法，连接器提供外部资源，两者共同支持可重复执行的工作流。〔S54〕
- [[AI插件与专项任务能力组合]]：插件可以将多个连接器与相关Skill组合，形成面向专项任务的综合能力。〔S54〕

## 不同说法
- 视频为了方便理解，将MCP和CLI概括为AI连接第三方应用的技术途径。〔S54〕
- 从技术分类看，MCP是协议，CLI是交互方式，API是程序接口，三者不能简单视为同一种连接技术。〔S54〕
- 连接器是对外部应用集成能力的概括，并不意味着每个平台都采用相同的技术实现方式。〔S54〕

## 待跟进
- 不同连接器对读取、写入、删除和发送等操作分别支持哪些权限。
- MCP、API和CLI在不同AI平台中的适用场景及安全机制。
- 如何建立连接器的操作日志、异常检测和人工审批机制。
- 企业如何在提高自动化程度的同时避免商业数据泄露和越权操作。
